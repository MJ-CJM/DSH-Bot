# DSH-Bot

[English](README.en.md) · 中文

**你的个人智能体工作区。** 在 DeepSeek Harness 中创建各有职责、记忆与工具的 Bot，持续对话、分工协作，并在原对话中拿到结果。

**当前源码：0.7.3 候选（npm 包名 `dsh-botgroup`）。** 候选功能见 [0.7.3 发布说明](https://github.com/MJ-CJM/DSH-Bot/blob/main/docs/releases/v0.7.3.md)。目前公开稳定版为 [0.7.2](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.2)。[更新记录](https://github.com/MJ-CJM/DSH-Bot/blob/main/CHANGELOG.md)。

## 从一个 Bot 开始

安装后，从 DSH 原生侧栏进入 Bots。

1. 打开原生侧栏 **Bots**，选择或新建一个 Bot，再打开它的原生聊天。例如：“比较这两份方案，需要时请研究员和审阅助手一起检查。”
2. 从 Bot／群目录查看职责、记忆、任务和资料；对话详情提供返回对应目录的入口。新建、搜索、分支和归档继续使用 DSH 原生命令。
3. 在对话里直接让 Bot 向另一只 Bot 提问或追问，回复会回到原对话。分享私有记忆或私聊内容时，会先请你确认。需要自动组队时，在 **Bots → 我的 Bots → 自动协作** 查看当前状态，点开即可修改开关。
4. 在原任务添加资料、继续或停止。切换页面、查看目录和关闭详情不会开启或停止自动协作；文件权限、工具审批与模型配置沿用宿主。

聊天需要 DSH 中可用的模型，模型服务可能产生费用。主动跟进和自动协作分别设置，不因打开 Bots 而自动开启。

## 常用功能在哪里

| 想做什么 | 入口与行为 |
| --- | --- |
| 看任务和主动跟进 | Bots → 对应 Bot／群 → 任务。跟进需要为该 Bot／群明确开启。 |
| 补充资料并继续 | 对应 Bot／群 → 资料。选择准确任务和文本文件，原问题默认保留；附加要求可选填。 |
| 看待处理事项 | Bots → 需要本人处理的任务。回到原对话补充信息、核对结果或使用原生提问／审批入口。 |
| 管理职责与记忆 | Bots → 对应 Bot 的详情，进入完整设置或管理已保存的记忆。 |
| 调整群与复用团队 | Bots → 对应群的设置，查看群偏好及团队配方。 |
| 配置可选服务 | Bots 中的高级设置；日常任务继续在 Bot／群对话中处理。 |

### 自动协作，结果回到原对话

Supergroup 复用 DSH 原生子任务、模型、工具和审批能力。已有 Bot 可根据任务自动组队，并在协作中请求其他已有专家支持；不必预先选齐成员。群里可查看真实成员、过程、用量与公开成果，也可补充任务或停止协作。

共享范围是当前任务文字、明确选择的资料及已授权成果。私人聊天与私有记忆不会自动整份交给队友；工作目录也不构成文件沙箱。具体回答和分工取决于模型、工具、权限和任务资料。

### 缺少资料或连接时，继续同一项工作

资料页显示当前原任务与获准读者，可直接选择有限文本文件；连接问题出现时，从原工作进入连接与凭据设置。**连接就绪后仍需明确继续原任务**，不会因为配置完成而自动重放。

工作目录汇总待补充、待核对、结果未知及可用的原生提问／审批入口。打开或阅读不会解决事项；审批仍在原生控件处理。交付或执行结果未知时，先核对已有操作，不自动重新执行。

### 可选的非定时跟进

在 **Bots → 对应 Bot／群 → 任务 → 开启主动跟进** 为当前 Bot 或群开启。本地查看与刷新不调用模型，不需要 GitHub 账号或外部凭据；跟进与实际执行分别授权。

已有支持的任务卡提供 **关注此任务**，自动填入任务名称、可用条件和可修改的截止时间。你可以观察原生子任务完成，或已配置来源的下一个 GitHub CI 结果；也可手工登记事项和完成条件。**保存前可以修改或取消，打开表单不会建立关注。** 条件满足后进入待核对，不自动启动模型或重做任务。

个人 Bot 聊天中的登记沿用原生工具审批；群聊提案需要明确“确认关注”才生效。可停止单项或暂停该 Bot／群的观察。此功能**不是定时提醒**，依赖本地 DSH Host 运行；普通日程继续使用 DSH 原生能力。

### 记忆有来源，也能核对变更

每个 Bot 有独立记忆。在记忆页查看 **最近记忆变更** 的来源、时间和前后差异；对允许恢复的历史版本，可明确选择 **恢复为新修订**。已遗忘、已撤销或当前无权读取的内容不会因此复活。

开启 Bot 记忆后，可在 **记忆 → 参与的群工作** 搜索本人实际参与且仍可访问的群记录，并打开原文。在群成员菜单选择“在单聊中追问”会准备带引用的草稿，发送仍由你决定。查到群记录不会自动存成长期记忆，私有记忆也不会自动共享。

### 保存团队偏好，按需使用普通群

群设置中的 **团队配方** 自动预览当前团队，可以直接保存；导入与 JSON 编辑收在高级入口，导出按钮保留在预览区。应用前预览角色映射，并明确确认成员变化。配方只含团队偏好，不含聊天、记忆、凭据或执行授权；**新成员只能读取明确授权给当前受众的记录，不能据入群推定可读全部旧历史**。

手动创建的普通群默认按问题在本地选择相关发言者，可在设置中关闭。明确 @、回复和轮次优先；无匹配时沿用原路由，选择过程不调用决策模型，成员回答仍会调用模型。已有群保留原偏好。Supergroup 自动团队围绕任务协作，无需配置普通群的发言方式。

群聊的 @ 菜单只列出本群可用成员和 @everyone。在普通群里直接输入「问 Jarvis：迁移还有哪些待办？」，由群外的 Jarvis 在群里回答。如果希望群内的通用助手代问，可以回复通用助手的消息说「你问下 Jarvis 迁移还有哪些待办？」，也可以写「让通用助手问 Jarvis 迁移还有哪些待办？」。Jarvis 把结果交给通用助手，再由通用助手回复群聊。在群里展开转问进度，可以核对实际送出的问题、中转答复和最终回群内容。点 Jarvis 会话里对应的收发标记，可以查看该次投递获准查看的原文。提到「这个」时，填写愿意分享的话题，或点「填入引用摘句」，编辑后发送。群外转问默认使用已分享给接收方的资料。使用私有资料时，向通用助手分享和向全群分享分别确认。

同一轮有多条待审群回复时，可以一起预览发给同一批成员的回复，取消勾选不想发送的条目，然后确认发送。审核期间新到的回复留给下次处理。在普通群输入「只记下来：要记录的内容」，成员各自保存，群里只报告写入状态。也可以引用一条群消息再说「只记下来」。

群里的提问和每条回复都可以单独展开、收起。多人回复时，长回复默认折成一行。短回复和单独点名的答复默认展开。同一轮收到两条或更多 Bot 回复后，可以一起展开或收起。

![普通群协作与成员执行过程示例](https://raw.githubusercontent.com/MJ-CJM/DSH-Bot/main/packages/dsh-bot/assets/showcase/zh-group.png)

原生后台任务、结果验收、普通日程、Bot 消息以及可选的文档快照分析与工作方法评估仍保留在任务／管理入口。高级执行和外部连接按需配置，不是开始 Bot 对话的前置步骤。

新原生方案不要求替换官方 web-app、安装三项 Client 适配或选择 Bot 模式。此前精确绑定 rc.3 的 `dsh-bot-web-app` 属于旧交付：已启用旧适配的安装须先在副本中迁移为官方组合，保留最新设置和数据。不能同时选择官方与替代 web-app，也不能直接给旧适配添加新版豁免。

### 已发布版本

公开 npm 包名为 **[dsh-botgroup](https://www.npmjs.com/package/dsh-botgroup)**；产品品牌、插件 ID 与数据目录仍为 DSH-Bot／`dsh-bot`。稳定版版本包为 `dsh-botgroup-0.7.2.tgz`，固定下载名 `dsh-bot.tgz` 是同包别名。

打开对应 [Release](https://github.com/MJ-CJM/DSH-Bot/releases)，阅读它自己的兼容说明，下载插件 tgz 和同一 Release 的校验文件。macOS 校验示例：

```sh
shasum -a 256 -c dsh-bot.tgz.sha256
```

在 DSH 中通过 **插件 → 添加插件 → 安装第三方插件** 选择 tgz，按宿主提示启用并完全退出重开。源码压缩包不是预构建插件。社区市场或 `latest` 地址可能仍指向稳定版，不能据此获取未发布候选或证明当前候选兼容。

### 当前候选

候选安装和迁移条件见 [0.7.3 发布说明](https://github.com/MJ-CJM/DSH-Bot/blob/main/docs/releases/v0.7.3.md)。请用对应包的校验和验证下载，再在已验证的宿主组合中安装。

从旧 `dsh-bot` 包迁移时，先停止 Host 并备份完整 profile 和数据，通过原生插件管理移除旧包，再安装 `dsh-botgroup`。启动前检查 profile 的 `cordis.patch.yml`：原 `id: dsh-bot` 覆盖行若带 `name: dsh-bot`，仅改成 `name: dsh-botgroup`，保留 id、config 与 dataDir；没有 name 的行无需新增。不要同时保留两个包依赖或 bundle；自定义包含层／模板中的旧包引用需另行核对。[迁移说明](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.6.7)。

升级前备份原 profile 和完整数据，保留原存储位置；不要通过删除 Bot 或重置数据升级。回退应保留升级后新增的历史与设置；仅在当前 profile 仍等于本次安装结果时使用本次快照，否则先做定向反向迁移，不能整库覆盖旧备份。外部连接、付费执行和共享权限不会因升级自动获得授权。

## 验证与边界

精确候选包、隔离 Host／浏览器验收及升级验证以 [0.7.3 发布说明](https://github.com/MJ-CJM/DSH-Bot/blob/main/docs/releases/v0.7.3.md) 为准。

真实付费模型的专业质量、外部账号认证、外部 IM 收发及未来宿主自动适配未由这些检查证明。任务依赖本地 Host 运行；当前不提供云端常驻、系统退出后的持续执行或系统／手机推送。不确定的执行结果不会自动重放。
