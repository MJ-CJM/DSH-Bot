# Supergroup 可派发开发计划

> 新增任务：[Bot 中心交互 B00–B04](BOT-MODE.md)整体已获批准，覆盖 Bot/群导航、可参与群聊与原 Bot 交付；B00 运行门槛未通过，B01–B04 暂停，等待具体宿主适配裁决。不与下方既有 SG00–SG05 的已实现状态混用。

日期：2026-11-12。代码核对基线：`main@f6e3c64`。实施分支：`codex/supergroup-p0`。状态与逐项运行证据见[实施验收](../../docs/verification/supergroup-p0.md)。
产品约束与整体设计见[总方案](../../docs/design/supergroup/README.md)，公开能力与路线取舍见[原生复用](../../docs/design/supergroup/native-reuse.md)。
此计划不授权真实付费模型、外部账号写入、发布或桌面升级；现有测试和历史群运行证据不等于 Supergroup 已通过验收。

## 1 产品结果与范围

用户开启 Supergroup 后，仍在原对话说需求；简单工作由当前 Bot 完成，复杂工作自动选择已有长期 Bot 组队。
成员可直接互通；发现能力缺口时请求支援，系统按现有许可选择并加入已有专家，继续同一件工作。
原对话显示可折叠过程、停止入口和统一成果；用户直接追问或要求修改，不必跳群、选成员或填写验收表。
自动组队、协作中拉已有专家、原对话交付均为 **P0**，任何一项未实现都不能称第一版闭环完成。

- 不新增项目中心、决策收件箱或必填配置表；工作、群、轮次与来源关联在后台保持准确。
- Bot 保持独立身份、preset、模型与记忆边界；Group 是真实协作单元，不是匿名工具的外观。
- 召集者是可选工作角色；Host 负责确定性路由，不要求每次成员交流先运行主管模型。
- 只在缺失信息会实质改变结果时作最少澄清；成员选择、群命名和内部状态不转嫁给用户填写。
- 模式配置结合准确的人类输入限定本次许可；开关、模型计划、群发言均不能单独构成任意授权。
- 已授权范围内不逐成员重复审批；增加资料可读者、工具/外发权限或预算等范围时才请求对应增量许可。
- P0 先覆盖只读分析和资料交付；工程执行、定时及外发沿既有能力边界，不以简化入口为由放开。

## 2 公共派发契约

每次开始读根 `AGENTS.md`、`docs/dsh-api-notes.md`、`docs/PLAN.md`、本清单与上面的设计文件，再核对 Git 状态。
只在本仓库写文件，保留已有改动；参考 `~/ai-workspace/deepseek-harness` 的 `dsh-v0.2.1-rc.2` 只读。
DSH 原生服务优先，其次复用现有 Bot/Groups/任务服务；不新建执行器、聊天库、任务状态权威、调度器或审批系统。
运行时仅使用公开包入口；API 新组合先由 SG00 实测，不从内部路径导入，不修改运行时版本锁定。
所有资源纳入所属 `ctx.effect`；参数进入 Config/schema；沿用中英 locale 与 `--dsw-alias-*` token。
实现任务执行适用检查及 `scripts/pnpm check`；需要复现依赖时用 `scripts/pnpm install --frozen-lockfile`。
DSH 使用 `scripts/dsh`，从仓库根设置 `DSH_HOME="$PWD/.dsh-dev"`；CLI 版本按 SG00 明确选择并记录。
默认模型测试只用本机合成适配器，真实 Host/UI 与真实模型质量分别验收；不能发起需要模型 API key 的会话。
禁止修改 `~/.dsh`、桌面安装、全局配置，禁止 commit/push；使用任务指定权限，不绕过审批或沙箱。
派发沿根规则：设计 `gpt-6-astra/high`，实现、返工及文档 `gpt-6.1-sol/high`；每次 `-c` 指定，stdin 用 `</dev/null`。
各任务结束报告改动文件、命令结果、逐项 PASS/FAIL、遗留问题；未执行项写 `FAIL（NOT_RUN）`，不能以静态检查替代运行。

## 4 SG00：原生兼容 spike 与路线决策

**目标**：在真实隔离 rc.2 Host 上验证自动组队、动态专家、当前对话回传的最小组合，再冻结实现路线。
**已有落点**：`src/host/groups/{roots,root-guard,turn-runner,concurrent,worker-tool}.ts`、`src/host/delegate/tool.ts`、`src/client/group-execution.tsx`（均相对 `packages/dsh-bot/`）。
参考公开入口为 `subagents`、`agentPresets`、原生 Session/投影、ToolRuntime 与可用 UI slots；核对实际 exports 与 provider capabilities。

- 核对 native Agent Team 与现有 Groups 的身份、成员加入、同伴消息、生命周期和回传能力；记录采用或不采用的逐项理由。
- 核对主助手入口的身份：既有 Bot preset 内组合须保留主会话绑定、记忆和审批；独立协调 preset 不得冒认原 Bot。不能只注册模式名便认定与既有主会话兼容。
- rc.2 Team 的 spawn 为 lead 路径，`SpawnTeammateRequest` 无 botId/agentPreset；不能把临时 teammate 命名当成已有长期 Bot。
- 现有 Group root 禁止 LLM；理解需求和必要汇总放当前会话或明确成员，不删除 root guard 来造主管。
- 实测普通成员直接互通、准确人类输入与模式范围关联、原对话过程投影及一次成果回传；UI 与 Host 分别记录证据。
- 实测 `membershipRevision` 冲突与旧 delivery 在途窗口；优先验证同一工作关联新轮次、冻结新成员快照的交接路线。
- 新轮次不自动拓宽群根累计数据标签；实测资料共享授权与根标签的准确处理。禁止重置标签、摘要洗权限或另建群规避，新专家必须在最终交付前实际参与。
- 新专家只接收准入后的任务摘要和明确引用，保留真实 machine/agent 来源；不将重放上下文改成 user 来源。
- 区分普通群协作与 `ownerFollowUp` 专用单成员、单次零工具路径；后者不能作为多人互通能力证明。

**验收**：产出公开签名/版本、真实 Host 事件、2→3 身份证明、来源与回传收据、取消清理结果及路线决定。
最小反例覆盖未授权成员、旧代际、旧成员版本、私聊上下文、群根模型请求和重复回传；全部使用合成模型。
**失败边界**：任一必要组合缺能力则记录 FAIL 并调整公开桥接路线；无法保留全部 P0 目标时报告能力阻塞，不能把范围缩减记为完成。不得删 guard、伪造来源或偷偷改用共享父 preset。
SG00 通过前不派发依赖其协议的正式实现；取证完成不等于对应能力通过。

## 5 SG01：模式入口、范围授权与工作关联

**目标**：开启后直接对话，后台准确识别本次工作、许可范围和原对话，不要求用户创建项目或配置团队。
**已有落点**：`src/host/{registry-config,bot-context,index}.ts`、`src/host/proactive/{config,service,follow-up-tool}.ts`、`src/host/delegate/{tool,guard}.ts`、`src/shared/{groups,identity}.ts`。
当前 `bot_delegate` 逐次请求审批；Supergroup 必须增加可核对的模式范围合同，不能只隐藏现有提示。

- 复用原生 ConfigEditor 与既有配置生命周期；普通入口只呈现模式开关及简短范围说明，额度等合理默认值放高级设置。
- 根据 SG00 选择兼容的 preset/模式入口，准确显示新对话或已有会话的生效范围，不热切已锁定 preset，不重建原 Bot 主会话。
- 绑定发起 Session、真实人类 message、所属 Bot 代际、配置/权限版本与稳定工作标识；引用既有任务/轮次，不复制第二份状态库。
- 冻结可选 Bot 集合或可核对的成员准入规则、任务资料/可读者边界、模型/工具范围、预算和期限；参数不硬编码。
- 支持当前 Bot 直接完成，只有需要协作时创建群工作；澄清只针对实质缺口，不预先追问成员或群名。
- 许可扩大时生成准确差异确认；批准与实际执行前重核版本，后台消息和专家请求不能自行批准。
- 记录当前对话与工作/群/轮次/结果的关联及操作收据；配置关闭先阻止新准入，在途工作按明确取消/收尾语义处理。

**依赖**：SG00 冻结的来源、模式配置与原生执行路线。
**验收**：开启/关闭与冷启动持久化；真实人类请求可进入，伪造来源/过期配置拒绝；范围内无逐成员确认，扩大范围才确认差异。
简单请求零群创建、零成员模型请求；切换会话/Bot 不串工作，重放相同输入不重复建工作。
**失败边界**：不能核实输入或范围就不自动派工，给原对话简短原因；不以“已打开模式”代替授权。

## 6 SG02：按需选择已有 Bot、自动组队与直接互通

**目标**：复杂需求自动选合适长期 Bot 开始协作，身份和经验连续；用户不用先挑选成员。
**已有落点**：`src/host/registry.ts`、`src/host/registry/presets.ts`、`src/host/groups/{service,members,routing,turns,concurrent,worker-tool,model}.ts`、`src/host/data-flow/{delegation,outlets}.ts`。
当前 natural 路由无点名会选全部启用成员；需增加任务级选人准入，不能把该行为当智能组队。

- 当前会话根据任务提出成员/职责计划，Host 用实际 Registry/preset 状态、模型和许可核验；不额外强制运行每步主管模型。
- 优先已有长期 Bot 与可兼容群；无匹配成员时说明能力缺口并保留可完成工作，P0 不悄悄生成永久 Bot。
- 自动创建或选择真实协作群，保存共同任务目标、本次成员和模型快照；复用已有群时检查历史可见性与新增工作资料范围。Teams 路线复用原生成员权威与投影，Groups 路线复用现有 Group 记录。
- 按选定路线复用 Team 消息或 `group_message` 的 request/progress/requestReply 与原生 inbox；目标限制为本工作获准成员，普通进度不唤醒闲置全员。
- 工作资料由原有数据流准入；Bot 独立记忆按原范围读取，不复制其他 Bot 私聊或自动共享所有记忆。
- 预算、并发、轮数与终止条件归已有执行/任务服务；成员可直接交接、要求复核或 skip，不要求跑满轮数。

**依赖**：SG01；共用合同冻结后与 SG04 视图并行。
**验收**：两名真实长期 Bot 使用各自准确 preset/模型；直接请求与回复可追 delivery；未选成员零请求；群 root 模型请求为零。
最少澄清、单人降级、成员不可用、模型配置冲突、重复消息和循环预算各有正反例。
**失败边界**：未确认能力不得用角色名称冒充；任务未完成不能因群进入 idle 自动宣告成功。

## 7 SG03：请求支援、去重选人、动态增员与安全交接

**目标**：两名成员发现缺口后，自动拉入第三名已有专家，并在同一工作中拿到其结果；这属于 P0。
**已有落点**：`src/host/groups/{worker-tool,concurrent,turn-runner,members,turns,state}.ts`、`src/shared/groups.ts` 与 SG01 工作关联/范围合同。
现 `turn-runner.enqueue` 会拒绝 `group.membershipRevision !== turn.membershipRevision`；直接 edit 群成员后继续旧轮次会冲突。

- 为工作者增加明确的支援请求合同：能力缺口、具体问题、已有证据引用和请求标识；模型提出需求，Host 负责准入和去重。
- 从 SG01 允许集合选择现有专家，复核 Bot 代际、能力、模型及费用；可见目录不等于允许该 Bot 读取全部共享历史。
- 以工作＋请求/缺口＋所选专家的持久收据合并并发邀请；同请求异正文拒绝，不依靠内存锁证明重启后幂等。
- 采用 SG00 验证的安全交接：Groups 路线冻结旧轮次入口，收拢或明确保留在途结果，关联新轮次和新成员快照，工作身份不变；Teams 路线沿原生 roster/activation 准入，不另造一套轮次。
- 不删除成员版本 guard，不伪称原地热增员；记录 predecessor、来源、已交付结果与新专家输入范围，准确处理迟到结果。
- 新专家只收到本次最小任务上下文；需要扩大资料可读者/权限/预算时只确认该差异，既有范围内无需另批每个成员。
- 增员和新轮次不会自动解除根会话累计标签；复核原资料及其摘要的真实读者限制。可以等待执行到安全交接点，不能等整项工作交付完再另起专家任务冒充中途加入。
- 将专家结论送回实际请求者及统一成果路径，保留真实作者和来源；不广播成所有成员的新一轮任务。

**依赖**：SG02；SG04 的最终交付与恢复以本任务的新轮次/增员收据为准。
**验收**：2→3 三个真实长期 Bot；两成员同时邀请只发生一次有效增员；新专家结果有实际执行证据并纳入同一工作。
邀请前/准入后/交接中取消、成员删后重建、权限撤销、收据丢失、重启及迟到结果均不得重复启动或突破范围。
**失败边界**：缺少安全边界保持等待/待核对；不能用“新增了一条群成员记录”冒充专家实际加入并完成协作。

## 8 SG04：原对话过程、统一交付、修改、停止与恢复

**目标**：无需跳转或操作工作台即可看到进展、收到成果、继续修改；动态加入的专家也体现在同一处。
**已有落点**：`src/client/{group-execution,workspace-group,group-views}.tsx`、`src/client/components/{GroupTurnExecution,GroupMemberProcess,GroupTimeline}.tsx`、`src/host/groups/{messages,roots}.ts`、`src/host/proactive/service.ts`。
复用公开会话投影与 UI slot；原对话显示真实群的受限投影，不复制第二套消息库，也不覆盖原生 View ID。

- 在发起消息附近显示默认折叠的成员/阶段/异常摘要，展开真实协作；补充、停止和范围扩大确认留在当前对话。
- 原对话结果与准确工作/产物版本绑定，通过持久回传收据保证同一结果版本最多一次可确认发布；未知回执先核对不盲重发。
- 汇总保留新专家贡献、证据、分歧和未完成项；可由当前会话或明确成员组织，不让群 root 调模型，也不把技术复核当人工验收。
- “继续改第二项”默认接续准确活动工作；多个合理对象冲突时才简短澄清，不要求用户填写 Ticket 或验收表。
- “给出结果”“用户接受”“继续修改”分别记录；沉默不自动算接受，修改只创建原工作的后续尝试。
- 停止阻断新邀请/投递并等待实际清理证明；重启按持久事实恢复展示，未确认执行/回传保留 unknown，不自动重跑。

**依赖**：SG01 后可先开发只读视图；完整验收依赖 SG02、SG03。
**验收**：原对话看见自动两人→三人过程和一次成果；不导航跳转；同工作追问命中正确成果，用户输入补充不会复制出新工作。
中英、亮暗、窄屏、键盘、页面切换/卸载、停止/重启均验证；新消息和旧响应不得串会话，订阅/引用须释放。
**失败边界**：原对话回传不可核实时显式待核对；不以导航到群页或一张静态卡片替代所需交付。

## 9 SG05：同包集成与真实 Host/UI 验收

**目标**：用同一冻结安装包证明全部 P0 链路，区分机制、界面与真实模型效果。
**已有落点**：`packages/dsh-bot/tests/`、`scripts/` 的现有群协作/主动任务隔离夹具及 bundle 审计；复用测试基础，不复用旧包结果。
**依赖**：SG02–SG04 全部完成；SG00 路线若发生变化，重跑受影响的原生组合门槛。

| 场景 | 必需证据；当前均未执行 |
| --- | --- |
| 简单任务 | 群创建与成员模型请求均为零；当前 Bot 正常交付 |
| 自动协作 | 无用户选成员，两个真实长期 Bot 独立 preset/身份，成员直接互通，群 root 零模型 |
| 动态专家 | 运行中请求支援、2→3、选定后端的准确增员/交接引用和来源、最终交付前专家真实回答、原对话包含其结果 |
| 并发邀请 | 重复/乱序/重启后收据不造第二专家执行；同键异正文明确冲突 |
| 数据与授权 | 私聊不泄漏；共享范围不因增员自动放大；范围内无逐成员批准，越界请求才确认差异 |
