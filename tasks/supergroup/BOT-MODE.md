## 执行契约

沿用根 `AGENTS.md`：保留现有工作区，只在本仓库写文件；DSH 固定 rc.2 参考只读；依赖精确锁定；使用 `scripts/pnpm` 和 `scripts/dsh`，实验 `DSH_HOME="$PWD/.dsh-dev"`；所有注册受 `ctx.effect` 管理。规划派发 `gpt-6-astra/high`，实现派发 `gpt-6.1-sol/high`，显式参数和 stdin 规则不变。

用户后续明确同意“在仓库内制作仅用于独立审批服务的 DSH 适配包，继续把剩余功能全部实现并部署”。批准范围包含仓库内宿主副本适配、必要的隔离测试启动选项、产品实现、合成模型验证及本地服务部署；当前桌面应用、日常数据和只读参考树不可修改。真实模型密钥会话、commit/push 或公开发布仍不在本次范围。审批服务使用独立 home/profile、端口、凭据与存储，不复用日常 desktop Host。

## B00 完整模式接管和群输入桥接

优先级：P0 前置。依赖：用户批准整体方案。目标：先解决可能影响整条产品路线的公开 API 缺口，再开发完整界面。

### 接管实验

在最小隔离 Host、真实 Browser 以及目标版本的隔离桌面桥环境注册 `sidebar`、`shell.leading`、标题与右栏，保留原生 Conversation/composer/审批/模型服务。逐条核对新建、搜索、分叉、归档的快捷键、菜单、macOS 收起左栏控制、旧深链与冷启动默认导航。桌面桥的菜单、快捷键、深链及退出恢复取证属于 B00，不能延后到 B04；实验必须明确使用隔离 profile，不修改日常桌面数据或应用安装内容。无法取得该环境时，对应项为 FAIL（NOT_RUN），不凭 Browser 结果放行完整接管。

未适配宿主的历史限制：快捷键同 ID/默认键不能冲突注册；公开 command 没有全局 when/isEnabled；workspace 同插件提供服务和注册快捷键，卸载可能使 Conversation 失活。实验先找公开可组合的模式路由；记录实际 API、作用域和恢复结果。不能使用 CSS 隐藏、永久改键位、DOM 全局截获、recording 状态冒用或私有 registry。

### 群输入实验

原 B00 基线只校验发起 Bot 的人类主输入；本轮已新增群内 owner Remote 输入桥。验收仍必须核对群根消息、原工作、用户、范围和 revision；输入保留实际来源，复用原 Groups 队列与安全交接。验证两处并发输入、成员文本伪造用户、重复提交、已停止工作、Bot 忙碌/删除和回交付未知状态。

通过既有 Bot 的公开后续执行和原生来源引用完成交付，不将群消息伪造为私人 user message，不解除 continuation guard。若需要扩展现有 Supergroup 的输入收据，可使用本插件内部 Host 合同，但不能将它称为新的 DSH 原生 API。

### 退出标准

- PASS：全部入口保持 Bot/群语义，原生发送/草稿/模型/权限/实际审批路径/停止仍有效；群补充准确接续并回原 Bot；重复输入不多派工；关闭/卸载/冷启恢复无残留和串话。
- FAIL：任一入口无法安全接管，关闭原生插件破坏聊天，必须依赖私有 API、越出已授权独立 runtime 的宿主修改，或群补充只能伪造来源/绕 guard 才能接续。
- 失败处理：保留具体收据并修复已授权范围内的缺口；若确实超出本轮授权，再提交最小范围说明。原命令/Chat 适配已有授权，不能重复以待审批为由停止，也不能把残留 Session 的版本改称完成。

落点：新增项目内 spike runner 与 profile、`docs/spikes/` 报告、API notes。共享 Host 输入合同在通过后冻结；不要在实验未通过时接入日常桌面。

## B01 Bot 导航和模式生命周期

依赖 B00。落点：`src/client/index.tsx`、新模式 shell/controller、现有 catalog/activity/group state、Supergroup 设置组件。

- Bot/群统一列表：头像、预览、状态、未读、置顶、最近活动与更早群；复用现有事实源，纯展示不调用模型。
- 对象导航输入为完整 BotKey/GroupKey；保存当前对象与阅读位置，内部解析底层 Session。
- 一个开关协调 Host 与 Client 的安装、恢复、停止和卸载；启动与失败态不泄漏原生 Session 页面。
- 承接设置入口和返回定位，处理 B00 证明的全部命令/菜单/深链路径。
- 生命周期合并到 `ctx.effect`，重复开关和热重载无重复 slot、快捷键或订阅。

验收：初次/二次开启、空目录、删除重建、切换失败、刷新冷启、失联、关闭中迟到回调；多窗口配置一致、导航与草稿不串；布局插件冲突明确可恢复；恢复用户原键位与导航。

## B02 持续聊天和历史呈现

依赖 B01 的对象导航合同，可与 B03 的 Host 部分并行。落点：`client/index.tsx`、公开 Conversation factory/slots、`host/main-session.ts`、既有记忆与历史查询。

- 打开 Bot 复用 `openConversation(botId)`，不热换已开始 preset，不通过复制消息制造新的主对话。
- 标题显示 Bot/群身份；保留原生个人输入和已支持的群输入控制，模型/权限始终明确属于当前对象。
- 草稿按对象隔离，切换和开右栏不触发模型；换主题直接聊天，歧义才提示选择工作。
- 旧 Bot 历史依已核实归属投影，未知普通 Session 不自动合并；旧深链定位对象内历史，失败可解释。
- 先复用原生上下文管理；后台分段不变成用户 Session 管理任务，不额外承诺跨段自动拼接全部上下文。

验收：同 Bot 多次打开及重启主绑定一致；模型/记忆/审批保持；草稿和异步结果不串对象；历史来源和搜索范围正确。

## B03 真实协作群与原 Bot 交付

依赖 B00 冻结的群输入合同及 B01/B02 导航。落点：`host/supergroup/*`、`host/groups/*`、`client/workspace-group.tsx`、`GroupTimeline`、`GroupTurnExecution` 与 Supergroup 卡片。

- 简单请求零组队；复杂工作创建一个稳定群，命名/选人自动完成，保持原 Bot 页面焦点。
- 同工作新增输入复用群，多个工作准确消歧，不仅按最新更新时间选目标。
- 真实成员消息、专家加入、公开进度和结果有作者/来源；内部过程折叠，成员互通不造成全员无限唤醒。
- 群中补充和 @ 按 B00 合同排队，保留身份、数据标签、成员版本和原请求预算；相同请求不重复执行。
- 原 Bot 负责最终交付，群展示受权成果引用；每个版本交付幂等，忙碌/离线时不丢结果、不绕旧 guard。
- 结束群保留并可继续；手动归档不删除，运行群停止后再归档；停止和关闭覆盖所有成员和待邀请。

验收：自动 2 人→3 人专家→群中真实补充→原 Bot 交付→继续修改→停止；并发输入、重复/乱序回调、权限撤销、专家不可用和冷恢复均有反例。不得仅用静态假卡片取证。

## B04 右栏和同包验收

依赖 B01–B03。落点：已有 Bot panel、group views、资料/成果引用投影、locale、样式和真实 UI runner。

- 右栏 Bot 详情/资料，群详情/资料/成员；默认收起，窄屏可返回当前对象。
- 资料条目只索引已有可读内容与成果；P0 Supergroup 文字范围不因可见附件而扩大。
- 中英 key 对齐，主题仅用原生 token，键盘、读屏、焦点和状态不依赖纯颜色。
- 冻结后同一 tgz 做源码→包→安装逐字节核对；独立 Web `0.2.1-rc.2` runtime 验证完整候选；真实桌面 `0.2.2-rc.2` 隔离副本的命令桥相关行为单独取证，不外推为完整桌面 UI 通过。
- 必跑 `scripts/pnpm check`、文档与格式检查及适用运行矩阵；报告实际命令、包 hash、逐项 PASS/FAIL、资源清理和未运行项。

用户日常桌面部署是后续独立步骤。应用版本不等于插件版本；某一 Browser 通过不能替代 macOS 菜单、深链和真实模型体验。

## 并行安排与交付

B00 是共同前置；通过后冻结对象导航、群输入与交付合同。B01 负责模式外壳，B02 负责原生聊天绑定，B03 负责群输入与成果联动；公共 index、schema、locale 与 lockfile 由集成方串行修改，避免多代理争写。B04 使用冻结安装包统一验收。

不新增 P0 的完整资料库、常用团队复用、临时永久 Bot、外部事件源、云执行或工程权限。所需仓库内宿主适配与兼容范围已有用户授权；继续保持独立 runtime 与只读参考树边界，不修改当前桌面安装或日常 profile。
