# P1-T08g：后台刷新无闪烁 + 智能轮询 + 会话真实标题

用户反馈（0.1.3 实机）：
- Bots 页会"自己刷新一下"（5s 轮询导致可见闪烁/重排）。
- 右栏 Bot 资料下的状态行"就绪"多余（红框标出）。
- 会话历史行标题显示成了工作区名（如 `pod_0814`），预览为"暂无消息预览"。

## 需求
1. **无闪烁后台刷新**（Bots 页、Bot 会话弹层、右侧栏 Bots 标签、会话行头像、会话徽标——所有用 catalog/activity 轮询的地方）：
   - 后台刷新期间始终渲染上一份成功数据；不显示 loading/状态文字切换，不卸载重挂列表，不改变选中项/滚动位置/焦点/展开状态。
   - 稳定 key（bot id / session id）；在 setState/notify 前做结构相等比较（结果与上次相同则不通知订阅者、不触发重渲染）。加测试：相同数据刷新时订阅者调用次数为 0、组件 render 次数不增加。
   - 首次加载才允许显示骨架/加载态；错误只在发生时内联显示（保留旧数据），恢复后自动消失。
2. **删除"就绪"状态行**：右栏 Bot 资料只在异常（preset broken/missing/unknown 等）时显示内联提示，正常状态不显示任何状态文字。
3. **智能轮询**（共享一个调度器）：
   - 仅当文档可见且窗口聚焦时轮询；`visibilitychange`/`focus` 时立即刷新一次；自己的变更（创建/编辑/删除/markRead/新会话）后立即刷新。
   - 退避：有变化时 5s；连续无变化逐步退避到 30s；检测到变化或用户交互回到 5s。失焦/隐藏时停止。
   - 评估 rc.2 是否有干净的公开流式 `watch()`/订阅机制（Remote stream / event forwarding）可用于 activity/catalog 变更通知；若干净可用则采用并保留轮询兜底；否则在 `docs/dsh-api-notes.md` 写明不用的原因（附源码出处）。
4. **会话真实标题**：会话历史（右栏、弹层、右侧栏）标题用会话真实标题：优先公开的会话标题来源（Host `sessionProjections` title / Client 会话列表投影 / SessionTitle observation，选最干净的公开来源），其次该会话第一条用户消息摘要（T08c activity 可在首条 user 消息时记录 `firstUserPreview`），最后回退"新会话 / New conversation"。**绝不使用工作区名作标题**。工作区名仅在与当前上下文不同且有意义时作为次要 meta（小号灰字），否则不显示。没有预览时不要显示"暂无消息预览"占位行，直接省略该行（或仅在首条用户消息存在时显示它）。
   - 查清 `pod_0814` 为何成为标题（是 catalog 的 title 字段回退到 cwd basename？）并修复根因。
5. i18n 中英文；不使用私有 API。
