# 群成员管理统一入口与安全增删

本记录对应用户已批准的整体设计、实现和本地部署阶段。实现基于 main `3c6cc22d3939fcba284199d524c782d58a941524` 的独立工作区，保留原工作区改动。实现阶段未公开发布、提交或推送；后续发布工作单独记录于 [0.7.4 发布任务](release-0.7.4.md)。

## 范围

1. Bots 群目录详情、原生群会话管理页、右侧群成员、旧群页面及设置入口统一为“管理成员”。主列表与紧凑列表均有“移出群聊”。
2. 复用现有 Modal、公开 DSH Menu/Button、成员存储和刷新链路。管理弹层展示完整未移除成员（含停用/不可用），草稿增删、撤回及变更摘要；单人移出只确认一次。
3. 纯移除/排序/普通设置不要求新增历史授权；存在新增 Bot 代际时由 Host 校验明确确认。混合变更及团队配方应用按同一规则。
4. 最少两位、上限以 Host memberLimit 为准（旧视图默认六位），停用占名额。超额旧群允许渐进减员；保留不可用成员不阻断纯减员，不能自动启用或添加不可用 Bot。
5. 成员编辑提供绑定准确群代际、请求及版本的操作收据。成功后刷新失败和写入结果未知分开处理；不盲目重放、不覆盖另一窗口新修改。
6. 移出保留 Bot、群历史、私聊和私有记忆；取消准确成员的未结束群执行。旧受众授权失效，不自动发送旧待审正文。自动群、归档、恢复状态保持现有边界并解释原因。
7. 按需响应设置不改变成员名单；人数、头像、@ 候选、成员模型菜单同步。关闭管理保留聊天草稿、引用、折叠和阅读位置。

## 验收与部署门槛

- 有意义的 Host/Client 回归：纯减员、新增确认、混合变更、团队配方、停用/不可用成员、上下限、重加/重建身份、运行取消、多窗口版本冲突、重复操作及冷启动收据。
- `scripts/pnpm check`、文档与格式检查通过；以真实结果记录失败和未运行项。
- 打包后同包隔离 rc.2/日常宿主版本测试，并使用真实浏览器核对所有入口、亮暗主题、窄侧栏、焦点与滚动。
- 验收通过后冻结包及 SHA；部署前核对日常宿主/profile，冷备份并保留可恢复原 profile，只更新插件。
- 部署后核对实际加载字节、原有数据与配置保留，用精确标识的临时群验证成员增删、同步及恢复；不在真实群试删，不发付费模型消息。
