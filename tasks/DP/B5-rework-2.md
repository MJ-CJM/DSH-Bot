# B5-rework-2（基于当前未提交工作区）

## 1. 写入成本二次增长（P0 性能缺陷）
独立日志逐条写入实测：1000/2000/3000/4000 op 累计 35/108/232/393 s，单次写入约 35→160 ms 随日志线性增长。
- 先剖析根因（node --cpu-prof 或计时分段），在 docs/deepening/B5-rework-2.md 写出证据：哪个函数/哪次全量读写导致 O(n)。
- 修复为单次提交成本近似常数（追加写、增量投影/快照、批量/节流 snapshot 等），保持 ops 为唯一提交点和崩溃安全语义；不改 storage-domain 公共格式之外的东西，若需要说明理由。
- 重测：1 万次独立 op 写入（报告每 1000 段耗时与单次 p50/p95，目标单次 p95 ≤20 ms 且无随 n 增长趋势）+ 30 次新进程冷恢复 p95（≤2 s）。如实报告。
- 增加回归测试：n=500 与 n=5000 的单次写入耗时比 ≤2。
