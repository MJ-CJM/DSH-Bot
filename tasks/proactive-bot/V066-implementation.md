## 实施接缝

1. 旧 CI 严格 schema 与 Remote 保持兼容，通过内部判别视图接入通用 Subject；不把 CI 条件拆成大量 optional 字段。
2. 开启服务的恢复准入必须在 coordinator hello/ready 之前提交，不能等 pending/自动派工/通知恢复后再暂停。
3. 公开 v0.6.5 没有主动协调器，属于原生 domains 保留与协调库首次创建；本地开发快照需要既有 SQLite 版本迁移，不能共用一个虚假升级夹具。
4. 已复用固定版本 Engine 的公开 attach/retryTicket：明确 owner 续办事务只为原任务许可一次重开，保留原 Ticket 和历史尝试。未知执行结果不可重试。
5. 新的群 ownerFollowUp 分支复用原群队列、模型选择和原生 Agent；只执行所选一名成员、一次只读请求。原失败 turn 是归属引用，用户提交新的具体指令，不宣称恢复原进程。SQLite 接受收据与原生投递之间通过同操作核对，不声称跨存储原子提交。
6. 已将主动子 fiber 与稳定 Bot registry 分离，ConfigEditor 仍在写盘前校验。两套隔离 Host 的首次启用、旧队列隔离和握手/收据两个强杀点已在最终冻结包重跑通过。
7. 群原生子任务的审批策略为 never。群聊天工具只提交待确认卡片，明确 owner 操作后才成为有效关注。个人聊天继续走正常工具审批；不为群功能改变原生子任务审批边界。
