### 根因与漏测原因

宿主证据 `dist/screenshots/2026-10-19T04-41-47.579Z-63798/` 显示活动读取失败，但 Bot/原生历史标题正常。正式 Client 使用 `ctx.get('remote.dshBot').activity`：rc.2 将 activity 注册为独立服务，父服务上的 traced 子属性仍要求该子服务的 inject。正式插件没有此注入，实际错误为 **`cannot get property "remote.dshBot.activity" without inject`**，发生在发起 HTTP 前。

## 设计取舍与遗留问题

1. 详情只显示摘要与会话列表。打开会话导航到原生 Conversation，不试图嵌入独占会话视图。会话 membership、running 来自公开 Host catalog；T08c 活动只补摘要，不伪造未采集的历史预览。
2. `activity.list()` 没有自定义 Remote 推送，页面/footer/徽标共享低频轮询。footer 常驻时即使不展开弹层也轮询活动，以刷新入口红点；文档隐藏与插件卸载停止。Bot 元数据在 footer 仍为被动订阅，继承既有跨 Client 更新边界。
3. **r1 修订：已读尽力而为。** 入口先尝试 markRead，失败仅记录本地化轻量 warning，不输出原始异常/载荷，仍导航打开；无摘要的旧/空白/LRU 会话同样可打开。失败不伪造本地已读，新回复不被抹掉，轮询失败保留上一份成功数据并保留重试提示。unary Remote 不支持撤销；离开页面或有新导航时仍阻止晚响应抢回会话，不回滚已提交 markRead。
4. 隐藏哨兵沿用 string 合约，避免新增字段或迁移。保留值恰被用户当正文输入时也会显示隐藏；秘密识别仍是 T06 启发式，不保证识别所有秘密。
5. 原生已读采用公开主视图引用与面板状态，不依赖 DOM 查找、私有 selection 或 `client-test-runtime`。空白会话不挂 header utilities，尚无 assistant 未读。实际桌面/浏览器挂载行为需宿主最终验证。
6. 唯一待交接项：在仓库根由宿主执行 `DSH_HOME="$PWD/.dsh-dev" node scripts/screenshot.mjs`，检查新生成的 7 张 PNG、summary 中的 layout/preview/contrast/conversationChecks。需要旧编辑器补充矩阵可加 `--extras-only`。未执行项在本报告保持 FAIL，直到有本轮真实证据。
