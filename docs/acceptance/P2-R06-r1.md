## 根因与证据

编排方证据 `dist/screenshots/2026-10-21T10-03-26.708Z-28269/summary.json`：`stage=avatar-ui`、`step=v022-avatar-light-open`，精确匹配的“编辑”按钮先 disabled，随后 detached；0 model requests、0 page errors。

这是两个因素叠加，并非头像加载：

1. `BotList` 行 click 同时调用 onSelect 和 onActivate。R05 的 onActivate 打开 Bot 主会话；`startBot` 等待公开 `dshBot/openConversation` 后执行宿主 `uiWorkspace.openSession`，切离 Bots 页。
2. 原 `BotsPage` 把 chat.start 与保存/删除放在同一个 perform 中；perform 设置全页 busy，“编辑”使用 disabled={busy}，因此等待主会话创建/迁移/读取期间不可编辑。成功导航使整个页面卸载，故脚本继续等按钮也无用。

`ready` 只控制“打开对话”；编辑原本不直接依赖 preset/session loading，但间接被导航共用的 busy 锁住。无法仅凭这份摘要判定 Host 当时具体处于创建还是迁移；这些阶段都会走同一问题路径。

## 修复与决策

决策：把导航状态与 Bot 写入状态拆开。理由：已有 Bot 数据足以编辑，主会话尚未打开不是编辑的前置条件。

- 导航单独持有 AbortController/navigating；保存/删除/复制继续共用 busy/busyRef，防止重复写入。
- 编辑、记忆、创建等管理对话框开启时取消尚未完成的导航；复用既有 startBot/openSession 的 signal 门禁。迟到成功不跳转、不关闭编辑器；迟到失败不覆盖编辑草稿；导航 finally 不解除写入锁。卸载时取消导航。
- 取消的是 Client 跳转意图，不回滚 Host 已受理的主会话创建或迁移。正常点击 Bot 行仍打开其主会话，保留 R05 行为。

决策：头像脚本使用原生列表 Home/ArrowDown 只选中详情。理由：此次要打开编辑器，行 click/Enter 是打开会话操作，等待无法改变其导航含义。

- 仍核对目标 Bot 的真实 id、aria-selected、可见详情和精确“编辑”名称；`click({trial:true})` 等待可见、启用、稳定、可接收事件，然后再次断言启用并正常点击。
- 没有 force、增加超时、删断言、换宽松选择器或 DOM 注入。原有六种造型、12 色、键盘激活、对比度和可见几何断言保留。
- 失败时先保留活页交给外层取证，外层 finally 关闭 browser；不再提前关闭 context，避免只得到“No live browser page”。
- `scripts/screenshot.mjs`、`screenshot-routines.mjs` 未修改；编排方已报告通过的 `--v022` 流程保持原样。主会话导航/原生定时组件等现有回归均随 check 通过；本轮没有重新证明浏览器 `--v022` PASS。
