## 实现边界

`Messaging.send(agent,input,invocationKey)` 是 Host 内部接口。它拒绝非 exact live 主 Agent、旧生日、子会话、未知/混合来源及已走过的请求路径；从当前原生日志推导 parent、thread、origin/hop/depth，不接受模型的 from/session/authorization 字段。生产入口未注册 `bot_message`、Remote 或 UI。

`messagingEnabled=false`。即使显式设 true，默认构造的授权适配器拒绝发送，且 processing capability 未开放，不启动自动恢复/唤醒。这不是 PTC 导致整体功能回退，而是 B04 原生审批、工具守卫与卸载保护尚未接入的阶段边界。测试仅在独立合成 profile 内注入运输层授权适配器、注册 scoped `bot_message`；**这不能作为正式原生审批已通过的证据**。

新领域 `dsh_bot_messaging` v1：messages 为完整发送意图，threads/dedupe 为可重建索引，limits 先持久预留，read_state 此轮只定义契约。回复/镜像各有真实 native ID，queued 仅表示意图持久受理，delivered 必须 flush；业务 claim、模型结束、回复投递分别记录。正文只通过原生 UserMessage/Inbox/Session 日志流转，不伪造 assistant 或 turn/end，不另开成对会话。

消息接受按一个 Host 的 admission 队列串行；投递按目标 BotKey 串行，均不持有 registry 写队列等待 Agent。Store 同一 Domain handle 的多 wrapper 共用写队列。没有新增跨进程锁，不承诺跨多个 Host 的事务或 exactly-once 外部副作用。

首次投递前将 delivering 落盘。恢复读取 flush 后完整持久日志：已入箱/已消费按原 ID 对账，不重复业务 send；人工 canceled 不复活；claim 后缺少可确认处理证据进入 unknown；缺失/替换主映射、删除/新生日不换路由。已确定发生于 native send 前的暂时 resolve 失败才有有界重试；不确定窗口保留 unknown。reply 固定回直接发送方。

限额默认遵守 §14：depth 3、hop 8、thread 16、开放 ask 4、Bot 对请求 6/60 秒/总计 12/60 秒、打断每对 1/60 秒及每目标 3/10 分钟。新 ask 预留返回预算；限流 reply 有持久 nextAttemptAt。限额时钟保留已记录最大值，回拨不给额外额度。重试 1/5/30/300 秒、最多 5 次。其余字节、TTL、积压、目录和保留参数均在导出 Config/Schemastery。

只有双方日志引用齐备、处理完成且线程不开放的记录，才在后续对账活动中按默认 7 天移除 outbox 正文/完整 native 对象；原生历史不动。去重墓碑保守保留超过默认 30 天，不因过期自动重放旧 invocation。旧滚动限额预留可清理，但保留最新接受时钟；无流量时不承诺精确到时钟的后台清扫。

## B04 接续与决策

1. 在 scoped 正式工具中绑定真实 ToolExecution 的 session/turn/step/rootCallId/callId，接入原生 pre-execute/guard/审批；生产 `MessagingAuthorization` 只能由已批准的精确操作返回授权 ID。替换 index 中的默认拒绝适配器并在守卫就绪后才开放 processing。
2. 线程内已批准只读询问/reply 复用范围，interrupt 每次独立审批。原生 deny/cancel 不可被覆盖。目录使用 B01 已证实的 required context，同步读取 registry 快照，处理 deny/旧代际/卸载。
3. PTC 按 §14.4 回退：run_code 子调用禁 bot_message；队友来源轮次的 run_code 原生 ask。补嵌套/混合来源测试，不能仅靠提示词。
4. 保持群 worker/Team teammate/delegate 的既有边界；补三层逐层 reply、同名 MCP 隔离、全量高风险工具批准与拒绝的真实 mock。B03 运输探针注册器只留在 tests，不用于产品。
5. 默认自动处理仍关闭。补 wake 只剩控制输入、用户取消竞态、强杀中间窗及 retained Agent guard 后，才按 B04/B06 决定开启相应 capability。

决策：交付 B01 基础 API、B02 持久契约和 B03 Host 运输层，继续采用原生 SessionController/Inbox/日志与工具循环。理由：真实首次/冷 Host 已证明该路径，无需自建模型循环、成对会话、schedule 轮询或修改 DSH；未证实的 PTC、正式 UI 与卸载/极端恢复能力保持单独门禁，不冒充已通过。
