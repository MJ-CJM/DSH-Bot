## 设计取舍

1. **原生 leading 格不是可扩宽区域。** 锁定版行高 32px、格宽 16px、高 20px、标题左距 4px；schedule 本身也占 16px。简单并排或负边距会压标题/越过平铺行左边界。因此 Bot `order:0`，检测自身后面是否存在非 style 元素，存在则仅隐藏自身，保留 `order:10` 的原生时钟。只用自身 CSS，不覆盖宿主布局，不查询或复制 schedule 私有 catalog，不依赖 schedule 私有 DOM 标记。其它后序插件输出元素时也保守退让，即使该元素自身不可见。这个选择意味着有时钟的 Bot 行主要通过 hover 标识身份。
2. **尊重宿主状态优先级。** 非 idle、空白、归档和搜索行不提供 leading。运行中/待交互/新消息状态点仍由宿主控制。没有额外未读点；既有 Bots 页/footer 未读提示保持原行为。
3. **复用头像约定。** `BotAvatar size={16}` 默认着色鲸鱼；已配置 emoji/图片的 Bot 保留用户头像。悬浮卡片自带 alias 背景和前景，避免在固定暗底宿主卡上直接使用亮主题文字色。
4. **刷新与一致性。** 两份数据第一次成功前为空，后续轮询保留最近成功快照。可见行持有共享主动轮询 lease，沿用 `Config.pollIntervalMs`（默认 5 秒）；外部删除在下一次成功刷新生效。Bot catalog 与 activity 没有共同 revision，不保证原子快照或瞬时删除消失。无摘要的安装前/空白/已淘汰历史会话不猜测身份。
5. **截图证据独立。** 新增工作区两张在原矩阵最后运行，避免打开原生会话改变原有未读样本。独立模式从原生工作区树进入，不提前挂 Bots 页面暖 catalog。失败后对此导航调整只做语法/helper 检查，未重复尝试受阻 Chromium。
