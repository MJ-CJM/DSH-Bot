## 实现约定与自主决策

- **决策：T12 提供独立工厂，暂不接入生产 patch。理由：**尚未实现拥有真实锁的 Host coordinator，不应提前打开第二个可写域。`openAutomationStores(ctx,{assertOwner,ownerId,resolveBot,...})` 要求先持锁，打开和每次写入均调用 owner 门禁。`resolveBot` 支持异步，通过后续协调器的公开 registry get/status 提供实际 presetId；不拼接 preset 前缀。
- **决策：Run 是 reservation、去重和扣额的权威，control 与 Routine cursor 是投影。理由：**公开 Domain 没有跨表事务。`enqueue` 写 queued（无额度），`reserve` 单行写 running/step=reserved、quota receipt、slotHeld，再修复 control；scheduled 的 Run 另保存 nextRunAt 决策供游标修复。重试先修复投影并返回原 Run，不重新分配会话或扣额。
- **决策：采用保守恢复。理由：**T12 不能核实原生会话和副作用。重开后已收费的非终态变为 recovery_needed，保留并发占位；执行器提供确认后才允许终态释放。失败、取消、超时均不返还当日额度。queued 在 reserve 前重验目标 Bot 的 createdAt、Routine 删除/启停/规则代际。
- **决策：暂停恢复增加 ruleRevision，重新计算未来目标；已过期 at 保留原绝对时间并耗尽。理由：**暂停期间不补跑，旧 generation 的 queued occurrence 不能复活。仅改标题/prompt 不改 ruleRevision，等价规范化规则也不改。manual 可在暂停中运行，不改游标；删除 Routine 软删除并保留历史，不终止已 admitted 的运行。
- **决策：不提供 Run 硬删除/历史裁剪。理由：**去重和配额仍需要这些记录；列表支持最多 200 条的游标分页。未来压缩必须保留必要墓碑，不能直接按 UI 显示数量删除。
- **决策：每日时区首次取系统默认并持久固定，显式改时区或额度日期倒退拒绝准入。理由：**避免更换时区/时钟回退产生空额度桶；control 缺失可从收费 Run 重建。计数按 botId，自然日分桶，重建 Bot 不返还已有额度。
- **决策：Remote 为单独 contribution。理由：**保留 P1 的 19 个端点和启动行为，后续 Host 持锁开域后调用 `registerAutomationRemote`，Client 显式 `$mount` 新 contribution。新增 7 个端点，写操作只允许 Routine CRUD；run_now/取消/回报投递留待对应服务实现后再扩展，不发布空实现。
- **决策：持久 report 限定完整的单文本 user notice 消息。理由：**本阶段只需要摘要回报；保存公开 `createUserMessage` 产生的固定 id/content/source，校验 run/session/message 身份，避免任意 JSON 进入回报状态。summary/message 文本需通过既有凭据启发式筛查；筛查不是完备脱敏。实际 followup 与来源防循环由 T15 完成。

状态：`queued / running / waiting_approval / succeeded / failed / cancelled / timed_out / skipped / recovery_needed`。创建/提交属于内部 step。终态不可再次运行；占位运行结束必须传入执行链已确认停止的内部证明标志，Remote 不暴露它。回报 `pending / sent / blocked`，sent 仅表示调用方确认持久入箱，不能解读为发起 Bot 已处理。
