## 设计取舍与遗留边界

- `displayTitle` 本来就是宿主展示标签，会回退 cwd basename。这是 `pod_0814` 成为标题的根因，不是 Bot catalog 的 Bot 名字段错误。公开 `SessionSummary.title` 是更干净且随投影更新的来源；所有候选标题继续共用摘要脱敏，避免 live title 绕过保护。
- 首条摘要的 schema 为兼容扩展，旧记录没有字段仍可读取。自有 Host-only projection 只保存 120 码点以内的脱敏摘要，注册不直接读日志；第一次所需 materialize 由公开 ProjectionRegistry 负责。旧会话无消息完成、没有 projection 服务或无法取得首条时回退“新会话”，不猜测、不扫描私有状态。本轮未重复完整磁盘冷启动 profile。
- 推送帧只有进程内 revision，不是数据或 durable cursor。opening 后完整读回关闭断线空窗，慢消费者合并通知；Host 自身 preset 健康等外部变化仍由轮询发现。rc.2 raw stream 不自动执行严格 encode/decode，双方显式 parse 已经测试。
- 基础间隔保留原 1000–60000ms 配置兼容范围；新增 `maxPollIntervalMs=30000`，实际上限为 `max(base,max)`。默认正是 5–30s。显式写后读回允许在失焦后完成，定期轮询和 stream 均停止。
- 相同数据不再重复驱动 React effect。当前会话自动 markRead 的偶发失败仍保留未读，重开会话、可见性转换或新活动会重试；不把重复的相同轮询响应制造成组件更新。
- A/B 在真实 HTTP 响应体完成且 `server-response.result.ok=true` 后计数，三个 catalog 端点各至少两次、间隔至少 5s，90s 内未满足直接失败；等待两帧后截图 B，observer 覆盖至 B 完成。比较 PNG 完整内容/hash、DOM、对象身份、焦点与滚动，瞬时变化也失败。仅检查静止种子会话，不冻结时间或 mock 浏览器状态。

## T08g r1：宿主截图失败根因与修复

### 根因：脚本未等待独立的原生会话列表首次加载

已核对编排方两份原始 `summary.json` 与 `failure-zh-dark-wide-bots-layout.png`：

- `dist/screenshots/2026-10-19T09-06-27.029Z-19669/`
- `dist/screenshots/2026-10-19T09-10-17.147Z-21867/`

**两张失败 PNG 的会话历史区域均为“正在加载会话…”，并非已显示两行而缺少 `data-session-id`。** 旧版 `captureFailureEvidence` 先 `await page.screenshot()`，再 `page.evaluate(readFailureState)`，因此 summary 中含两条会话的 `mainText` 是截图完成后的另一时刻，不能证明排序断言发生时两行已存在。

矩阵每个语言/主题案例都会销毁上一 browser context 并创建全新 Client。旧准备条件仅等待 Bot 的 activity 预览、创建按钮及左右栏几何位置；这几个条件都可能在独立的 `sessions.list` 首次结果到达前满足。此时 Bot 资料已显示，但历史仍为合法的首次加载态，`readBotsLayout().sessionIds` 正确返回 `[]`。中文暗色连续命中这一竞争窗口，不是该主题修改了行属性。

产品渲染条件在 `packages/dsh-bot/src/client/pages/BotsPage.tsx`：`sessions.phase !== 'ready'` 或 activity 尚未首次加载时显示初始 status；实际历史按钮总是带稳定 `key={session.id}` 与 `data-session-id={session.id}`。锁定 rc.2 源码 `packages/api/session-controller/src/client/sessions/manager.ts:35–42` 明确 `phase` 从 pending 到 ready 单调变化；`refreshList()` 的 `:413–443` 在首次成功响应后设 ready，后续后台拉取只切换 `state`。结合失败 PNG、全新 context、组件延迟原生列表的确定性复现，根因属于脚本首次就绪条件遗漏。本轮没有修改产品刷新或列表渲染逻辑。

### 修复与防止掩盖闪烁

- 新增 `waitForInitialBotHistory`：宽屏选择 Bot 后，先等待该 Bot 的本地化历史 region 可见，再等其中的初始 status 消失。单独的 `*-initial-history` step 超时会失败，沿用 30s 页面超时，不增加固定睡眠。
- **不等待预期 session id 或排序“最终正确”**；就绪后仍一次性严格比较完整 id 数组，已加载的空列表、错 Bot、缺行和逆序仍立即失败。原 A/B 检查、MutationObserver、像素比较、节点身份与焦点/滚动断言均保持。
- 每次布局断言前写 `layout-checks.json`，保存同一次 DOM 求值的 sessionIds、detailStatuses、capturedAt。失败诊断改为先采 DOM，再截图，并分别记录 domCapturedAt / screenshotStartedAt / screenshotFinishedAt，避免把不同时间样本当成同一状态。
- 中英文组件测试从 native `phase=pending` 启动，同时已有 Bot/activity 数据；验证初始列表确实为空并显示 loading，原生首次响应后按新到旧显示两行，随后两次相同刷新无新增 render、无节点替换、无属性/文本/子节点 mutation。
- 脚本辅助测试验证 region/status 等待顺序、超时传播、不重试 id/顺序，以及截图期间 DOM 变动不会被误记为截图前文字。上述均为 jsdom/服务 double 检查，不代替宿主浏览器结果。
