## 设计取舍

使用任务允许的最弱公开审批机制 `tools/pre-execute → ask`，不新增工具正文二次询问。先保留下游 deny/cancel/ask，仅把 allow 提升为 ask；DSH 处理 open-turn 审计、会话 never 策略及取消。审批说明从中英 locale 读取。DSH 原生拒绝没有稳定结构化错误码，沿用其错误文本；业务 DshBotError 则通过 HarnessError 保留 code。

参数复用既有 schema：create 的 id/name 放在 input；get/update/delete 的 id 放顶层；delete input 只接受 deleteMemories（默认 true）。不适用字段严格拒绝，update 替换顶层对象，null 清除四个已有可选字段。删除不删除会话历史，但缺失 preset 会阻止冷恢复，审批说明与工具描述明确此影响。

standard 使用当前 `composedPreset`，不使用创建时 header；Bot 使用公开 scope 链定位精确 generation，以免稳定 id 的旧代际干扰新代际。工具与审批成对交接，仅协调本包定义；不会覆盖其它插件同名工具。T07 只补管理工具的 preset 选择处理，不重写 T05 的记忆、人设或模型生命周期。

## 遗留问题与建议

- `pre-execute` 本身是可信宿主插件的可扩展 waterfall，更外层插件仍可短路/改写结果。该方案不是对任意第三方插件的隔离边界；若以后要求强制工具正文审批，应单独调整契约与组合测试。
- standard 开关启用时不扫描已有 live Agent；新建、冷恢复或之后的空白 preset 选择事件生效。
- T07 的空白切换通过只证明 bot_manage；T05 的 binding/memory/model 在该路径上的完整语义应另行验证，不由本轮结果外推。
- 工具正文进入 Registry 写队列后不保证取消撤销已接受的写入；沿用既有串行事务及跨表删除边界。
- T10 仍需真实 UI 审批确认/拒绝与模型→bot_manage→UI 刷新闭环。此次真实 Host 只验证激活、工具挂载和已有冷恢复回归；standard 开启及切换使用公开服务测试，未称为完整 Web/桌面实测。
