## 实现与决策

- 删除 `routine_*` 的注册实现和中英描述，Bot 提示改为 `Use schedule_* for scheduled tasks.` / `定时任务用 schedule_*。`；保留其他 Bot 工具。
- Composer 保留宿主 `dsh-tool-schedule` 行，缺失时补入，包括默认 minimal。已有嵌套行不重复，id 冲突拒绝；不修改原生 standard/minimal 定义。
- 决策：只在 Agent 的 deny 参数中过滤已退役的五个准确名称，不重写 Bot 数据，也不把旧 deny 映射为 `schedule_*` deny。理由：原生未知 deny 会导致 Agent 创建失败，但宽泛忽略任意未知名或改写权限会掩盖配置错误。测试确认 `routine_typo` 和其他未知名称仍拒绝，显式 `schedule_delete` deny 仍隐藏工具并拒绝调用。
- 决策：复用原生工具自身的作用域、参数及执行逻辑，不新增包装工具。理由：原生已支持当前会话 CRUD，满足 R01。新增 `@deepseek-ai/dsh-tool-schedule@0.2.1-rc.2` 仅为精确测试 devDependency；产品仅通过宿主 Loader 行加载，无新 runtime import/peer。
- 决策：旧 Routine UI/Remote/Dispatcher/数据层留在过渡实现。理由：本任务只收敛模型入口，完整方案 A 的聚合、调度删除和迁移由后续任务处理。此轮不宣称两套存储已合并。

## 遗留与建议

R01 必需验收无阻塞。原生 schedule 服务必须由宿主启用；用户禁用该服务/插件行时不强行启用。显式原生工具 deny 和完整人设抑制其他 prompt sections 均遵守既有行为。当前版本进程中已加载的旧插件/旧 Agent 不会被文件修改自动替换，需重新加载版本后验收；此轮未操作桌面应用。

后续继续方案 A 的 Bots 原生聚合、旧 automation 数据兼容与 Dispatcher 收敛；这轮没有迁移或删除旧任务，也不把原生投递回执当执行成功。
