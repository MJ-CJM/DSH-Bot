## 4. 决策及实现边界

- **决策：采用唯一后继文件的锁代际，而不是删除陈旧文件再竞争。理由：** 多个 stale reader 的 unlink 存在删除新 owner 锁的竞态；每个旧 token 只允许一个后继 `wx` 成功。保留前代小收据，不做在线清理。
- **决策：ps 不可用时记录 `unverified:` 开始时间，仅死 PID 可接管；活 PID/未知状态保守只读。理由：** Node uptime 估算值不能与 OS 启动时间精确比较，不得据此误判 PID 复用。没有绕过沙箱或以测试替代系统结果。
- **决策：follower 只提供只读诊断，不打开业务领域。理由：** 既有 P1 启动会 prune/seed/修复，JSON 后端没有共享实时只读缓存保证。此阶段 P1 方法返回 unavailable，automation CRUD 不注册，避免第二 Host 意外写入；不是业务历史只读镜像。
- **决策：存实际 create 回执，prompt 前重验 Bot 身份/更新时间/preset。理由：** create 的请求 sessionId 不保证原样返回；创建期间 Bot 删除/更新不能继续用不明配置发模型请求。
- **决策：停止无法证实时保留 slot 和 recovery_needed；同进程卸载时不释放可能仍有外部操作的 lease。理由：** 取消只表示请求发出，不能将它当成副作用已终止。正常确认后才终态并释放；不自动重放。
- **决策：Host 根入口激活内部服务，不新增 Loader 子路径导出。理由：** T12 两个 export 不属于 DSH 加载必需，按返工要求移除。
- **决策：只暴露只读 status，不提前增加 run_now/cancel Remote。理由：** T13 提供内部 execute/cancel 边界，后续 Dispatcher/工具统一处理身份、审批和准入，避免提前扩大产品入口。

后续建议：T14 接入 Dispatcher 时使用同一 stores/executor，不另开可写 domain、不绕过 reserve；T15 执行器之外实现来源闭包和持久回报；T16 增加状态/UI 文案和 Client 挂载。在允许 OS 进程查询的环境复验启动时间核验。本期不支持不同 DSH_HOME 共享同一自定义后端、多机或网络盘，也无法保护不遵守本锁的旧 P1 Host。
