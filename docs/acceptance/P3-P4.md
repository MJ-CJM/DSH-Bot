## 决策、遗留与建议

1. 决策：沿用 §14 依赖门禁继续交付其余功能。理由：IM consumer gate 没有公开 fake 注入与卸载无 fallback 实测；禁用是已验证行为，收发不是已完成能力。OS 通知无公开 API，同样不自研内部桥。
2. 决策：市场仅 fixture + mock registry。理由：没有已发布 0.3.0 npm/最终 Git tag，不能写虚假正式索引或运行只读 private generator。Git nonexistent path 的远程安装、发布后的版本匹配与外部机器安装仍 FAIL（未执行）；parser 的 path traversal 拒绝不能替代远程 Git fetch。
3. 决策：修复 Client CSS 虚拟标识中的构建路径后重打包。理由：第一次包审计真实发现 client.js/map 泄露 checkout 绝对目录；相对标识和新增 bundle 回归已通过。pnpm manifest 重新序列化仅比语义，所有安装文件仍严格比 tgz 字节。
4. 开发中包审计先后发现 CSS 绝对路径和 pnpm manifest 序列化差异，均修正后重验。market fixture 的内容寻址缓存导致“必须下载 tgz”的初轮断言失败，现为每轮生成独立合成归档并实际验证版本错配；升级探针等待完整公开 ready 状态，避免将服务启动竞态误判为数据损坏。早期失败日志和收据保留，不计为最终 PASS。
5. 编排方在允许 Chromium 启动的环境按截图 README 重跑同一脚本；仍需按设计 §13 核每页身份/状态/取消/冲突等交互，不能只凭 PNG 生成就宣称全部流程通过。本轮没有绕过沙箱、请求新增审批或修改浏览器/桌面安装。
6. 真实 GitHub 等 MCP、飞书/Lark 收发、OS 通知、关闭 Host 后推送、桌面体验、线上发布均 FAIL（不支持或未执行）；不会自动 commit/push/publish。只支持同一数据后端一个活动 Host，单写者不协调外部程序。
7. 群内 ask 拒绝、群/记忆提交间的物理强杀窗口仍 FAIL（未执行）。正常冷恢复、取消、半批失败、max_tokens 和 server 强停的实测不能替代这些窗口。
