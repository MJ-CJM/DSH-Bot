## 决策与完成范围

决策：U04 交付可选服务检测、锁定来源说明和中英禁用诊断，暂不注册 consumer、不连接通知投递端口，也不新增绑定/发送 Remote。理由：U01 `im-consumer-exclusive-dispose` 仍为 FAIL/NOT_RUN；既有 API 核实记录明确该 gate 未通过时不得启用入站/checked 平台投递。按设计 §14-2 关闭依赖功能并继续 U05。不存在用 Config、fake 服务或仅检查方法名绕过此 gate 的开关。`pin` 表示要求的源码提交，不冒称从服务合同检测到了已安装 commit。

决策：U05 只保存 BotKey → 主会话/原生 Team ID 的关联，原生 Session 中的 roster/tasks 是唯一事实来源。理由：原生 Team 已有成员持久化、依赖和 CAS；不存在单独的 createTeam API，每个有效顶层 lead 的 Team 是隐式的。用户点“创建／关联主会话任务板”时复用 `openConversation`，不会创建第二个 Bot 主会话。任务只提供创建、claim、complete；不实现 reassign、成员伪装或独立 preset 注入。

决策：宿主显式启用原生 `agentTeams` 服务后使用任务板；服务缺席时显示“当前宿主组合未启用”。理由：它是实验组合，本包不自动安装、挂载或接管全局原生服务，也不为缺席场景复制任务板。已有 `bot_delegate` 保持原实现。Teammate 的创建和配置由原生组合负责，此次 UI 不提供 spawn 编辑器。

## 实现与边界

- 独立 `dsh_bot_collaboration` v1，只有 `team_links` 表；不改旧 Bot/Memory/Session 表。身份包含 Bot 生日，关联创建携 `expectedRevision`，坏数据由 storage-domain 拒绝并保留。
- 每次任务操作校当前主会话、exact live Agent、Bot binding/生日、顶层 lead membership 和 Team ID；不接受任意 sessionId、agentId、agentPreset 或 owner。输入/输出均用同源严格 Zod/Typert codec，Gateway 也拒绝额外参数。
- 任务变更直接交给原生 `createTask/updateTask`。原生 stale revision/已领取映射 conflict，依赖阻塞映射 invalid；不返回原始错误。额外确认 `sessions.flush=true`，不确定持久化返回 recovery-needed，不自动重放创建或任务变更。
- 只读任务板不创建主会话，但有关联的冷会话会经原生 resolveAgent 恢复。原生 Teams 可恢复已有子代理运行；不能承诺查看冷任务板时原生恢复绝不调用模型。本包没有补跑或发送队列。
- Host effect 管理关联 domain 和 Remote；关闭先拒新请求、等待正在处理的请求再关 domain，不处置宿主拥有的 lead/Team service。Client 沿用统一轮询、focus/reset/watch 和 epoch，保留草稿/焦点/DOM。locale 中英同键，样式复用已核实主题 token。
- 新增原生 Team 精确 rc.2 **devDependency**，正式 Host 只有 type import，没有新增 Team runtime peer。可选 dsh-im 不进入产品依赖；只在隔离 profile 安装锁定包。engines/exports/版本不变。

## 遗留问题与建议

- 先补齐锁定真实 dsh-im 的公开 fake 平台 consumer 注册/注销与无 fallback gate，再实现/启用入站、绑定、去重、replyChecked 和通知端口；这次仅交付禁用诊断。真实飞书联调另由用户验收，不能拿契约 mock 代替。
- 原生 Teams 需宿主显式挂载 `@deepseek-ai/dsh-experimental-agent-team@0.2.1-rc.2`（公开根 default 服务）。本包不会提供跨机器或跨 Bot preset Team、任务重分配、任意后台补跑或文件锁。
- 浏览器需在允许 Chromium 启动的执行环境重跑真实亮暗/窄屏验收。当前 DOM、token 和 Host 结果不能替代截图。
- 首轮失败目录保留：`runtime-1792862762955-57946` 是按全局 agents.get 轮询 child idle 而错过短暂生命周期；改为先取得 Agent 再 await 公开 whenIdle。`runtime-1792862861034-61078` 是探针对额外 Gateway 参数会被忽略的错误假设，实测严格拒绝；恢复负向断言。`runtime-1792862925088-62869` 两阶段 Host 已通过，但 runner 错误预设只会有 1 次模型请求，实际有 2 次 loopback；后续核实额外请求来自原生 subagent-settled 唤醒 lead，并按阶段记录 worker/parent settlement。`runtime-1792863019138-66156` 保留了错误套用 lead 零模型断言的失败；`runtime-1792863164512-70033` 保留了遗漏原生 runtime-context 来源的过严断言。最终检查原生 settlement 来源与 child 关联，并比较任务板操作前后的 lead assistant 计数不增加。未把这些失败目录改写成 PASS。
