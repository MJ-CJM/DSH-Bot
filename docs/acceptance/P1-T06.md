### 设计取舍与遗留

- 整条遗漏数只统计本次 snapshot 候选，injectLimit 之外的记忆不计入 N；预算连完整尾行都放不下时不注入。超长置顶缩短后仍是完整 JSON 字符串，有 `[truncated]` 标记，不算整条遗漏。
- 去重是规范化后的精确匹配，区分大小写；不做语义去重，不清理已有历史重复。旧重复选最早 createdAt、再按 id；所有合并落在 Domain 同一写队列，跨进程写同一 JSON 的限制保持不变。
- 规则有意保守，可能误报/漏报；没有承诺识别所有秘密，也没有清理已存秘密。手工来源策略交给 T09，模型不能通过参数伪造 source。服务继续用 DshBotError，工具仅将拒绝错误适配为公开 HarnessError，以保留官方 Runtime 错误码。
- KV cache 保证限于同一存活 Agent 的 memory section；冷恢复重新创建 Agent 并读当前记忆/当前 preset，新请求前缀可能变化，不承诺跨重启缓存命中。当前已实测冷恢复 section，后续请求由 DSH 自己记录 system/message，插件不改历史日志。
- T09 的 complete persona 提示尚未实现；完整 UI/真实模型/Windows 验证仍交后续任务。本次四项评审无剩余实现阻塞。

## 设计取舍与遗留问题

- 服务复用 T03 Store 和 T04 Host 队列，不增加单独存储服务或另开领域；T09 可复用门面，但本次不提前增加 Remote/UI。
- 快照在一个队列槽中同步分页；置顶不占最近普通记忆的名额。超过预算时按顺序保留前缀，因此所有置顶参与选择，并不保证预算之外的置顶全文仍能进入 prompt。字数采用 JS UTF-16 长度，默认 4000。
- 内容 JSON 引用并提示仅作为参考数据；`interpolate:false` 保留 `{{...}}` 原文。不为记忆增加 assembly 监听器；既有 T05 模型路由监听器保持原职责。
- 工具额外绑定 owning Agent，来源由可信会话生成。取消在实际队列操作开始前再次检查；持久写入开始后不保证撤销。
- 自有 memory 工具的 deny 通过省略注册实现，因为 rc.2 restrict 只作用于继承层。其余工具保持 T05 restrict 语义。
- **已验证的限制：** `persona.complete=true` 会按 DSH 契约覆盖其他所有 section，包括 memory；记忆工具仍可用。需要自动注入时使用普通 persona prefix/suffix。本实现没有改写 assembly 来绕过 complete。该边界由测试明确记录。
- 活跃旧 Agent 保留旧代际 memory 开关和静态提示词；Bot 更新影响新 Agent。禁用整个插件则释放现有 Agent 的扩展。
- 未验证 Windows 原生路径、桌面交互或真实模型质量；正式 profile/冷恢复/桌面集成继续由 T10 验收。本次无剩余 T06 实现阻塞。
