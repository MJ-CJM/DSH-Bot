## 3. 实现说明

- 五个工具在所属 Bot Agent 的 effect 内注册并清理。`routine_create` 使用 model/session 来源；`routine_list` 支持 botId 筛选；update/delete 使用 expectedRevision；run_now 使用 session、持久 step 和 call/rootCallId 派生操作 UUID。
- 四类写操作走原生 ask 审批，中英显示完整目标、任务和修改；上游 deny/cancel 保留。执行时再次验证绑定、存活 Bot 身份、参数和来源；后台、子会话、回报轮次不能写 Routine。Bot deny 清单直接省略本地工具定义。
- 正式 Client 独立 await 挂载 automation contribution。总览和 Bot 详情复用同一组件，显示 Bot、规则、时区、启停、下次运行、最新 Run 状态。历史支持分页、九类状态、跳过原因、执行快照和会话链接。
- 编辑器提供 at/every/daily/weekly/cron；Host 仍是时间规则校验权威。单次时间要求带 Z/偏移；daily/weekly 补秒；更新冲突保留草稿和旧 revision，需用户重开核对。
- 立即运行、删除均有确认框；立即运行受理提示与执行成功分开，同一确认框内失败重试沿用 UUID。暂停和删除不会中断已有 Run。
- 新 Client Config `routineHistoryPageSize=50`，验证 1–200；沿用现有可配置轮询、可见性/reset 和旧响应丢弃逻辑，无浏览器调度器。所有新文案中英同键，CSS 仅用锁定 `--dsw-alias-*` token。

## 7. 决策、限制与复跑

- 决策：复用 automation Remote 与既有 shared polling scheduler，不新增 stream/调度 API。理由：当前公开契约足够覆盖任务，Host 仍唯一执行定时器。
- 决策：最新状态每 Routine 查最新 Run，而非读取 lastRunId。理由：lastRunId 是 scheduled 游标收据，可能遗漏更晚的 run_now。
- 决策：单次规则使用显式偏移的 ISO 输入。理由：避免浏览器本地 Date 对 DST 缺失/重复时刻静默修正，Host 继续校验未来时点。
- 决策：Chromium 受阻后继续非视觉正式 Client/Gateway/Host 验证，单列失败。理由：任务单明确允许由编排方复跑截图；不绕过沙箱、不生成替代图片。
