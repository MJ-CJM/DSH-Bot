### T11（[原报告](../../spikes/p2/README.md)）

- **决策：schedule 作为共享服务包外置，精确 dev + 兼容 peer。理由：**根入口同时导出服务，不能因只用时间函数就内联第二份服务定义。探针声明 `@deepseek-ai/dsh-schedule` dev `0.2.1-rc.2`、peer `>=0.2.1-rc.2 <0.3.0`，Cordis dev `4.0.5`/peer `^4.0.5`；llm 工厂同理。只有类型导入的 jobs/subagent/session/controller/workspace 留 dev；Schemastery 普通 dependency `3.18.5`。类型从共享 strict 配置继承。根导出见 `packages/schedule/schedule/src/index.ts:25-61`；依赖规则见 `docs/user/develop/basic/publish.zh.md`。
- **决策：每次查询 Bot status 列表，使用真实 presetId；创建传 workspaceId。理由：**P1 `status()` 是无参数异步列表，并非 `status(botId)`。`create`、`rename`、`prompt`、`resolveAgent` 根服务入口见 `packages/api/session-controller/src/index.ts:243,301,431,462`。Bots 分组成员验证走真实公开 WorkspaceRegistry，不以 dump 或自建数组代替。
- **决策：先定位 committed user/message，再找它所属 turn 的 start/end，核实 step 和完成原因，最后检查 idle、后台工作、Inbox、flush。理由：**本次原生日志的 step/start 在 user/message **之前**；只向后搜 step 会误判空轮。事件契约见 `packages/core/session/src/types.ts:283-310`。不能将 accepted、assistant 中间消息、孤立 completed 或单独 whenIdle 当作完成。测试 job 是通过公开 jobs.start 创建的受控 Promise producer，不是 shell 命令；先注册 wait 再 settle，刻意不触发 tool-jobs 的额外父通知。
- **决策：jobs.list(sessionId) 后再做 `owner===sessionId` 过滤，并处理 running/stopping；子代理用 listDescendants 的公开 activity 和诊断。理由：**list 包含 unowned；listChildren 只是持久目录，已完成条目仍保留，不代表还在运行。参考 `packages/jobs/jobs/src/index.ts:101-129`、`packages/subagent/subagent/src/index.ts:292,405,425`。测试真实 spawn + caller delivery，仅验证后台子代理查询/等待，不实现原生 subagent 作为 bot_delegate 的备选执行器。
- **决策：回报使用公开 MessageSourceMap 扩展、自定义 kind 与 `form:'notice', summary`，持久保存 messageId。理由：**不会伪装人工请求，消息能落日志并冷恢复；工厂会自己生成 id。见 `packages/llm/llm/src/message.ts:95-115,241-253` 与 `packages/core/agent/src/runtime-types.ts:184-222`。本次是两次独立回报各送一次，**不证明重复 followup 同 messageId 会自动去重，也不证明跨崩溃 exactly-once**。T15 须保存 report 状态并串行协调，未知投递窗口走 recovery_needed/blocked。
- **决策：锁文件存在即只读、不调度，不自动删除疑似 stale 锁。理由：**pid/启动时间仅是诊断，PID 可复用，检查存活后 unlink 会引入竞争；`wx` 本机独占 + token 所有者释放能验证安全性。正常卸载释放；崩溃后需确认所有旧 owner 已停再人工解除锁。双进程竞争由相同锁代码的最小 worker 验证，未让两个完整 Host 同时写 JSON；生产必须在打开可写 automation 域和开始 timer 之前取得锁。
- **决策：effect disposer 先关闭 admission/active 标记，清 timer，再等待已启动异步工作。理由：**clearInterval 本身不能阻止已经进入的异步回调提交。此次真实插件双代卸载已验证该差别；不依赖窗口/UI 存活。

### T12（[原报告](P2-T12.md)）

- **决策：T12 提供独立工厂，暂不接入生产 patch。理由：**尚未实现拥有真实锁的 Host coordinator，不应提前打开第二个可写域。`openAutomationStores(ctx,{assertOwner,ownerId,resolveBot,...})` 要求先持锁，打开和每次写入均调用 owner 门禁。`resolveBot` 支持异步，通过后续协调器的公开 registry get/status 提供实际 presetId；不拼接 preset 前缀。
- **决策：Run 是 reservation、去重和扣额的权威，control 与 Routine cursor 是投影。理由：**公开 Domain 没有跨表事务。`enqueue` 写 queued（无额度），`reserve` 单行写 running/step=reserved、quota receipt、slotHeld，再修复 control；scheduled 的 Run 另保存 nextRunAt 决策供游标修复。重试先修复投影并返回原 Run，不重新分配会话或扣额。
- **决策：采用保守恢复。理由：**T12 不能核实原生会话和副作用。重开后已收费的非终态变为 recovery_needed，保留并发占位；执行器提供确认后才允许终态释放。失败、取消、超时均不返还当日额度。queued 在 reserve 前重验目标 Bot 的 createdAt、Routine 删除/启停/规则代际。
- **决策：暂停恢复增加 ruleRevision，重新计算未来目标；已过期 at 保留原绝对时间并耗尽。理由：**暂停期间不补跑，旧 generation 的 queued occurrence 不能复活。仅改标题/prompt 不改 ruleRevision，等价规范化规则也不改。manual 可在暂停中运行，不改游标；删除 Routine 软删除并保留历史，不终止已 admitted 的运行。
- **决策：不提供 Run 硬删除/历史裁剪。理由：**去重和配额仍需要这些记录；列表支持最多 200 条的游标分页。未来压缩必须保留必要墓碑，不能直接按 UI 显示数量删除。
- **决策：每日时区首次取系统默认并持久固定，显式改时区或额度日期倒退拒绝准入。理由：**避免更换时区/时钟回退产生空额度桶；control 缺失可从收费 Run 重建。计数按 botId，自然日分桶，重建 Bot 不返还已有额度。

### T14（[原报告](P2-T14.md)）
