## 决策

- 决策：复用原生 `sessionController.rename` 的 user-source 固定标题。理由：锁定源码明确支持取消自动标题并防止后续自动覆盖（`packages/session/session-title/src/index.ts:395-421,508-510`）。无需禁用整个宿主的标题模型；仅对主会话显式标题变更进行合并修复，自己的 rename 不循环。
- 决策：只增加 Bot 生日 → 主会话 sidecar。理由：DSH 已有会话、Inbox 和持久化，但不知道本包 Bot 身份。所有 Client 打开动作、立即运行共享 `openConversation`；并发打开只创建一次。
- 决策：已有会话选最近活跃的合格普通会话，保留原 cwd、工作区和其他历史。理由：原生工作区要求 cwd 精确匹配；不改会话 header、不移动或删除历史。新建主会话统一使用 Bots 工作区，旧 defaultCwd 仅保留兼容并在 UI 说明。
- 决策：删除新会话 RunExecutor/runtime/barrier/config，显式请求只记录 `delivered` 投递回执。理由：主会话内的执行、审批、子代理和完成状态由原生管理。投递不明标 recovery_needed，不重放、不取消用户的共享会话。Client 只有在 delivered 时显示成功。
- 决策：保留既有 `.dsh-dev`，新建 profile 与独立 storage/session 根。理由：任务要求保留数据并只使用该 DSH_HOME。
- 决策：截图失败保留证据，继续完成独立 Host 验收。理由：任务明确允许 Chromium 不能启动时标 FAIL 由编排方复跑；未降低沙箱或借用旧截图。

## 遗留问题与建议

1. 编排方在允许 Chromium 启动的环境重跑上述 `--v022` 命令，检查中英亮暗和主会话打开/详情行为。桌面升级按原项目规则由编排方执行，本轮未操作桌面安装。
2. 标题遵守 DSH 原生规范化：普通 Bot 名完全一致；多空格、控制字符或超出宿主 maxTitleBytes 的名称采用原生接受值，不反复写入。Bot 名更新与会话标题没有跨存储事务，失败报告后可由后续对账恢复。
3. 迁移只使用已有元数据/摘要；缺失预览不会回读旧消息，下一条真实消息才更新。旧任务保持原来的到期会话，立即运行始终投递当前主会话；没有自动移动旧 schedule。
4. 同一后端仅支持一个活动 Host；sidecar/显式投递历史未自动裁剪。完整 Host 冷重启未在本轮另测，仅有 JSON 重开、冷 metadata 与 tarball Host 的分层证据。
