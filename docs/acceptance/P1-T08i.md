## 实现与设计取舍

- Host 的 `ensureBotsWorkspace()` 从公开 `resolveDshHome()` 解析 DSH home，经受管路径检查创建 `dsh-bot/bots`（0700），用公开 `workspaceRegistry.resolveByPath/create` 复用或创建工作区。首次创建标题为 `Bots`，不调用改名接口，已有同路径工作区和用户改名均保留。新增 `@deepseek-ai/dsh-workspace@0.2.1-rc.2` 精确 dev 依赖，仅用于类型与测试，不增加运行时 peer。
- 串行 registry 队列保护 ensure；原生 create 本身也按 canonical path 串行幂等。零参数严格 Remote 返回 `{workspaceId,path}`。id 放在 `dsh_bot.registry_state` 的 `bots-workspace` 行，扩展 schema 兼容旧 examples 行，写前 parse。每次以 path 查询为准，失效或其他 profile 留下的 id 会补正。启动尝试恢复；暂时失败不阻断 Bot 管理，新会话时可重试。工作区已创建而 Bot 存储写失败时不删除工作区，下次按 path 复用并补写 id。
- rc.2 删除工作区只移除工作区记录和成员列表，不删除目录、会话日志，也不改变全局归档/固定集合；保持 `initialized=true`，正常重启不会按 cwd 重新迁移。**重建不重新 attach 历史会话**，保留用户删除后的未分组/归档状态，不搬动其他工作区会话；旧 T08h 私有 cwd 历史也不满足根目录精确相等要求。只有人为清空整个 workspace 域才可能触发宿主首次历史迁移。
- 三个主要入口重新读取 Bot/status：无 defaultCwd 时 `ensureHome → ensureBotsWorkspace → sessions.create({workspaceId,agentPreset}) → openSession`；有 defaultCwd 时使用公开 `ctx.workspaces.create({path})` 取得该路径工作区，再以 workspaceId 创建。没有 cwd 参数或权限参数。四个阶段的失败内联呈现，卸载/取消/被取代导航的迟到结果不触发导航。原“在工作区中新建…”流程保留。
- 编辑器中英文显示默认 Bots 根与 Bot 私有 home；填写默认工作目录时另外显示实际会话工作区路径，清除仍使用 `defaultCwd:null`。说明共享根不提供 Bot 间隔离，目录外操作沿用宿主权限与审批。
- `agent/created` 使用 `ensureHome` 的实际绝对路径注册 Agent 所属的双语 home section，与 memory 开关无关；自定义工作区时说明实际 cwd，不误称当前目录仍是 Bots 根。home 创建失败使用不含路径的说明，会话继续。section 归 Agent effect，并随插件卸载清理。保留已有 `persona.complete=true` 的原生完整替换语义：它会抑制 home 和 memory 等其他 section；通常的 `complete=false` 会正常注入。未通过修改 complete 设置或替换宿主汇编绕过此行为。
- 删除 Bot 默认不删除目录；勾选后只删除原有 owner/inode 检查通过的 home、marker，以及空的 `bots/<id>`。不删除 Bots 根、工作区、其他 Bot、技能目录或 defaultCwd。沿用 T08h 跨存储/文件系统非原子及部分清理失败的明确报错。
- 原生侧栏仍由宿主按 workspace membership 分组。rc.2 不为 blank/archived 行挂 leading slot，因此新空白行保留原生显示；同组已完成 Bot 会话继续显示 T08e 鲸鱼。没有覆盖树或用 DOM 修改宿主行为。

公开接口、作用域、源码位置及删除语义详见 [API notes 的 T08i 节](../dsh-api-notes.md#t08i共享-bots-工作区)。
