## 决策与边界

- **决策：使用既有 RunService 作为所有入口的权威准入，Dispatcher 不自行扣额或建会话。理由：** 统一 scheduled/manual/delegate 的去重、reservation、配额及 slot，不产生第二套执行链。
- **决策：新增严格 `runNow(id, operationId)` Remote，返回受理记录。理由：** T14 需要可复用的立即运行入口；客户端只能传 Routine id 与幂等操作 UUID，不能提交收费、来源或 reservation 字段。模型工具及审批界面仍留给 T15/T16。
- **决策：scheduled 满队列记 skipped/queue_full，额度耗尽记 skipped/quota。理由：** 保留可查跳过原因，避免一条 Routine 持续重试阻塞其它 Bot 或无限排队；manual/delegate 入队已满仍明确 busy。已收费的失败仍计额度。
- **决策：scheduled 队列只留同 Routine 最新一次，旧项记 superseded。理由：** 休眠/满载跨周期时避免依次补跑积压；替换先持久终止旧项，符合“宁可少跑不重跑”。
- **决策：skip 策略容忍一个 sweep 周期内普通 timer 延迟。理由：** 系统计时器通常略晚，不能将几毫秒迟到等同漏跑；跨多次 occurrence 或迟到至少一个周期时跳过。默认 latest 不受此特殊判断影响。
- **决策：没有可证明停止的恢复项继续占位，不自动消费。理由：** Dispatcher 只能启动 queued，recovery_needed 不重放；沿用 T13 完成屏障和所有权限制。

已知边界：只保证同机同 DSH_HOME 单 owner，不能保证外部副作用 exactly-once；历史 Run/锁收据本轮不压缩；日配额不是 token/金额预算。没有新增 UI、Routine 工具、委派工具或回报。建议 T15/T16 复用 `dshBotDispatcher.submit/runNow`，不要直接另开执行或扣额通道。
