## 行为与决策

1. **决策：立即返回持久队列受理的 `{runId, sessionId, status}`。理由：全局并发满时也不能阻塞当前模型等待目标执行。** `sessionId` 此时是预分配值，`SessionController.create` 返回不同 ID 时，最终身份以 Run 记录为准；没有把受理声明为已创建或已成功。本轮正常 Host 路径预分配/实际 ID 一致，工具返回 queued 的时间早于目标终态。
2. **决策：发起 Bot ID/创建时间取自 Agent 的不可变 binding，会话取 `agent.session.id`。理由：不接受模型提供来源、深度、requestId 或 operationId。** 目标只接收 task，独立使用目标 Bot preset/记忆/权限及 Bots 工作区；不复制父历史。操作 UUID 由会话、持久 step/turn-start seq、rootCallId 和 callId 派生。同一步重入去重；后续 step 重复 provider callId 不吞掉新调用。
3. **决策：继续使用 T14 Dispatcher 和 T13 RunExecutor。理由：所有入口共用配额、并发、队列、Bots 归组、完成屏障与退出规则。** 排队后任一参与 Bot 删除/同 ID 重建/身份不可用时，未收费 Run 取消并保留记录，避免永久排队或绑定新身份。
4. **决策：后台 Run 历史中的会话、subagent/有 parentSession 的 fork 均拒绝 `bot_delegate` 与 `routine_*` 写工具，读取 `routine_list/get` 保留。理由：在 v1 没有独立的可证明安全 fork 授权时，禁止通过换 preset/fork 绕过深度。** 回报引发的步骤也拒绝，直到新的普通 user 输入；限制由 Host 工具门禁及 delegate execute 双重校验，不靠提示词。常规人工会话允许自委派或跨 Bot 委派。
5. **决策：摘要采用执行器记录的最终 assistant 文本，先秘密筛查，再限长。理由：不投递中间工具输出、原 task、标题或父对话。** 新 Config `automation.delegateReportMaxChars=4000`，范围 1–8000（UTF-16 单位，避免尾部半个代理对）；消息整体仍受 schema 8192 上限。沿用现有凭据启发式，命中则整段 `[redacted]`；不是完备的秘密分类器。内容带 Run ID、终态和 sourceSessionId，失败也回报状态。
6. **决策：report `pending → sent / blocked`，串行投递且先落固定 message + attempts，再 followup。理由：公开 followup 没有幂等保证。** 已确认本次新 Inbox splice 后 flush=true 才记 sent；followup 可能同步取走 Inbox，不能因 pending 暂空且 user/message 尚未提交而报错。sent 表示曾持久投递，**不等于原 Bot 已处理成功**。本轮 e2e 另验证原会话 completed。
7. **决策：冷启动时未尝试的 pending 可恢复原 Agent 后投递；已有尝试且找到完整同消息 user/message 时补 sent；只有待处理 Inbox 或证据缺失时 blocked，不自动重发/强行唤醒。理由：宁可少跑，不在未知崩溃窗口制造重复模型轮次。** blocked 不自动重试；T15 不新增手动重试 Remote/UI。
8. **决策：回报前后核对原 Bot createdAt、binding、原 session、归档状态和活 Agent 身份，不创建替代会话或取消归档。理由：消息不能串到同 ID 新 Bot。** 不可恢复、丢失、归档、身份变化或持久化不明均 blocked。Reporter 的订阅/清理归 ctx.effect，关闭停止新投递并等待已入场扫描，存储关闭前 join。

三阶段：

- **first**：显式测试 turn 中实际审批拒绝不建 Run；随后真实模型请求 `bot_delegate`，返回 queued；目标 researcher 普通会话在 Bots 组，仅收到 task；目标模型尝试再委派被 Host 拒绝，最终回复完成且秘密被筛除。原始 turn 刻意延迟，报告先入 next-turn 队列，原 turn 正常 completed，后续报告轮次再委派被拒绝，最终只出现一次摘要输入。共 6 次模型请求：原会话 4、目标 2。
- **cold**：前一进程在关闭 reporter/dispatcher 后构造未执行便取消的终态 Run，作为 outbox 恢复夹具。冷恢复可达原会话后发送一次 cancelled 报告并 completed；已归档/不存在/原 Bot 同 ID 重建三类 blocked。仅 1 次额外 mock 请求。这些夹具不冒充目标模型失败运行。
- **again**：再冷启动，sent/blocked 保留，同一 messageId、attempts 不增加；无新增模型请求。
