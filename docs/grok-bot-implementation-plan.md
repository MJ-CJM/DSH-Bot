# Grok Bot 体验实现计划

开始日期：2026-10-28。基线：`b4cd01d`，0.4.1。
用户授权：整体设计后依次实现，自行验证完成后统一交付用户验收。
原有工作树修改保留；只写本仓库，不修改参考 DSH、全局配置或桌面安装，不启动真实模型会话。

## 产品约束

一个 Bot 有一个持续聊天入口，并可拥有多个原生后台执行。用户可以中途补充、问问题、另开工作，单独停止某项工作。
多个 Bot 在普通群聊里自然回应、互问和接续，不要求任务模式、计划卡、协调者、DAG 或固定评审流程。
工具、会话、子代理、审批、存储、附件、定时、模型、连接器均优先使用宿主公开服务。
文档依据见 [整体差异审计](grok-bot-parity-audit-2026-10-28.md) 和 [群聊专项](group-collaboration-review-2026-10-28.md)。

## 实现批次和责任边界

| 批次 | 交付范围 | 核心验收 |
| --- | --- | --- |
| A 基础执行 | 重新限定通用工具阻断，保留原生权限/审批和跨 Bot 记忆边界；修复后台任务结果生命周期 | 实际工具进入原生执行；deny/ask 不被覆盖；停止前台不丢无关后台结果 |
| B 聊天并发 | 原生子任务汇总/打开/补充/停止、背景执行指引、正常忙时输入 | 两工作重叠，用户可继续交互，停止 A 不影响 B |
| C 自然群聊 | 普通消息、@/引用、可不发言、同群消息工具、上下文承接、接续链停止、聊天时间线 | A 找 B，B 回答，A 继续；结果在群内；取消后不再接续 |
| D 工作成果 | 原生附件/文件引用、资料库、模型选择、技能管理、能力诊断和错误恢复 | 用户能找到/打开/继续使用产物；实际能力与界面状态一致 |
| E 日常助手 | 原生定时完成状态、可用事件桥、通知、常用连接配置、主动功能可用性 | 投递与完成分开，回执可追溯，缺服务有准确原因 |
| F 平台配套 | 常驻 Host 部署入口、响应式多端访问、浏览器/语音/内容生成/共享能力的公开扩展适配 | 配置存在时真实调用；无提供者时如实不可用，不伪造云服务或外部账号 |
| G 交付 | 迁移/卸载/恢复回归、mock Host/界面验证、构建打包、用户验收指南 | 同一构建产物有可追溯检查记录；遗留限制明确 |

依赖顺序是 A → B/C → D/E → F/G；独立文件的开发可并行，集成验收按依赖顺序进行。
对确无公开 API、外部部署地址或必要账号的能力，记录具体阻断与可用替代；不将“显示未配置”算作功能实现完成。
核心之外的购物/支付、账户体系、托管云电脑等外部服务仍在完整差异清单内，不能用本地占位功能宣称一比一完成。

## A 工具与后台执行

先查实际公开工具定义和源身份，允许适用的原生本地执行进入原有审批/权限链；不得注册同名仿冒工具或覆盖 native deny。
保留 managed connector、记忆共享、跨 Bot 消息的准确身份和数据范围；工具调用后的来源标签不得将未知资料自动提升为可公开共享。
可调行为使用导出 Config/schema。新增行为有正反回归，而不只测试拒绝。

后台执行的启动信号、用户取消指定任务、插件卸载与父回复结束分别处理。结果按 native child/parent 身份回传，
持久回执用于恢复与去重；无法确定是否已执行的副作用不自动重放。

## B 原生子任务产品入口

复用公开 subagents catalog/prompt/interrupt 和原生 child UI，任务状态不复制为可独立修改的第二套调度器。
一个 Bot 的任务按主会话 parent 身份关联；只停止用户选定 child，全部停止明确列为另一动作。
界面使用小型正在处理列表，提供来源、状态、打开和停止；无需用户填写计划。

## C 群聊协议

保留已有 group root/no-model、spawn/caller/preset、turn/delivery 持久收据。新增自然模式默认允许普通消息；旧模式仍可读。
群消息有 replyTo 与真实 author。Host 绑定群、Bot、child 和触发链；模型只选已确认群成员，不能填写任意 Session 地址。
group_message 持久受理后立即返回，目标稍后执行，不同步等待目标答复；明确 skip 不是失败。
成员普通发言对全群可见，但不触发全员无限重入；直接提问/回复才追加后续执行，链有次数/时长上限。
取消覆盖该输入所有未开始接续和在途执行，迟到结果不能复活链。新用户输入可正常开始新链。
上下文包含对应输入、引用和已完成前序结果，旧执行不能看到未来排队输入。

## 验证与交付

先跑针对性回归，再 `scripts/pnpm check`。真实公开 API 组合使用隔离 `.dsh-dev` 和 loopback 模型夹具，真实模型 0。
UI 检查中英、亮暗、窄屏；只通过 DOM 时明确不称真实视觉通过。
版本升级在集成收口统一处理，锁文件只因确有依赖变更更新；最后打包一次并记录 SHA256。
不提交、不推送、不覆盖用户目录。最终列文件、命令、PASS/FAIL、产物路径与用户验证步骤。

## 当前状态

设计已落地为 0.5.0。实现范围和证据以 [交付验收](acceptance/V050-natural-bots.md) 为准，不能据此宣称完整 Grok 云端产品一比一完成。

| 批次 | 实际结果 | 仍有边界 |
| --- | --- | --- |
| A | native 文件/命令/定时恢复；checked result 生命周期修复 | native 是单用户可信Host策略；任意脚本不是数据隔离沙箱；存量强遗忘门禁仍会关闭普通工具 |
| B | 多个原生后台任务、在途补充、单停/全停、前台独立输入 | 已结束/冷恢复child需新委派；不保证强杀后caller必达 |
| C | 自然群、普通输入、引用、@、互问接续、skip、整链停止、附件 | 有界接续；保留原生模型/审批限制 |
| D | 模型目录/推理选项、原生技能目录+自有编辑、群成果引用、来源打开、会话恢复 | 未自建Pages/云Library；文件浏览器下载受宿主API限制 |
| E | 原生定时投递/回复状态、原有应用内通知/connector复用 | 外部事件/邮件/IM/push、主动助手仍需实际provider闭环 |
| F | 隔离Web启动入口、响应式、原生Voice Input诊断与复用路径 | 云账号、共享链接、支付、远端部署未实现；browser exact bridge缺公开API |
| G | 自动检查、真实Host合成模型链路、真实Web/Chromium与tgz审计 | 真实模型、精确rc.2二进制、桌面安装由后续用户验收 |

后续自动化和平台能力只有具备真实provider/账号/部署目标后才能继续落地，不将状态提示或接口声明作为完成证据。
