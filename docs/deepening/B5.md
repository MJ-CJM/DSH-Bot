## 实现与边界

同一 v2 日志提供 private/shared、修订、裁决、分片退休和遗忘闭包。
有效时间与 recorded/commit 截止时间独立；当下墓碑和退休私有权限优先于历史查询。
未来修订不提前生效，当前 context 可使用仍有效的旧修订；管理的“全部条目与状态”能查看未来修订。
冲突按结构化 subject/factKey/qualifiers、信任、有效起点和 commitSeq 裁决；未知时间不强行最新胜。
候选不会覆盖用户事实，冲突不注入，user_event 按事件身份保留。
另测 private bot_role/how_to_work 与明确局部例外，包括时间未知的例外；候选仍不能借这些类型覆盖用户事实。

只开放用户管理发布。模型没有 createManaged/confirm/resolve 的工具入口。
确认将复制准确正文和界面展示的结构字段；不携带私有 legacy tags/pinned/sourceExcerpt/confirmation。
来源引用与 no-egress/secret 等限制保留，不把共享当作外部发送授权。
手动来源指向同次已提交的 managementOpId，能回查权威操作；不会伪造 M4 的可信入口收据。
来源名称、头像和鲸鱼颜色/形态快照放在可删除 payload，不把这些正文放进不可删除 op header。

删除 Bot 退休旧 BotKey 的分片，撤销旧写入能力；保留已发布共享贡献和显式保留的私有数据。
重建同 ID 不继承旧私有读取权限。贡献遗忘另行预览整个 shared shard 和已知派生闭包，复用 B4 两级流程。
旧隔离项必须由用户明确选择当前 Bot 的生命周期并确认私有归属，不自动变共享。

context 默认预留 private/shared 2400/1600 个 Unicode 码点，公共 framing 计入私有预留，未用预算可借。
journal 默认最多共享分配预算的 25%，只注入近 30 天；过窗口仍可检索。
整条选择，超长跳过并给检索提示；缓存记录历史/未来有效边界、午夜和 journal 失效点。
JSON single 后端的可重建缓存改为一个 snapshot，避免每次提交逐条重写全文件；ops 仍是唯一提交点。

工具统一为 bot_memory_save/search/list/forget，没有旧名别名。
save 仍写 private，search/list 读取自身私有及已发布 shared；模型不能确认、发布或删除别人的共享项。
精确旧 deny 名在 Bot 存储、创建/更新和 preset 激活前迁移，限定的 MCP/社区名称保持原值。
同层社区 memory_save 与本包新名可同时调用；社区工具卸载后，原生 guard 对未知旧名给改名指引。
