## 实现

- `dsh_bot_memory` version 2 保存严格的 meta、ops、payloads、barriers、receipts、migration 和 migration_items。
  projections 是可丢弃缓存；开域允许读入损坏缓存，写入仍经严格版本 schema 校验，再从 ops 重建。
- Host 生成 UserScope、BotKey、随机版本/载荷/op ID、commitSeq、forgetEpoch、来源和 candidate 信任。
  模型输入不能写这些字段；private 的 owner、shard 和读取者必须一致。
- 单条 `ops.put` 是提交点。同 opId、同参数不会二次提交；换参数或已擦除载荷的旧提交重用会拒绝。
  payload 先写，日志提交结果不明时冻结读写，重开按同 opId 核对实际持久状态，不改用新 ID 盲重试。
- 内核发布不可变投影。缓存失败不撤销已提交操作；恢复清理未提交的孤儿载荷。
  遗忘删除该 memoryId 的历代 payload，而批操作中其它 subject 的载荷保留。
- 私有工具和 Remote 统一进入 v2 门面，保留旧返回 DTO、去重、分页、来源和校验行为。
  服务能力绑定 BotKey；同 ID 新生日不能继承旧私有分片，旧能力也不能操作新 Bot。
- owner lease 使用排他创建、不可变后继链、随机 token 和本机 PID 检查。
  活进程、异机或未知身份拒绝接管；仅已证实不存在的本机进程可接管。
  生产 owner 目录固定到当前 DSH_HOME 的 `dsh-bot/memory-owner`，不随技能 dataDir 改变。
  不承诺不同 DSH_HOME 显式共用外部 backend、网络文件系统或绕过协议的写者安全。
- `bot-context` 不再捕获一次性记忆 section，而注册公开
  `systemPrompt.context({name:'dsh-bot:memory',order:300,required:true,interpolate:false,text:provider})`。
  provider 同步读取已发布的内存投影和载荷；不做文件检查、数据库等待或网络调用。
- 默认预算是私有 2400 / 共享 1600 个 Unicode 码点；共享本批为空读路径，未用预算借给私有。
  标题、标记、分隔符计入预算；整条放不下就跳过，不截断置顶事实。
  缓存覆盖 UserScope、BotKey、seq、epoch、policyRevision、配置和时间边界，跨午夜、from/to 和时钟回拨失效。
- Host 和 Agent pre-step/final llm/stream 都检查准入；队列中先持久读取依赖、取得在途 lease，迭代结束才释放。
  遗忘先安装屏障，再提交递增 epoch；旧队列操作失效、活跃 Agent 取消，原生 keepInbox=true。
  旧 Agent 上的最小守卫保留到 Agent dispose，不在卸载时依赖已经消失的 Host 服务。
  不能确认属于当前门禁的旧 Bot 代际拒绝发送，不私取旧 section disposer 或换会话掩盖。
- 屏障期间，辅助无归属请求、模型工具以及 Reference Memory 管理/调用入口拒绝执行。
  B3 没有自动清除屏障或“强遗忘已完成”入口；受影响会话维持 blocked。
- 配额时区默认取 Host 系统时区，首次持久化到策略元数据；不是 UTC 硬编码。
  自动共享及其配额提交仍属于 M4。中英旧“完整人设抑制记忆”提示已跟随 required context 修正。

## 迁移和恢复

公开 `KvTable` API 完成 prepare → copy → verify → cutover → legacy-clean → done。
旧 `dsh_bot` unit 仍为 version 1，bots/activities/registry_state、Bot 生日和主会话身份保持原样。
memories 的迁移 opener 独有 strict union，能识别保留键 `__dsh_bot_memory_v2_fence__`；普通旧 schema 不能识别。

映射在复制前持久生成。逐项对账原文、legacyKind、原始来源和时间，再检查日志重建与影子投影一致。
Fence 在 cutover 之前持久写入；Fence 后、cutover 前中断可以用原映射续迁，不重复复制。
legacy-clean 删除旧正文并删除临时 sourceDigest，保留 Fence。done 后重新出现旧正文会拒绝恢复。

v1 没有 BotKey 生命周期收据。仅凭 createdAt 先后不能证明同一生命周期，
因此旧项全部完整复制为 **private / candidate / proposed 隔离项**，包括孤儿，不自动分配给当前同名 Bot。
它们不进入普通模型注入；显式归属/候选管理留给 M3。没有静默丢行，也没有把 source.by=user 当成授权。

cutover 后的兼容恢复必须支持 Fence、tombstone 和 epoch；关闭共享不清除遗忘状态。
本批不提供丢弃影子回 v1 的降级操作。真实旧 0.3.2 包在 Fence 前可创建两条合成旧记忆，Fence 后实际拒绝打开。
旧 tgz SHA256 为 `1cad1685ae60deef5197a374d2213bb160cb5246eea4ad3e449035de050f986b`。
每个阶段用新 profile 安装，逐字节核对旧包 domain 模块与 tgz，避免同版本 link 残留造成假验证。
