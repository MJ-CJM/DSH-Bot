### Fence：断言真实拒绝原因

旧脚本要求 stdout 出现 `__dsh_bot_memory_v2_fence__`，但旧 Host 日志仅有 URL 和完成标记。
编排方收据已经显示 rejected=true、adapterRequests=0，因此“stdout 没有键”并不是未拒绝。
本次改为从实际 `registry.waitUntilReady()` 拒绝中保存原因，再由父 runner 校验 receipt。

只读真实 0.3.2 安装包确认：旧 registry 把存储异常转换成 startupError 字符串，公开拒绝错误没有保留 cause 链。
因此 probe 严格要求 `code=bot/unavailable`，并逐字匹配以下领域/表/键/schema 拒绝原因：

```text
Bot registry startup failed: domain 'dsh_bot': stored record '__dsh_bot_memory_v2_fence__' in table 'memories' does not match its schema
```

父进程还要求 status=PASS、rejected=true、adapterRequests=0，不能由其他启动失败或“没有报错”通过。
最初本轮拟按 DomainError cause/detail 判断；核查旧包发现其丢失 cause，已在实际执行前改为上述真实公开错误。
新 Host 尚受环境阻断，严格拒绝断言的运行结果仍为 FAIL(environment)，没有虚报验证成功。

### 生命周期：等待异步 preset 列表

编排方 rc.3 实跑在 `list().map` 报 TypeError。公开 rc.2 `AgentPresetRegistry.list()` 签名为 Promise<AgentPreset[]>，
同方法的 Remote roster 才包装为 `{presets}`，不能把它们混用。
基线与每轮卸载后的列表均改为 `(await ctx.agentPresets.list()).map(...)`。
保留 20 次循环、服务/领域释放、旧引用调用拒绝、owner lease 重新获取和 preset 基线相等断言。
本轮新包完整 Host 在 loopback listen 前被拒绝，20 次 Host 循环尚未执行；npm/JSON 单元卸载结果另列。
