### Host 引导边界

旧入口静态 re-export host/index.js。ESM 会先链接所有静态依赖，再执行入口代码，
所以 0.3.2 缓存的 schema.js 缺少 memoryFields 时，旧入口内部的 try/catch 无法拦截。

0.4.1 入口不静态导入本包业务模块，仅使用 Node 内建模块和既有公开 Schemastery 根入口。
构建给 171 个 Host/shared/typert 模块追加 DSH_BOT_MODULE_VERSION，生成随包分发的 module-manifest.json。
入口先核对安装版本及每个模块的 SHA256，再动态导入 schema 和所有清单模块，核对各加载 namespace 的版本戳。
成功后才暴露业务 Config/inject 并调用原 Host apply；每次 apply 再次核对磁盘，避免已缓存的新引导入口静默运行另一版安装。

缺失版本戳、旧缓存、混装、损坏文件或动态链接失败均拒绝激活。
失败 Config 和 apply 只返回以下中英提示，不附原异常 cause，不开放 registry/storage/migration：

> DSH-Bot 模块版本不一致或加载失败。请完全退出并重新打开 DSH。
> DSH-Bot modules are stale or could not load. Fully quit and reopen DSH.

此提示属于 locale 服务尚未可用的加载错误，直接提供双语，不调用 Client locale 或引入客户端依赖。
没有新增 DSH API、Remote、依赖或 peer。

最初尝试给整个依赖图添加版本查询串，回归发现其改变直接导入错误类的实例身份，
使 bot_manage 的原有 instanceof 错误映射失效；最终方案保留所有模块 URL，逐 namespace 校验版本。
该初次失败未隐藏，最终 bot_manage 与完整相关回归均通过。

### 能力边界与存活 Host 探针

**无法让尚未执行的新代码修复一个仍被宿主直接复用的旧入口 namespace。**
如果宿主连入口也完全沿用 0.3.2 缓存，0.4.1 引导代码没有执行机会，仍必须完全退出重开 DSH。
本次不修改宿主 HMR、不使用其 internal module cache，也不声称已实现任意旧版本无重启热升级。
静态业务入口链接错误只有在宿主实际加载到新引导入口后才能被本包捕获。
Schemastery 本身的包解析错误仍发生于引导入口执行前，不属于本包动态业务加载边界。

新增 release-upgrade 的 hot-upgrade 子测试：

1. 在隔离 profile 安装真实 0.3.2 tgz；将其解包至固定 canonical-deployment，启动一个真实 CLI Host。
2. 通过公开 ctx.plugin 激活旧包，创建合成 Bot/记忆；仅卸载旧插件，保持 Host PID 和 ESM 缓存。
3. Host 存活时依次 CLI 安装 0.4.0 和 0.4.1，并将真实 tgz 覆盖到上述同一规范路径。
4. 在同一 PID 强制加载新入口，先复现旧 schema 的 memoryFields 链接错误，再验证 0.4.1 重启提示。
5. 核对前后 storage 文件摘要一致、没有 registry 服务和模型请求。

pnpm 安装可能更换 package realpath，因此**固定路径覆盖是显式故障夹具**；不是原生插件管理 UI/HMR 的运行证明。
强制新入口使用查询串的操作也只属于测试夹具，业务模块仍使用稳定 URL。
本次仅完成旧包安装，Host 在 webserver listen EPERM 失败，尚未取得 hot-ready 或同 PID 升级收据。
因此旧包完整激活、活进程安装新包和数据摘要不变这组 Host 验收仍 FAIL(environment)。

另有独立 Node 子进程测试使用真实 tgz，不依赖网络或完整 CLI Host：

- fresh：0.4.1 模块与 Config 可加载。
- legacy：先缓存真实 0.3.2 schema，再覆盖 0.4.0，确实复现 memoryFields 链接错误；覆盖 0.4.1 后安全拒绝。
- mixed：文件摘要不符时拒绝。
- link-error：清单摘要正确但业务入口含缺失导出时，动态链接错误被转换为双语提示。
- other-cache：先缓存真实 0.4.0 的另一个模块（shared/version），验证不只检查 schema。
- replaced-entry：0.4.1 引导入口保持缓存，再更换磁盘安装版本，apply 拒绝。

以上 6 项均 PASS；失败路径使用会在任何 Host 服务访问时抛错的 Proxy 验证访问次数为 0。
它们是原生 ESM 边界证明，**不替代完整 Host 升级或真实浏览器证明**。
