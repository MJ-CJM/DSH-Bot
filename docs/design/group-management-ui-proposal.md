# 群管理与原生交互优化方案

> 状态：**已实施；隔离与本机桌面核心验收通过**
>
> 基线：`main@d47b8b5`，分支：`docs/group-management-ui`，插件 `v0.6.4`（未提升版本号）
>
> 范围：群目录、群详情、会话内群管理，以及与之直接相关的导航和交互闭环。
>
> 本文保留获批的原始设计，并在第 14 节记录最终取舍。运行证据及正式桌面验收边界见 [验收记录](../verification/group-management-ui.md)。后续用户已明确授权本机桌面安装；仍不启动真实模型任务。

## 1. 背景

当前 `GroupManager` 位于 `packages/dsh-bot/src/client/components/GroupsPanel.tsx`，主要展示群名、成员清单，以及打开、编辑、归档等操作。它还没有充分利用已有的 `GroupSummary`、`GroupView`、原生 Session 和统计投影，导致页面更像一张静态资料卡片，而不是群工作入口。

当前主要问题：

- 缺少最近问题、成员运行状态和失败摘要。
- 缺少成员有效模型、工作目录和权限等有效配置摘要。
- 群目录只有成员数与最后发言人，缺少时间、搜索和筛选。
- 打开、编辑、资料、更多等操作权重相近，`<details>` 被当作更多菜单使用。
- 群资料与群会话各有一套编辑入口，但群资料展示的信息反而更少。
- 所有群共用同一个双鲸鱼图标，辨识度不足。
- 群目录与执行详情之间缺少连续的原生导航。

现有群消息、逐问题执行过程、原生思考、用户右/Bot 左、权限菜单和统计投影已经验证过，应保留，不在本轮重做。

## 2. 目标

群管理页应优先回答四个问题：

1. 哪个群需要我打开或处理？
2. 每个成员正在做什么、使用什么有效配置？
3. 最近的问题执行得怎么样？
4. 下一步应该打开群聊、补充工作，还是修改设置？

工程目标：

- 优先使用 DSH 公开 API 和原生 UI 能力。
- 复用现有群数据、执行与统计实现，不新建第二套事实来源。
- 保持中英文、亮暗主题、窄屏和键盘可用。
- 将 UI 改造与 Host/持久协议变更解耦，分阶段独立验收和回退。

## 3. 非目标

本轮不做：

- 修改群并发、自然讨论、消息投递、取消或恢复协议。
- 修改成员身份、revision、membershipRevision 或 Bot 代际规则。
- 修改默认权限、原生子任务 `approval=never` 或文件沙箱边界。
- 新建运行数据库、统计后端、任务 DAG 或调度器。
- 引入社区插件代码、运行时依赖、新 UI 框架或新主题系统。
- 首轮修改 Host Remote、持久 schema 或群列表消息预览契约。
- 正式桌面安装、真实模型任务、发布或社区目录更新。

## 4. 方案选择

### 方案 A：群目录 + 原生会话 View + 右侧详情（推荐）

- Bots 的“群聊”页负责跨群目录、搜索筛选、群详情与新建。
- 群会话保留“对话”，新增“成员”和“运行”两个 `conversation.view`。
- 右侧栏继续展示单个 Bot 和单个执行详情。
- 群详情与会话 View 复用同一组展示组件和数据源。

优点：原生导航一致、信息容量充足、能复用当前实现，且不需要新建运行应用。

### 方案 B：只重排现有 GroupManager

仅改善群目录、详情头部和成员列表，不接入 `conversation.view`。

优点：改动最小。缺点：群管理与运行仍然分裂，后续容易继续堆叠页面，不作为推荐。

### 方案 C：独立群运行中心

新建完整群工作台、运行历史、统计和设置页面。

优点：可自由定制。缺点：与原生会话和现有统计重复，状态与维护成本最高，本轮不采用。

## 6. 详细设计

### 6.1 群目录

顶部包含：

- 标题“群聊”。
- 唯一主动作“新建群聊”。
- 搜索框。
- “全部 / 运行中 / 未读 / 已归档”筛选。

每行展示：

- 由成员头像组成的 2×2 群头像；不足四个时保持可读，不拉伸头像。
- 群名称。
- 成员数。
- 运行、失败、未读、归档等状态。
- 最后发言人与相对时间。

首轮不展示消息正文预览。当前 `GroupSummary` 只有最后发言人和时间，没有正文；不得为目录中的每个群分别请求完整 `GroupView` 形成 N+1 读取。

状态：

- 无群：展示“创建第一个群聊”。
- 无搜索结果：提供清空搜索/筛选。
- 初次加载：保留最终行高的骨架，不造成布局跳动。
- 刷新失败：保留最后成功数据，在目录区域内显示重试。

### 6.2 群详情头部

展示：

- 群头像和群名。
- 成员数与讨论模式。
- 工作目录，使用原生 `PathLabel`。
- 当前访问模式。
- 是否存在群级模型覆盖。

动作：

- **打开群聊**：primary。
- **编辑成员**：secondary。
- 归档、诊断等：原生 `Menu`。

不再使用 `<details>` 模拟更多菜单。归档保留现有 revision 和运行状态检查，不扩大权限。

### 6.3 成员视图

每个成员一行：

- 头像、名称与职责摘要。
- 工作中、空闲、失败、不可用等状态。
- 有效模型及来源，沿用 `GroupModelControl` 的继承计算，不另写规则。
- 最近活动。
- “查看 Bot”“查看执行”和成员 `Menu`。

“编辑成员”进入统一编辑态，保留：

- BotKey 与成员 ID 校验。
- revision / membershipRevision。
- 未保存草稿与离开确认。
- 现有启停、移除和归档语义。

### 6.4 活动视图

使用现有 `turns + deliveries + messages` 展示最近 5–10 个问题：

- 问题首行、时间与状态。
- 参与成员。
- 失败或权限拒绝摘要。
- Token 和缓存命中；没有数据时明确显示未知，不补零。

点击“查看运行”后：

1. 打开对应群会话。
2. 激活 `dsh-bot-group-runs`。
3. 通过公开 `openView(view, focus)` 定位对应 `turnId`。

不通过 DOM 查找按钮或模拟点击选择 View。

### 6.5 设置视图

默认只读展示：

- 讨论模式。
- 群级和成员级模型继承关系。
- 工作目录与访问边界。
- 历史可见性。
- 归档状态。

点击编辑后再显示表单，避免首屏就是完整配置页。

### 6.6 会话内成员与运行 View

使用 rc.2 已公开的 `conversation.view` 注册：

- `dsh-bot-group-members`
- `dsh-bot-group-runs`

要求：

- 复用第 6.3、6.4 节的展示组件与数据源，不复制业务实现。
- 只激活当前选中的 View，历史 View 不持续持有 Session/统计订阅。
- 保存原生 View 偏好，不另建客户端持久偏好。
- 群会话头部“群管理”入口进入成员 View。
- 空白 Session 不渲染 View 标签时，保留 Bots 群目录与头部入口作为回退。
- 无对应原生服务时保留原页面，不阻断现有群聊。

### 6.7 从群到单聊

成员操作增加“在单聊中追问”：

1. 打开该 Bot 的持久主会话。
2. 使用原生 `sessions.using` 和 `requestDraftInitialization` 预填选中的问题或回复。
3. 只填写草稿，不自动发送，不发起模型请求。

沿用现有职责编辑的草稿初始化模式，保留迟到导航取消与 Bot 身份检查。

## 7. 原生能力复用

| 原生能力 | 用途与边界 |
| --- | --- |
| `conversation.view` / `openView` | 会话内成员/运行视图与深链接定位 |
| `Button` / `Menu` / `SegmentedTabs` / `Modal` | 操作、导航、编辑确认与焦点管理 |
| `InlineEditor` | 群名快速编辑，保留 Enter/Escape/IME 语义 |
| `rankByName` | 群和成员搜索 |
| `ReferenceChip` | 结构化成员与 Bot 身份入口 |
| `HoverCard` | 桌面成员摘要；移动端使用详情回退，不作为唯一入口 |
| `Tag` / `Pill` / `StateDot` | 统一运行、失败、归档、不可用状态 |
| `PathLabel` | 工作目录 |
| `ConnectionIndicator` | 断线、重试和恢复反馈 |
| `ShortcutKeys` | `@`、`/`、Enter 等键盘提示 |
| `ImageLightbox` | 群图片附件原图预览 |
| `requestDraftInitialization` | 单聊追问草稿 |

所有 API 只从公开包入口使用，不导入 DSH 内部组件，不修改宿主样式或全局主题。

## 9. 数据、状态与性能

- 群目录只读取现有 `catalog`，不逐行请求完整 `GroupView`。
- 选中群才创建详细 `createView`，切换与卸载时 dispose。
- 有效模型沿用现有 `GroupModelControl` 计算结果。
- 统计沿用 `GroupStatistics` 数据源，只读取当前问题或用户明确选择的全群范围。
- 不新增独立定时器；轮询继续纳入共享 scheduler 和 `ctx.effect`。
- 后台刷新保留最后成功快照，不清空内容、不重置草稿与展开状态。
- 归档群只读；不可用成员保留身份，不静默删除。
- 空、加载、失败、无权限、统计未知分别呈现，不伪造零值。
- 群成员、View、统计和图片资源均纳入所属 Context effect 生命周期。

## 11. 验收方案

### 11.1 单元与 DOM 回归

覆盖：

- 群搜索、筛选、排序与空态。
- 成员有效模型来源。
- 活动到运行的 `openView` 参数。
- 归档与不可用状态。
- 编辑脏状态、保存冲突与返回确认。
- 菜单 Escape、焦点恢复与键盘操作。
- 单聊只预填、不发送。
- View、统计与 Session 订阅释放。

标准命令：

```sh
scripts/pnpm check
scripts/pnpm check:docs
scripts/pnpm check:format
```

### 11.2 真实隔离 Host 与浏览器

全部使用 `.dsh-dev` 与合成模型，不启动真实模型任务。

矩阵：

- DSH rc.2 与 rc.5。
- 中文 / English。
- 亮色 / 暗色。
- 1440 / 768 / 390。
- 0、1、50 个群。
- 2、16 个成员。
- 长群名、长 Bot 名、同名 Bot。
- 运行中、失败、归档、不可用成员。
- 有统计、无统计、部分统计。

关键断言：

- 打开目录和详情不新增模型请求。
- 活动定位到正确 `turnId`。
- 切换群不串数据或草稿。
- 右侧详情和原群消息行为保持不变。
- 无页面横向溢出。
- 所有成员操作在窄屏也可达。
- 反复进入/退出 View 后订阅和 Session 引用释放。

### 11.3 证据边界

- DOM 测试不能代替真实浏览器。
- 合成模型结果不能代表真实群聊质量。
- 正式桌面安装和用户真实任务复验需单独授权并记录。
- 未完成或受阻的项目必须明确标记 `FAIL` / `NOT_RUN`，不得把静态检查当成运行通过。

## 12. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 空白 Session 无 View | 保留群目录和头部入口，提供页面回退 |
| 目录与 View 重复实现 | 共用展示组件与数据源，不复制状态 |
| 群列表预览造成 N+1 | 首轮不显示正文预览，后续独立评估 Host 契约 |
| 统计读取扩大内存占用 | 仅当前选择范围，沿用现有限流与释放机制 |
| 社区旧版 API 不兼容 | 只借鉴交互，不导入实现或依赖 |
| 改造演变成新运行系统 | 不重写调度、消息和权限逻辑，按三个小 PR 验收 |

## 13. 建议审批结论

建议按 **PR 1 → PR 2 → PR 3** 执行，默认决策：

- 采用原生 `conversation.view`，不另建群运行应用。
- 保持 DSH 原生视觉，不引入新主题或 UI 依赖。
- 首轮不改 Host、不改持久数据、不改执行协议。
- 群列表消息预览和自定义群头像后置。
- 不在本轮安装正式桌面或启动真实模型。

审批通过后，从 **PR 1：群目录与群详情** 开始实施。若需调整范围，优先确认以下三点：

1. 是否接受“群目录 + 会话内成员/运行 View”的信息架构。
2. 是否同意首轮不实现群列表消息正文预览。
3. 是否同意三个 PR 的顺序与验收边界。

## 14. 实际实现与验收结果（2026-11-05）

本次在一个工作分支完成原 PR 1–3 的实现，未创建提交或推送。最终取舍如下：

- 只注册一个公开 `conversation.view`：`dsh-bot-group-management`，内部使用原生 `SegmentedTabs` 切换成员、活动、设置。多个动态 View 会在原生恢复时竞争，因此不采用原方案的两个独立 View；切到普通 Bot 会话时注销群 View。
- 群目录使用现有 `catalog` 和 `rankByName`，提供共享搜索框、原生筛选菜单、刷新图标、简洁计数、组合头像、成员数、最后发言人与相对时间。新建入口位于列表末尾，不再堆叠大型筛选按钮；没有新增逐群 `view` 请求。
- 群详情展示真实描述、成员状态、有效模型及来源、最近 10 个问题、参与成员、失败原因与既有统计。`bot-…` 占位 ID 不再作为职责描述；资料、查看执行、单聊追问收进原生成员菜单。工作目录、讨论模式、模型继承和归档状态来自同一 `GroupView`。
