# 取消独立 Bot 模式，回归 DSH 原生工作区

2026-11-18 · 产品与技术设计。实现与同包实测见 [原生工作区验收](../../verification/native-bots-workspace.md)。首个交付目标是官方 macOS DSH 0.2.2-rc.5，升级回归基线是 0.2.2-rc.3。

## 1. 产品决策与依据

用户安装一个 `dsh-botgroup` 插件，从 DSH 侧栏的 **Bots** 进入目录，选中对象后在原生会话中聊天。移除面向全局的模式开关、独占界面和对应的安装步骤。自动协作、主动跟进、回传授权各自保留明确的用途与设置入口。

本机上次排查观察到，rc.5 正在加载官方 web-app 和产品插件，标准侧栏、Bots 入口和已有 Bot 会话均可见。旧适配包仍在依赖中，只适用于 rc.3。两版的快捷键、聊天和工作区三个目标 Client 字节相同，旧实现仍需专门选择与宿主版本匹配的组合。在每次升级前重新认证整套桌面外壳，对保留聊天和群审批的价值很低。以上是现状证据；下文的原生方案仍需完成第 7 节的运行验收。[原适配的原因与限制](../../verification/official-signed-desktop-update.md) · [原生扩展入口](../../../packages/dsh-bot/src/client/index.tsx)

这项取舍对用户可见。DSH 的“新建会话”、搜索、分支和归档执行宿主动作。新建 Bot、建群和管理成员在 Bots 内操作。以后某项宿主接口改变，受影响的入口显示具体原因和可用去处；普通 DSH 启动和导航独立于这些扩展。

## 2. 用户从哪里完成任务

| 用户意图 | 目标入口与交互 |
| --- | --- |
| 找到原来的 Bot 或群 | 侧栏 **Bots** 打开现有目录。首屏提供搜索、置顶和最近使用，区分同名 Bot 与群。选中条目进入原生会话。返回目录恢复筛选和位置。DSH 自己的最近会话也能直接进入。 |
| 和一个 Bot 聊天 | 使用这个 Bot 已绑定的主会话、原生输入框、文件、模型选择、访问模式、提问和审批。会话右上 **资料与详情** 打开当前 Bot 的任务、资料、记忆和管理入口。 |
| 在普通群里协作 | 打开原群会话。沿用点名、回复、成员选择、模型与权限选择、执行详情、停止、附件及真实发言者。群根确认后才显示群输入框；原生审批或提问接管时，保留群草稿与输入选项。 |
| 请三个成员记录经验 | 在普通群的 **＋ → 只记录记忆** 选择本次动作，输入框显示可取消标签。仅在同一草稿成功提交后清除，发送失败保留。群里按成员显示“已记入”“失败”或“未核实”，以实际写入收据为准。 |
| 审核三份回传 | 输入区旁固定显示 **待审核群回复（数量）**，按轮次列出。逐份查看全文和读者，勾选后一次提交，仅授权本次。也可逐份拒绝、稍后处理或丢弃已失效且可安全关闭的条目。成员回复陆续出现时队列保持可达，逐项回显结果。 |
| 设置以后如何回传 | 原群右侧 **资料与详情 → 设置 → 始终允许回传**。列出具体 Bot 和完整读者，确认后对该 Bot 后续符合条件的内容生效。既有待审项留在队列；更换成员使旧授权失效。 |
| 跟进或继续任务 | **资料与详情 → 任务** 保留当前 Bot／群的主动跟进。自动组队产生的讨论在原始 Bot 消息下有工作卡，可进入群、补资料、停止、返回发起 Bot，最终结果仍回原对话。 |
| 处理跨会话工作 | Bots 目录提供现有 **需要本人处理的任务**、通知与管理入口。分别标明“未读”“待回传”“待补充／待核对”；点击定位原群、原消息或原生审批控件。目录和系统通知只呈现有权显示的摘要，私有待审正文由群内审核入口读取。 |

宽屏使用宿主右栏，窄屏使用可返回的详情视图，返回后仍指向原会话与草稿。群详情聚合概况、任务、资料、成员、设置；Bot 详情复用现有私聊面板。已在会话里打开资料时，不重复弹出第二个管理面板。右栏扩展不可用时，页内按钮落到 Bots 的对象详情或现有“群管理”视图，并定位同一项设置。沿用 DSH 主题、焦点和中英文文案。打开资料、查看审批数量、切换面板均无模型请求。[现有右栏](../../../packages/dsh-bot/src/client/right-tab.tsx) · [群管理视图](../../../packages/dsh-bot/src/client/group-views.tsx) · [群回传交互验收](../../releases/v0.7.1.md)

## 3. 技术落点

| 实施位置 | 复用与改动 |
| --- | --- |
| 桌面与目录 | 复用 `main` 的 `dsh-bot` 页面和 `sidebar.panellist` 注册。把旧联系人列表的对象身份、搜索、置顶、未读投影移到现有 Bots 目录。撤掉底部模式菜单、全局 guard、命令覆盖、全屏侧栏与会话替换。普通会话继续由 DSH 渲染。 |
| 会话与群输入 | Bot 走 `openConversation → uiWorkspace.openSession`；群走准确 GroupKey 对应的 rootSessionId。继续使用已注册的群消息、输入框和执行视图。普通群走 Groups 的发送接口；自动协作群核对原工作身份和 revision 后走 `sendGroupInput`。群身份尚在加载或无法确认时保留草稿并暂停提交，禁止把同一内容改投普通会话或另一类群。 |
| 详情、资料与工作卡 | 从旧外壳抽出仍独有的当前工作资料、接收者预览、群来源返回和详情导航，接入已有 Bot 右栏与群管理页。按当前 session 和 Bot／群代际重新绑定，切窗后迟到的请求只能更新原对象。文件补充绑定具体工作及读者。 |
| 协作与权限 | `registerSupergroup` 直接使用既有 owner Remote 和公开的插件设置扩展。移除对模式生命周期的回调依赖。Host 继续负责私有记忆、群成员、精确回传、预算、工作取消和幂等；界面只展示、导航、提交明确操作。 |
| 打包与资源 | 产品分发使用官方 DSH、官方 web-app 和一个产品插件。构建与启动移除对 `dsh-bot-web-app`、私有命令桥和三个 Client 补丁的依赖。历史迁移和回滚仍能识别旧包。仅在替代入口通过后清理无调用的旧 shell 组件、文案、样式和发布说明。所有新增注册与订阅由 `ctx.effect` 释放。 |

工程入口见[原生界面装配](../../../packages/dsh-bot/src/client/index.tsx)、[主会话绑定](../../../packages/dsh-bot/src/host/main-session.ts)、[群发送分流](../../../packages/dsh-bot/src/client/groups-state.ts)、[群原生输入](../../../packages/dsh-bot/src/client/workspace-group.tsx)和[协作工作卡与设置](../../../packages/dsh-bot/src/client/supergroup.tsx)。

### 需要先验证的宿主行为

- **空白 Bot 会话冷启动。** 旧补丁曾修复空白会话恢复时丢失 preset。用原版 rc.5 建立空白 Bot 会话，重连、重启、跨工作区打开，再从目录和历史分别进入。核对同一 session、Bot 代际及首次发送时的实际身份。若原生隐式导航会复用错误 preset，优先使用公开的显式目标导航；仍不能证明身份时保留原记录并暂停发送，提供针对该 Bot 的恢复入口。已有绑定或记录异常时，查看目录不得静默创建替代主聊。[旧空白会话的复现](../../../adapters/bot-mode-workspace/README.md)
- **分支、归档与深链。** 原生分支可产生新的会话。只有 Host 能核实的会话才获得对应 Bot 或群的业务操作，来自历史或分支的普通聊天记录不能据此解锁私有记忆、长期授权或协作续办。归档会话与删除 Bot、解散群是不同的用户操作；重名、删除后重建、旧深链均按原 ID 和创建代际核对。[原生命令实测记录](../../spikes/bot-mode-shell.md)
- **插件局部不可用。** 目录服务不可用时只在 Bots 页显示“暂时无法读取 Bot 和群”；目录、输入和详情按各自所需的宿主接口独立注册。资料加载失败时只禁用相应动作。群输入接口缺失时，群历史仍可查看，输入区解释暂停发送的原因。历史上的“Bot 中心未就绪，请刷新”全局遮罩随模式移除。依赖缺失时保留已确认的原会话入口。写入结果未知时先核对原操作收据；刷新只重读状态。

## 4. 开关、工作与权限如何承接

**自动协作沿用现有的 `supergroup.enabled`。** 在“插件 → DSH-Bot → 自动协作”提供唯一的设置来源，Bots 管理页可跳转。文案说明开启后 Bot 可以在任务内组队并邀请专家，关闭会停止相关运行中的协作。修改通过既有 owner Remote，核对 `expectedEnabled`；跨窗口并发变更后先读回。进入或离开 Bots 页面只导航。主动跟进按 Bot／群独立开启，群回传策略按 Bot 与当前群受众生效。[配置默认值](../../../packages/dsh-bot/src/host/supergroup/config.ts) · [运行中的协作与取消](../../../packages/dsh-bot/src/host/supergroup/service.ts)

| 安装时读到的状态 | 升级后的处理 |
| --- | --- |
| 明确开启或关闭 | 原值继续决定自动协作。仅迁移 UI 不写 Host 配置，避免触发取消活跃工作的副作用。 |
| 首次安装或已确认字段缺省 | 继承 schema 默认关闭。Bot 私聊和手动群聊可以直接使用。 |
| 读取失败、配置损坏、版本冲突 | 显示“暂时无法确认自动协作设置”并提供重读。读失败不当作关闭写回；基本导航继续。 |
| 旧窗口保存过置顶或选中对象 | 按旧窗口的 `sessionStorage` 尽力承接有效置顶。选中记录用于目录定位，尊重 DSH 已恢复的前台会话。显示偏好不得成为身份、读者或授权依据。 |

**保持原有数据的权威来源。** 复用现有 Bot ID、创建代际、主聊及群根绑定、成员、轮次、交付、任务收据、私有记忆正文及访问规则。无需搬运历史或重建索引来生成界面。批量回传继续逐份核对正文、群、成员版本和读者；“始终允许”不自动批准既有队列，查看或恢复页面不触发发送。只记录记忆时群里仅提供写入状态；服务商拒绝、权限阻断和结果未知分别呈现，不由客户端猜测成功。人数上限沿用现有规则：新建或增员最多 6 人，用户设定的更小限制优先；遗留超限群保留完整历史和成员，按既有限制处理后续操作。[回传权限检查](../../../packages/dsh-bot/src/host/groups/export-settings.ts) · [成员上限](../../../packages/dsh-bot/src/shared/group-limits.ts)

**区分界面切换与实际重启。** 导航到 Bots、切换详情、关闭右栏均不得影响正在执行的工作。安装新版可能卸载 Host 或需要冷启动，已有进程不能保证延续。日常切换前读取活动轮次、交付及协作状态；有运行中工作时优先等其结束。冷启动沿用既有逐项恢复规则，例如意外中断的协作工作从 `running` 转为 `unknown`，普通群已启动的交付转为未知、相应轮次进入待恢复。原工作 ID、预算及已有收据保留，核对前不重放。需要退出桌面时，先处理仍在窗口内的未发草稿。相关状态见[协作恢复](../../../packages/dsh-bot/src/host/supergroup/service.ts)和[普通群恢复](../../../packages/dsh-bot/src/host/groups/roots.ts)。

## 5. 安装迁移与回滚

| 当前桌面组合 | 迁移动作 |
| --- | --- |
| 官方 rc.5，已经选用官方 web-app | 直接在隔离环境验证新产品包与此组合。日常切换只更新产品插件。已安装但未选中的旧适配包可以先保留，确认没有活动引用后再用包管理流程清理。 |
| rc.3 或其他已知安装，仍选用旧替代 web-app | 在当前 profile 的暂存副本里，按原位置将旧替代包换为官方 web-app，保留其他 bundle 顺序及产品包名。使用目标版本官方配置组合器，核对 shortcuts、ui-chat、ui-workspace 每个原生 ID 唯一，确认用户当前聊天设置、模型与权限实际读写生效。 |
| 已升级、旧组合失效，或有自定义配置 | 先识别实际选中的包、配置层及用户后来写入的设置。在副本中恢复官方组合并检查生效差异。遇到无法解释的差异，保留现场和备份，明确指出哪项需要人工选择。 |

迁移工具复用已有的 profile 锁、完整性检查和原子交换；现有首次安装脚本对“已安装旧包”和旧产品名有前提，需要针对当前状态新增迁移分支。配置组合在副本中进行，因为目标宿主的加载器可能顺手更新退休 bundle 的声明。保护用户最新的 `ui-chat` 设置，包括之前迁移产生、仍在生效的通用 ID 配置。[首次安装工具](../../../scripts/install-official-desktop-compat.mjs) · [profile 更新与回滚](../../../scripts/update-bot-mode-desktop-plugin.mjs)

上线顺序为隔离演练、冷备份、比对暂存配置、切换、启动、只读核验。备份使用切换当时的 profile、相关数据和校验摘要。切换失败且 profile 仍等于本次写入结果时，可原子撤回本次 profile 修改；若用户已写入新设置，执行定向反向迁移。rc.5 的回退目标应是能启动的**官方 rc.5 界面和兼容产品版本**，不把 rc.3 专属适配包重新选给 rc.5。保留升级后的聊天、记忆、授权和设置。用户日常库的端到端发送、记忆写入和审批验证均用隔离样本替代。

## 6. 实施顺序

| 顺序 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P0 先在原版证明关键路径 | 官方 rc.5 + 原版 web-app + 产品包，隔离 profile 建立一个 Bot 主聊和一个三人群。优先跑空白 preset、群根输入、原生审批接管、自动协作群接续。 | 真实 Host 和界面均能核对身份、会话、消息及请求数。身份或输入归属无法证明时，该路径保持只读；修复并复测后再发布。 |
| P1 用户入口和业务解耦 | 改造 Bots 目录，迁入详情、任务资料、发起 Bot 返回入口；自动协作设置直接连 Host；补充错误、窄屏和键盘交互。 | 在官方组合上，从目录和历史两处均能独立走通第 2 节，不需要原生 Client 补丁。 |
| P2 移除模式及交付依赖 | 移除模式菜单、命令注册、独占 slot 和全局遮罩。更新打包、安装和升级说明，提供可重复执行的 profile 迁移。保留历史回滚所需工具。 | 原生全局命令正常；干净安装仅需一个产品包；旧 profile 的设置与存量数据核对通过。 |
| P3 发布验收 | 在同一冻结包上跑下表，完成一次从 rc.3 旧组合升级到 rc.5 官方组合的演练。 | 保存版本、安装与实际加载字节、交互、收据、数据对比和回退结果。通过后再安排日常更新。 |

## 7. 上线验收

| 场景 | 必须得到的结果 |
| --- | --- |
| 安装与日常打开 | 在原版 rc.5 安装一个 `dsh-botgroup` 后即有 Bots 入口；冷启动和第二窗口均可用。无模式开关、无全屏未就绪页。官方应用签名和实际加载的原生 Client 可核对。 |
| 私聊与全局导航 | 从目录和历史打开同一 Bot，两次得到同一主会话与旧记录；新建但未发消息的 Bot 重启后仍以准确身份首发。测试新建、搜索、分支、归档、旧深链、同名重建和双窗口切换。普通会话的快捷键和原生审批正常。 |
| 三人群批量回传 | 制造三份需审核的回复，审批其中一份，其余仍在固定队列；逐份预览后批量处理另外两份。另测拒绝、稍后重新打开及丢弃已失效项，核对计数、键盘焦点和零发送。双窗口重复提交、审批中成员变化、发送成功后回执中断均不得二次发布。 |
| 跨会话待办与通知 | 在另一群或私聊收到待办，点击定位原对象；核对已处理、归档及同名重建的旧通知不会误开其他对象。通知摘要无私有标记，单击后无批准、写入或重放。 |
| 始终允许与记忆隔离 | 对一位 Bot 开启，旧待审仍在、后续合规内容可回传、其他两位仍逐次确认；撤销及增减成员后再核对。对三份不同私有记忆设置可识别标记，证明互相不可读，且群记录没有泄漏正文。 |
| 只记录记忆 | 实际点击＋菜单，验证可取消、发送失败保留、成功自动清除、下一条恢复普通发送。用原生工具回执和实际存储核对每名成员，将故障样本正确归为失败或未核实。私聊、引用回复和自动协作群中按现有支持范围呈现。 |
| 六人及历史群 | 三人和六人均可操作；第七名在 UI 和 Host 都被拒绝，小于六的有效配置生效。停用但未移出的成员仍占名额，满额时仍可取消选择。历史超限群保留成员与记录，恢复至限制内前禁止发起或续办工作；成员编辑只允许从原名单减员。 |
| 自动协作与主动跟进 | 分别以开启、关闭、缺省和读取失败的设置启动。进入 Bots 不改变配置。开启时验证原 Bot 发起工作、组群、邀请专家、群内补充和原对话交付；主动跟进单独开启，查看不执行。冷启动未知工作零重放。 |
| 草稿、失败与视图 | 切 Bot／群、打开资料、原生审批接管、断线重连，验证同窗口草稿不串。区分内容风险、执行失败、等待回传和结果未知。390px 窄屏、中英及亮暗主题、键盘与读屏均能访问菜单、队列、取消标签和返回按钮。 |
| 旧安装迁移及回滚 | 覆盖已选旧适配、残留旧依赖、官方组合、重复迁移和中断恢复。比较实际生效配置、旧会话与绑定、群记录、私有记忆及权限、待审与长期授权。升级后再添加一条历史、修改一个设置，验证回滚仍保留两者。 |
| 下次升级 | 已知原版 rc.3 与 rc.5 做真实 Host／浏览器回归，rc.5 另验 macOS 原生窗口与系统快捷键。模拟可选右栏、文件上传或设置服务缺失，验证其他入口继续工作。每个后续目标宿主用其官方产物重跑核心用例，再公布支持范围。 |
