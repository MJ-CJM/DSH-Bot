# Bot 聊天界面重设计 · 已批准

日期：2026-11-12。用户随后已批准本稿实施与独立服务部署；产品落实和真实验收见[交付报告](../../../verification/bot-mode-visual-delivery.md)。以下保留原审批设计及其当时的原型证据，不能将原型结果当作产品运行证明。

推荐采用「联系人列表 + 聊天 + 按需详情」。日常只需找到 Bot、说需求、收结果；群协作作为聊天的自然延伸。原型入口：[交互设计稿](bot-chat-redesign.html)。其中消息、成员、模型选择和状态均为示例，不调用模型、不接入 Host。

## 这次改什么

| 当前问题 | 推荐设计 |
| --- | --- |
| Bot Center、搜索标签、Add、大按钮和星标占据左栏 | 紧凑品牌区、小型新增按钮、一个搜索框；联系人行展示头像、名称、真实摘要和时间 |
| 每行都是描边按钮，头像缺少辨识度 | 整行点击、浅色选中背景；真实 Bot 头像优先，现有 fallback 次之；置顶/归档收进对象菜单 |
| 欢迎行和输入框挤在顶部 | 标题固定、消息独立滚动、输入贴底；空态给一句职责介绍和少量可填入草稿的示例 |
| Details / Materials 和两套设置同时出现 | 标题右侧一个「资料与详情」入口；右栏内分详情/资料/成员；左下一个设置入口 |
| 中英混杂、字号层级不清、日期重复 | UI 跟随宿主语言，Bot 自定义名称保持原文；时间靠右，无消息时显示职责而非创建日期占行 |

输入位置是本次验收重点。原稿功能流程的通过，不等于布局或视觉质量已经通过；新的视觉验收不能沿用此前截图的结论。

## 布局与视觉规格

- 默认两栏，右栏收起。宽屏左栏约 266px，消息阅读宽度最多 760px，输入最多 800px；打开详情时右栏约 288px。标题统一高度，输入在空态、短消息和长消息下保持一致位置。
- 1100px 以下右栏作为覆盖面板，不继续压缩消息；700px 以下列表、聊天、详情逐层进入，保留返回路径和当前对象。
- 联系人行约 72px，头像 38px。正文 14px，次要信息 12px；辅助时间最低 11px。采用细分隔线、轻选中背景和有限圆角，避免每个控件一圈边框。
- 产品实现只使用宿主 `--dsw-alias-*` token。原型根部定义的浅/深色值仅模拟主题，不作为产品硬编码配色。正式版本复用 BotAvatar / GroupAvatar 和已有用户头像数据。
- 原型的消息气泡、时间和操作栏表达目标层级；实施继续复用原生 Conversation、composer、审批、工具执行和已有群消息组件，不能为了像截图而重写执行逻辑。
- 名称过长截断并提供完整可访问名称。同名 Bot 保留不同对象，使用已有职责/简介辅助区分；没有可区分简介时展示已有创建信息，精确身份在详情核对。绝不按显示名合并或删除用户数据。

## 交互合同

1. **Bot 私聊**：直接进入长期 Bot；最后结果在原 Bot 交付。协作只增加一张轻量进展卡，展示工作名称、成员和查看讨论入口，不自动抢焦点。
2. **自动群**：真实作者名字与头像、加入事件、用户补充和整体停止。群内随时可回原 Bot。资料只展示当前已授权文字和既有成果引用，不增加上传解析或私有记忆共享能力。
3. **资料与详情**：打开/切换标签不改变草稿或消息阅读位置。Bot 显示详情/资料，群额外显示成员。记忆打开该 Bot 已有管理页。
4. **模型与权限**：入口保留在输入区，按真实 Bot/群上下文使用现有设置。原型按对象隔离演示选项；群权限只说明现有入口，不模拟增加完全访问权限。实际可选项与授权效果由 DSH 现有能力决定。
5. **联系人菜单**：置顶作用于所选对象。新建只保留 Bot 和手动群，自动协作无需手动组队。运行中群先停止才可归档；归档移出对象列表、保留数据，不声称现有「更早的群」可以恢复已归档对象。
6. **列表调整，待本稿审批**：刚完成的群仍在最近活动里，避免完成后立即消失；较早的已结束群折叠。只调整可见列表分组，不改变工作状态和持久数据。原型已完成群放在最近列表，用于审批该体验。
7. **设置**：日常只保留一个设置入口；Supergroup 状态显示在品牌区，开关仍使用已有设置合同。原型不实际切换服务配置。

## 状态覆盖

| 状态 | 展示与操作 |
| --- | --- |
| 首次打开 Bot | 头像、职责、简短引导；示例只填草稿，发送由用户决定；输入仍贴底 |
| 已有聊天 | 最近消息、原生生成/审批/停止；长消息单独滚动，尾部操作完整可见 |
| 协作中 / 交付 / 停止 | 同一工作卡更新状态，真实成员和停止范围可辨，记录保留 |
| 同名 Bot | 独立对象行与职责副标题，选中和设置不串用 |
| 连接中断 | 原有记录与草稿保留；简短状态和重新连接入口，不出现空白整页 |
| 发送待确认 | 显示真实待确认状态，不盲目重试或重复创建工作；保留草稿 |
| 无匹配对象 | 搜索区内解释无匹配，不引导创建重复 Bot |
| 完全无 Bot | 单一「创建 Bot」引导，沿用现有表单；本稿文字定义，原型未模拟空注册表 |
| 未知/失效链接 | 说明对象不可用，返回列表；不把未知历史挂给同名 Bot。本稿文字定义，原型未接真实深链 |

原型可点击左侧 Bot/群、查看讨论、资料与详情、成员、空态示例、发送与停止、搜索和设置。宿主提供的设计控件可切换浅/深色、列表密度和长消息/同名/连接中断/待确认状态。所有操作只更新原型内存。

## 原生复用与落实顺序

这次先调整插件 UI。没有证据要求追加宿主适配，已有三个适配包保持原范围。

| 顺序 | 调整范围 | 实施门槛 |
| --- | --- | --- |
| 1 | 缩小插件 CSS 作用域；修复空态占位与消息/输入布局 | 真实空态→首条消息→长消息、输入增高、审批、窄屏、焦点和草稿验证 |
| 2 | 联系人行、标题、单一设置入口、中文文案 | 真实头像/摘要、重名、长名、置顶、未读、完成分组及键盘可访问性 |
| 3 | 右栏、成员与资料排版、轻量协作卡 | 不重复实现 Host 能力、不扩大资料可见范围；打开面板保留阅读位置 |
| 4 | 同包视觉与功能验收 | 原生真实组件在亮/暗色、中文/英文、宽/窄窗口下截图与交互验证；再更新独立审批服务 |

只读核实的原因：

- 当前 `packages/dsh-bot/src/client/bot-mode/style.module.css` 对 `.dsh-bot-mode` 下所有 `button/input` 加样式，会匹配原生加号和文件 input。应限定到插件自有导航、标题、右栏，不能覆盖原生 composer 后代。
- 固定 rc.2 的 `DefaultConversationViews.tsx:32` 在真实 blank 时返回 null；`ConversationContent.tsx:198` 的 scrollBody 因而可能只剩 composer；`ConversationRoot.module.css:431` 的 sticky bottom 不主动把短内容推到底。
- `contract/slots.ts:318` 提供 `conversation.content` 的局部 `slots.views`，原生 `ui-subagent` sidebar-chat 有注入范例。可先验证自有弹性容器内部继续调用公开 `conversation.session` 的包装方式；不能复制内部 viewArea CSS。此处仅源码核实，尚未运行证明。
