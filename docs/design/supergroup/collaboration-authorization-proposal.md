# Supergroup 自动协作授权优化提案

日期：2026-11-13。状态：用户已批准；P0 仓库实现、隔离验收及后续日常部署完成，详见[实施验收](../../verification/supergroup-collaboration-authorization.md)与[部署记录](../../verification/supergroup-collaboration-desktop-deploy.md)。下方保留原始设计与当时检查记录；P1 尚未完成。

## 1. 建议采用的产品规则

**开启 Supergroup，即允许已有 Bot 围绕用户的当前任务自动协作；文件访问继续使用当前设置。**

用户只需开启一次、正常提需求。系统自动决定直接询问其他 Bot、委派或建群，需要时邀请已有专家，最后由发起 Bot 在原对话交付。两位 Bot 的简单问答不强制建群，不暴露后台执行会话。

开关旁说明：

> 允许你的 Bot 为当前任务自动互相提问、组队、邀请专家并汇总。默认共享本次提供的任务材料，文件访问权限沿用当前设置。

无需新增授权面板或要求逐个批准成员。过程折叠展示“研究员正在请通用助手协助”，提供统一的“停止”。涉及扩大资料范围时才展示具体资料与接收者。

| 行为 | 优化后的处理 |
| --- | --- |
| 询问、回复、委派、自动组队、范围内加专家、同任务接续、原对话交付 | 自动执行，不产生本插件的逐次协作审批 |
| 分享本次用户文字与已授权的同任务成果 | 随工作授权复用，工具执行和资料流转使用同一依据 |
| 分享其他私聊、长期记忆或新增私人资料 | 确有需要时，针对资料与接收范围一次明确选择／确认；同范围不重复询问 |
| 文件读写、命令、联网和对外发送等实际操作 | 沿用原生权限、审批和其他插件限制；协作本身不要求切换文件访问模式 |
| 关闭 Supergroup／停止本项工作 | 撤销后续协作，取消尚未投递的队列，保留历史与已产生结果 |

当前文件模式允许的操作继续执行；被宿主策略禁止的动作显示具体原因和待处理状态。不能承诺任何文件操作都免审批，也不能把内部协作许可扩大为全局工具批准。

## 2. 现在为什么反复受阻

这是授权入口不一致造成的交互冲突：

1. [Bot 消息](../../../packages/dsh-bot/src/host/messaging/tool.ts)通常主动要求一次原生 `ask`；已有获批线程仅有限复用。
2. [Bot 委派](../../../packages/dsh-bot/src/host/delegate/tool.ts)逐次要求 `ask`；[队友执行保护](../../../packages/dsh-bot/src/host/messaging/safety.ts)对工具使用另有限制。
3. [资料出口](../../../packages/dsh-bot/src/host/data-flow/outlets.ts)在接收方无权读取内容时，另行要求精确资料授权。
4. [现有 Supergroup 工作授权](../../../packages/dsh-bot/src/host/supergroup/service.ts)已支持受限自动组队，但旧消息／委派入口没有统一使用它。

DSH 的 `never` 表示“需要询问的动作直接拒绝”，不是“全部允许”；它在审批答复器之前生效。因此修改自动答复器或提示模型换一种工具不能解决。最近修复的原生上下文来源误判是独立问题，不等于已经完成无审批协作。现有证据见[来源兼容与原生审批记录](../../verification/bot-native-context-approval.md)。

## 3. 最小实现：一种工作授权，覆盖所有协作入口

### 3.1 开关提供持续许可，真实请求提供具体范围

复用现有 Supergroup 工作记录和准入，不另建调度系统。Host 从真实用户消息自动建立任务范围，绑定发起 Bot／消息、已有允许 Bot 的完整身份、任务材料、协作动作、预算和有效期。模型提出分工与目标，Host 核对范围；队友消息、网页指令或工具参数不能自己签发授权。

开工时沿用现有允许 Bot 配置和成员上限；同范围专家随时加入，无需确认。新增、替换身份或范围外目标不自动获得旧工作的资料。后续真实用户补充归入同一工作，新增材料和受众只处理差异。

### 3.2 统一消息、委派、群协作与资料准入

`bot_message`、`bot_delegate`、组队、加专家、续办和返回共用一个判断：**有效工作 + 允许动作 + 可读材料 + 允许接收者**。满足时不增加本插件的重复 `ask`，资料出口也不因相同已授权材料再次询问。

原有来源检查保留，对 Host 验证的同一工作 continuation 增加精确分支，覆盖目前仅接受真实人类输入的委派和队友保护；队友消息本身仍不构成人类授权。仍执行原生 `next()` 和工具 guard；宿主／其他插件返回的 `ask`、`deny`、`cancel` 不被提升为允许。关闭模式或没有工作授权时，原有流程继续有效。不能将所有审批统一自动同意，也不能借 `run_code` 或更换工具名称逃逸。

### 3.3 长期 Bot 保留身份，任务执行限定资料

这是必须先验证的技术点：[MessagingCore](../../../packages/dsh-bot/src/host/messaging/core.ts)绑定 Bot 主会话，而[数据流检查](../../../packages/dsh-bot/src/host/data-flow/egress.ts)合并其已见历史与资料标签。主聊读过私人记忆后，不能仅给生成消息加 `workId` 就自动分享，也不能清空旧标签或要求模型“不要引用”。

先验证公开 API 能否为同一 Bot 的任务执行提供仅含已授权材料的上下文；无法做到时，复用原生隔离 continuation 执行该 Bot 的任务，沿用其身份、职责、模型和现有 Messaging 队列／收据，结果投影回原对话。它不是新 Bot，也不要求建群。

干净任务只注入本次真实用户文字与可读的同任务材料；任务拆分文字也必须从该上下文产生，不能直接转发长期主聊自由生成的私人摘要。未经授权的历史、自动私有记忆注入及工具读取结果不能混入可共享材料。摘要保留原资料限制。若所需公开 API 或上述准入组合尚不成立，先记录能力缺口并验证最小桥接，不能用提示词当隔离证明。

当前自动工作主要支持文字。附件选择／解析／版本授权另列后续增量，不能把开启模式解释为自动共享所有文件；老工作、老私聊及 unknown/no-egress 标签不批量改写。

### 3.4 文件权限保持独立，停止与预算统一

派生执行沿用发起任务的工作区与权限上限；Bot 自身更严格的限制仍有效，不因换 Bot、建群或邀请专家而提权。任务执行的权限上限组合须在 P0-1 通过公开 API 实测，不改写其他 Bot 主会话的持久设置；无法保证上限时不启用对应文件工具。不同 Bot 无需用户逐个切换文件模式。实际文件／外部工具继续走原生策略：`ask` 时可能询问，`never` 时所需询问会被拒绝并明确显示“策略阻止”，不能伪称用户点击拒绝或仍能弹窗。

复用现有成员、请求、超时预算与 Messaging 防循环，私信、群和接续累计计数。目标忙时正常排队，自动协作不打断或改写对方不相关工作。

关闭模式、停止、身份或范围变更后，在投递前重新核对并撤销失效工作。已发送内容不能宣称撤回。重连／重启按工作与操作收据恢复；无法确认的执行保留 `unknown`，不自动重发或重复创建群。

## 4. 开发顺序

| 优先级 | 内容 | 完成标准 |
| --- | --- | --- |
| P0-1 | 验证干净任务上下文与现有资料出口的组合，统一工作准入 | 不读取旧私聊的两 Bot 文字问答可自动完成，长期 Bot 身份和主绑定保留 |
| P0-2 | 接通消息／委派／组队／途中加专家／接续／交付 | 同一工作内不重复审批；简单问答不强制建群；权限模式不变 |
| P0-3 | 停止、预算、恢复、错误展示与轻量过程提示 | 所有入口撤权一致，无循环、重复投递或“自动拒绝”误报 |
| P1 | 明确选择的附件、私人资料片段和受众扩展 | 一次具体授权可在本工作范围复用，版本或受众变化重新核对 |

P0 不新增权限设置面板、不重建 Bot 系统、不迁移旧数据标签。若主聊天上下文限定能力不足，P0-1 先验证原生隔离执行与 Messaging 的最小桥接；未经运行验证不宣布免审批可用。

## 5. 必须通过的运行验收

以下为原始设计验收合同；当时尚未实现。当前逐项 PASS／FAIL、同包证据及范围以[实施验收](../../verification/supergroup-collaboration-authorization.md)为准：

1. `workspace-write/ask` 和 `danger-full-access/never` 下，同一合成文字任务均自动协作，内部审批数为零，原 sandbox／policy 完全不变。
2. 不建群的两 Bot 问答成功；原 Bot ID、主对话绑定与已有消息保留。
3. 自动组队、途中加专家、继续和原 Bot 交付共用授权及预算，成员实际参与。
4. 长期主聊含私人历史／记忆时仍能执行干净新任务；私人内容与旧 unknown/no-egress 标签不泄漏、不改写。
5. 未选资料、范围外目标、身份替换、资料版本变化不能借同工作标记自动通过。
6. 原生／其他插件的 `ask/deny/guard` 仍有效，文件权限未扩大；`never` 的拒绝提示准确。
7. 停止／关闭后零新增派工与投递，跨私信、群和接续的预算、防循环有效。
8. 重复调用、断线、强杀恢复不重复执行；不确定状态保留。开发锁定版和当前桌面宿主均用隔离环境与合成模型验证，真实模型质量另列。
