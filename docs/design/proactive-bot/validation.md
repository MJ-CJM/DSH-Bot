## 证据层级与报告格式

| 层级 | 能回答什么 | 不能支持什么 | 必备记录 |
| --- | --- | --- | --- |

| HOST-SYNTHETIC | 隔离真实 rc.2 Host、公开入口、真实会话/存储、合成模型/工具运行 | 模型判断能力、正式桌面兼容、生产业务通过 | Host CLI 实际版本、PID、profile、模型请求计数、关联 ID、日志 |
| BROWSER | 真浏览器与真实 Host 上的交互、主题、窄屏、键盘、状态一致性 | 后台无人值守可用、真实模型/业务验收 | 构建 hash、截图、交互断言、renderer error、浏览器版本 |
| MODEL-PILOT | 获授权的实际 Source/模型上的发现与执行质量、费用、干扰 | 未测项目、模型、外部渠道的泛化 | 授权动作范围/费用上限、来源与模型版本、盲评标签、失败与费用 |
| BUSINESS-ACCEPTANCE | 独立于执行者的用户/评审者按预先条件验收交付 | 自动推广到全部任务；证明无风险 | 交付版本/证据 digest、审核者决定、条件逐条结果、返工关联 |

所有结果行只用 PASS/FAIL。未跑为 `FAIL(NOT_RUN)`，未授权为 `FAIL(NOT_AUTHORIZED)`，环境为 `FAIL(ENVIRONMENT)`，能力缺失为 `FAIL(CAPABILITY)`；另设“适用范围/原因”列，不把不适用项目塞进通过率。旧记录可引用为背景，不能算当前版本验证。真实 npm 服务运行不等于真实 Host；合成模型请求虽然不花真实模型费用，仍应计入调用次数。

每次 run 保存：本仓库 commit/dirty diff hash、产品包 hash、上游 full SHA、协议/schema 版本、DSH CLI/Node/OS、Config（脱敏）、fixture hash、时钟/seed、命令/退出码、开始结束时间、断言、成本/副作用计数和失败收据。PID 与 profile 数据只留 `.dsh-dev/proactive-bot/<run-id>/`，可提交报告引用其脱敏摘要。不得收录凭据或真实源正文作为公开 fixture。

## 必须成立的不变量

1. Engine 单写业务事实；Source 游标不能越过未持久受理事件；重放允许重复接收，不允许重复任务/副作用。
2. core SQLite / Host JSON / 外部传输不具有分布式原子性。提交后派工，稳定 operationId 和请求摘要，unknown 是持久可见状态，不能自动转成功或失败后重试。
3. Ticket、Assignment、群 turn/delivery、child/session/run、证据版本准确关联。旧 Bot 代际、旧 policy、旧 worker 回报不复活新任务。
4. review/ready/ended/turn-end 都不等于独立人工验收。失败、blocked、unknown、预算耗尽和未执行均不得隐去。
5. 自动来源不可伪造 user；每次新副作用前权限取策略/Mandate/原生工具权限/数据目标许可的交集。撤权不能撤回已发出的请求，但必须阻止此后新发起的禁止动作。
6. 原生 schedule 仅提供其实际支持的时钟/投递语义；history/responded 不表示业务完成。不得重复建设通用 timer/runtime/group UI。
7. 核心 Outbox 与 Notifications 只有一个重试责任方；传输超时或冷恢复不证明“未发送”。现有 failed/suppressed 也不默认自动重试。
8. 生命周期清理覆盖连接、监听、timer（如经批准的 Source 必要摄取）、子进程与 DB；关闭先拒新工作再排空，对不确定项留持久收据。

## 性能与容量基线预算

先在 PB00/PB01 记录指定机器的冷启动/空载基线，PB09 再与同机、同 Node/Host/上游 SHA、同数据集比较。以下预算是**建议验收目标，尚无测量**；若不满足，需要解释瓶颈并评审调目标，不得删除慢样本。

| 指标 | 固定负载与测量边界 | 初始目标 |
| --- | --- | --- |
| 无模型过滤延迟 | 已在内存的1KB事件，1000条，去重/范围/过期，不含网络 | p95 ≤20ms/事件，p99 ≤50ms |
| 持久受理延迟 | 本地 SQLite，10k历史、1并发，再10并发；含事务提交 | p95 ≤100ms，p99 ≤250ms |
| 事件到建议延迟 | 无模型规则分支，来源已读到到建议投影可见 | p95 ≤2s；模型研判分支单独报告，不混入 |
| 接受到 Host 收据 | 同机、空闲、非模型工作；计核心IPC+Host持久受理 | p95 ≤1s；排队时间另列 |
| 冷恢复 | 10k事件、1k结束Ticket、100待处理effect，需对账范围固定 | ready ≤10s；ready不代表所有unknown已解决 |
| 突发摄取 | 100事件/s持续60s，单事件≤4KB，禁止外部执行 | 队列有界；无静默丢失；回压/拒收有明确计数 |
| 空载成本 | 没有变化的Source，24h对照 | 真实模型请求=0；新增常驻RSS建议≤100MiB，p95空载CPU≤1% |
| 资源清理 | 20次加载/卸载、100次可控派工、72h soak | 活跃handles/listener/子进程无持续净增；内存暖机后增长≤10% |
| 去重与保留 | 100k重复事件、裁剪后重放保留窗口内事件 | 无重复业务任务/副作用；磁盘/索引增长曲线公开 |
| UI 可见更新 | 已持久事实到活动页面可见 | p95≤现有轮询周期+1s；不为达标另建通用轮询 |

p50/p95/p99、峰值RSS、CPU、磁盘大小、SQLite锁等待、排队长度、Source请求数均报告原始样本量。CPU百分比以一个逻辑核计，使用的计算方法必须注明。外部 API 限流/网络/模型 latency 分开列。一次大批次快于目标不代表长期稳定；加速时钟和虚拟事件不等于真实72小时运行。

## 真实模型质量与公平比较

PB02 建冻结脱敏回放集；真实模型执行前仍须单独授权，当前这层结果为 `FAIL(NOT_AUTHORIZED)`。至少 200 条事件建议作为起始规模，按任务而非重复消息划分 train/tune/held-out，防止同 CI run 的重复或后续证据跨分区泄漏。标签包括需处理、只通知、继续观察、无关、重复、过期、冲突、回声、恶意内容；异常类不因数量少而被排除。

独立人工先标注目标动作、允许范围、可接受时限与证据；争议记录两位标注者及裁决。公开标注协议、类分布、分母、混淆矩阵和误例。建议阈值预先在 tune 集确定，冻结后不再为最终测试改规则；至少三批独立回放，报告置信区间，200条不能宣称统计显著性充分。

| 指标 | 定义与分层 | 初始目标（未测） |
| --- | --- | --- |
| precision | 被建议/自动执行候选中人工确认应处理的任务占比；建议与自动候选分别算 | 自动候选 ≥95% |
| recall | 应处理任务中在期限内发现的比例；严重漏报单列 | ≥90%；严重漏报逐项分析 |
| 建议接受率 | 有效、已被用户查看的建议中接受比例；未查看/过期/合并另列 | 先建立基线，不以接受率替代正确性 |
| 交付通过率 | 预先定义业务条件的任务中独立验收通过比例；失败/超时/unknown均留分母 | 不低于相同执行器被动基线 |
| 虚报完成 | 没通过对应条件却宣称通过的任务数 | 测试集内0 |
| 成本 | 研判/执行/外部服务费用分列；每个通过任务总费用，含失败重试 | 报绝对费用及分布，不先假定更便宜 |
| 注意力 | 每任务通知/提问/审批数、人工操作分钟；漏报损失单列 | 比每事件提醒降低人工时间30%，recall下降≤3个百分点 |
| 任务耗时 | 首个可用事件到发现、接受、交付、验收的分段时长 | 报p50/p95，不混淆人工等待与模型速度 |
| 反馈收益 | 相同held-out、无反馈版vs候选版；总权限集一致 | 误报降低，recall下降≤3个百分点，有效交付不下降 |

比较组必须冻结相同模型版本、系统/任务输入可用信息、工具与沙箱、预算、超时、source窗口、初始仓库/fixture；随机化运行顺序，重复批次，保留缓存命中/预热差异。基线为：①现有被动 DSH-Bot；②相同模型/工具的固定 DeepSeek 参考实现；③每事件提醒；消融为仅规则、规则+模型、加持续跟进、加反馈。另设“人直接给正确任务”参照，分离发现与执行增益。单 Bot/群分开计算费用、时延与通过率，不能让群多用预算后声称更强。

如果参考实现无法在相同权限/模型运行，标为非等条件观察，不输出胜率结论。商业产品仅能核对公开能力时不作性能优劣声明。来源质量、模型版本漂移和人工标注分歧都需要在结论中保留。

## 第一条闭环与独立业务验收

固定任务：CI failure→建议→用户接受→单 Bot 定位并修复隔离 fixture→运行指定构建/测试→证据索引→人工验收。通过后，同类任务再验证既有群承接。fixture 提前有已知根因和可测行为，执行者不能修改验收测试降低条件；源码、测试和交付物版本均记录 digest。

验收清单包括：来源/run是否准确；建议是否应该产生；接受范围是否明确；修改仅在授权工作树；失败测试是否被修复而回归不增；命令实际执行与退出码；产物是否对应本次代码；无评论/commit/push/merge；独立审核决定；返工后重新证据。合成模型只能证明链路，不证明实际定位修复能力。

第二条“迁移缺设备验收证据”必须分别展示 build、install/start、设备行为和业务验收状态；静态/截图分数不能填设备或业务 PASS。第三条日报任务才引入来源、去重和审稿评价，不能用生成了一篇文字替代交付质量。

## 72小时 soak 与版本发布门槛

PB09 先执行72小时真实进程+合成模型/工具/transport：每天固定普通流量、突发、空载、重复、乱序、撤权、核心重启、Host重启和冷恢复；所有注入由 manifest 记录时间/seed/barrier。进程级强杀必须等待确认退出再起新 PID。watchdog只恢复进程并触发对账，不自动重播未知副作用。

通过要求：零不可追溯任务；授权外新副作用为0；计数工具重复副作用为0；未知均可定位且不会自动重发；无超预算新派工；资源目标达标；所有未解决错误列清；无真实模型/外部写入。发现 P0/P1 恢复或授权缺陷，修复后相关矩阵和完整 soak 重跑，旧报告保留失败史。

真实试点包必须写明项目/模型/来源/动作/数据/费用/时长、停止条件、人工审核者。当前未获授权，不执行。模型费用或超出动作边界立即停新派工；unknown 或撤权后动作异常时冻结相关规则、保留证据。合成 soak PASS 不自动开启真实功能。
