# 个人 Bot 与群主动跟进：产品范围修正

本文件是后续实现建议，不代表这些入口和触发器已经交付。2026-11-09 根据本地验收反馈复核。具体实施范围、原生前置验证和逐条验收标准以 [0.6.6 落地方案](v0.6.6-personal-group-follow-up.md)为准，当前待审批。

## 当前实现与缺口

- 当前自动建议入口是 CI 事件：本地 CI feed 或 GitHub Actions 来源。文档任务提交、原生日程是另外的入口，不等于任意场景的主动发现。
- 群已有任务分工、受控续接和修复流程，但没有“以整个群为职责主体”的主动建议开启入口。执行既有任务不等于主动发现群内待办。
- 将这一 CI 纵向场景直接命名为通用“主动建议”，并把连接 GitHub 放到默认开启路径，会让用户误以为主动 Bot 只会监控代码仓库。这与原先个人 Agent / Bot Group 的目标不一致。
- 本次头像修复独立处理会话归属，不能作为上述缺口已经补齐的证据。

## 用户最终看到什么

沿用个人 Bot 和群的详情页，各提供一个“主动跟进”入口。默认关闭；开启默认“只建议”。显示当前关注事项、待处理建议、正在执行和待验收结果。高级来源和预算折叠进入现有设置，不新增仪表盘、工作流编辑器或另一套任务中心。

个人 Bot 示例：“任务失败了，要我继续排查吗？”“昨天约定的事项到时间了。”群示例：“实现已完成，是否交给评审成员？”“任务仍在等你的补充信息。”每条建议说明触发原因、对应会话/任务和下一步动作，可以接受、忽略或暂停该项关注。

GitHub 是可选外部来源；不连接仓库也应该能够使用基于本地任务状态和明确日程的主动跟进。语义理解需要模型时必须纳入现有模型选择与预算；不能继续笼统承诺“主动建议完全不调用模型”。刷新已有建议仍可保持只读、不调用模型。

## 复用范围和最小实现

| 能力 | 优先复用 | 本项目需要补的部分 |
| --- | --- | --- |
| 任务完成、失败、待补充信息 | 原生 session/event、现有任务状态与 Task/Assignment | 将明确状态变化投影为建议，去重、冷却、过期处理 |
| 明确日期或周期的关注事项 | DSH 原生 schedule 与现有自动化桥接 | 将提醒关联到同一 Bot/群和原任务；不自建计时器系统 |
| 群内协作 | 已有 Groups Host 协调服务、成员快照、turn runner 和分工协议 | 群级职责归属、统一开关及建议汇总；成员不各自重复发言 |
| 执行与审批 | 现有执行入口、原生权限/审批、预算和任务验收 | 接受建议后复用原任务或创建一次任务；防重复提交 |
| 通知与展示 | 现有消息、通知和详情页 | 无需处理的事件不打扰；重要建议聚合展示 |
| 外部来源 | 当前 CI feed/GitHub 适配器 | 从主开启路径移到可选来源，不做全功能连接器平台 |

最小新增对象是“建议的归属与触发事实”，不是新的 Agent runtime、消息总线或执行账本。建议必须绑定准确 Bot/群代际，关联原任务/会话和事件游标；已有字段可表达时直接复用。群成员变更、职责暂停、原任务完成后，过时建议应失效。

## 建议的落地顺序

1. 修复会话身份与头像回归，覆盖原生配置重载、主会话切换和历史会话；保留原生状态点和日程标记的优先级。
2. 补个人与群一致的开启/暂停入口，先支持任务完成、失败、待补充信息三类确定性事件；不要求外部账号，不默认启动模型或自动发消息。
3. 接上原生 schedule 的明确关注事项；建议接受后进入既有任务和群分工链路，保证仅提交一次。
4. 最后补基于聊天语义的机会发现，明确开启、模型预算和打扰频率；CI 等外部来源作为可选增强。

## 验收标准

- 无 GitHub 凭据的个人 Bot、群均能开启只建议模式，并产生有来源的本地任务建议。
- 同一事件重复投递、刷新、重启不会生成多个建议或重复任务；群由现有 Host 协调服务汇总一次，不假设存在固定主管 Bot。
- 忽略、暂停、任务结束、成员变更能够使相关建议停止或失效；不存在每个成员轮流提醒。
- 默认开启不自动执行、不自动对外发送消息；接受建议和开启自动执行分别沿用现有授权边界。
- 开启、暂停和修改来源不丢失 Bot 头像、主会话归属和历史记录；不能将暂时不可用显示成 Bot 已删除。
- 测试分别报告确定性机制、真实原生运行和模型效果。通过 CI 纵向场景不再报告为通用主动 Agent 已全部完成。
