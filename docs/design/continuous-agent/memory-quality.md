# 持续工作与记忆质量评估方案

状态：用户已批准，实施与验证见报告。基线：2026-11-16，`3b1c32c2a7c9fb1f4959bdc80f68c0c0c92a23a0`。
本文件只定义实验与交付门槛，不授权真实模型调用、日常资料读取或通知外发。
范围和实施顺序见[方案总览](README.md)及[任务计划](../../../tasks/continuous-agent/README.md)。
对应总计划 P1 交付评测机制，P2 接入整理臂，P5 才执行另获授权的真实试点。

## 1. 要回答的问题

首要问题是：同样可访问原始记录时，记忆是否提高未来任务的完成质量，整理是否值得其成本。
次要问题是：主动建议是否更准确、更及时，并减少重复解释和无用提醒。
检索命中、模型回答、工作交付、用户收益分层报告；任一层通过不能替代下一层。
本轮目标是建立可复现的小规模试点，不声称统计显著、普遍有效或自动学习已经可靠。

## 3. 数据集与时间隔离

首批 24 个独立场景：8 开发、8 验证、8 最终留出；每组各覆盖下列八类一次。
另备 24 个独立机制夹具，只用于 P1 接线、计分与故障验证，不与最终留出共享事件家族或事实答案。

1. 长期偏好与一次性要求的区分。
2. 显式事实修正、历史事实与当前事实的区分。
3. 跨会话任务承诺和未完成事项。
4. 群经历转入本人单聊时的来源与访问权限。
5. 来源撤销、遗忘及无法恢复的内容。
6. 无依据推断、矛盾证据与正确拒答。
7. 值得主动跟进的新证据及通知时机。
8. 无须行动、重复事件和无用提醒。

每场景包含带时间戳的事件序列、任务截止时间、权限快照、允许来源及冻结标签。
只向运行器开放任务截止时间之前的记录；整理也只能处理相同时间窗口。
同一真实事件、同一用户时间线及其改写、翻译、同义变体整体进入同一 split。
开发、验证、最终不得共享可识别的事实答案；通用场景类型可以一致。
有真实时间线时按时间向前切分，并保持事件家族不跨组；合成语料也遵循同样约束。
首先用明确标注的合成材料；真实资料必须经用户指定范围、脱敏与批准后另建数据版本。
不自动扫描日常 `~/.dsh`、桌面数据或私人历史来填满题数。
每个场景预先标注必需事实、禁止引用内容、允许动作、成功条件、正确无行动条件。
事实标签引用原始记录 ID 和时间段，不依赖某个整理实现的内部 memory ID。

开发集可迭代；验证集用于选择一次候选，读取结果后不得继续称为未见数据。
候选、提示、工具、参数、语料和评分规则冻结后，最终集只允许一次登记的评估批次。
最终批次预先包含每题 3 次重复；重复是独立运行记录，不是 3 个独立场景。
P1 仅校验最终集的 manifest/schema/hash；最终事实、Gold、断言和内容日志不能进入实现者的调试视野。
需要提前检查最终数据完整性时，由隔离评分侧只返回无正文的结构检查结果，不调用候选模型或输出题目。
最终失败后要修改候选，应建新实验与新最终集；保留旧失败，不覆盖收据。
Gold 文件由评分侧持有，禁止出现在 worker prompt、搜索索引、整理输入、日志回流或工具结果中。
机制测试加入 gold canary；任何泄漏使整个实验无效，先修机制再重新冻结。

## 4. 公平三臂对照

| 臂 | 可见资料 | 回答时的能力 |
| --- | --- | --- |
| A：原始搜索 | 截止时间前的授权原始记录 | 只有相同原始搜索，无持久记忆注入 |
| B：现有记忆＋搜索 | 同一原始记录与当前实现生成的记忆 | 现有记忆检索/注入，加同一原始搜索 |
| C：整理记忆＋搜索 | 同一原始记录、由 B 快照派生的整理版本 | 整理后记忆检索/注入，加同一原始搜索 |

B 必须从冻结事件流按当前写入规则生成，不能手工替它补答案；已有人工编辑在生成前冻结并留来源。
C 不得取得 B 不可访问的原始事实；首版整理只生成 proposed 候选，人工采用后才对回答生效。
A 禁止隐式继承 Bot 记忆、旧会话或其他臂输出；三臂各用独立会话和存储副本。
C 在独立影子副本内经隔离 owner 操作采用，复用产品 revision/权限/来源检查，不写回日常数据。
先冻结非 Gold 审阅规则：来源可核对、事实等价、时间准确、无权限提升、无已撤销信息及新推断。
审阅人只能看截止时间前的授权来源、B 快照与候选差异；隐藏未来任务、Gold、模型身份和回答结果。
候选按预登记顺序仅批准或拒绝，不允许补写、选最好答案、反复生成至满意或为最终题定制整理。
批准产生准确的采用回执；拒绝保留 B 快照继续 C 的完整产品流程，并记录拒绝原因与全部成本。
正常拒绝不是执行失败；整理执行失败/unknown 则按冻结失败规则登记，不冒充正常拒绝或成功采用。
最终回答开始前冻结 C 实际生效快照，三次重复共用该快照，不按第一次答案重新审阅。
审阅时间、批准/拒绝数与人工操作成本单列；评分人员不能兼任该场景的候选审阅人。
C 对 B 的主比较测量“整理＋人工采用”的完整流程，不能把人工筛选收益归为整理模型的纯自动因果收益。
现有人工编辑不能等量控制或审阅无法盲化时，明确报告观察性差异，不作整理模型因果结论。
要研究纯自动整理需另行预登记无人工筛选的影子消融，不改变首版必须人工采用的产品规则。
机制 fixture 可以统一采用满足冻结合法性条件的候选；此结果只证明采用链路，不作为质量收益。
相同 provider、模型版本、推理参数、基础提示、工具权限、任务时限和回答阶段预算。
原始搜索的索引、返回上限和每次调用行为相同；不把 A 的搜索上限压低以制造收益。
三臂相同上下文总上限；记忆注入消耗 B/C 的上下文预算，统一记录截断与拒绝原因。
按预登记种子打乱执行次序；有缓存时记录冷热情况，不能只给候选预热。
记录 baseContextHash、各臂 memoryHash、searchCorpusHash 和最终 requestHash；不要求三臂正文哈希相同。
首轮不使用额外模型裁判；结构化事实自动核对，任务质量由隐藏臂标识的人工评分核验。
对有争议的判定记录理由和复核结果，不能在看到哪一臂胜出后改变 rubric。

按模型分别报告；首批可只选用户指定的一个模型，第二个模型作为独立实验。
禁止把不同模型、不同 provider、不同参数的成功率直接合并为“记忆收益”。
模型版本不可锁定时记录服务版本/时间；发生切换则拆分批次，不强行补齐配对结论。

## 5. 计分与固定分母

每个 `场景 × 臂 × 模型 × 重复序号` 在调用前登记唯一 ID。
失败、超时、取消、unknown、预算拒绝和未启动都保留在预登记分母，并分别计数。
任务成功率仅以有完整证据且满足全部必需条件的记录作分子；unknown 不能计成功。
批次未完整执行时标 inconclusive，同时公布保守成功率，不删除未启动项后宣称完成。
运行重复独立计分并报告逐场景 0/3–3/3 成功分布；不挑最好一次，不把重复数当样本独立性。
安全事件按全部记录报告，包括失败输出中的泄漏和禁止动作。

| 层次 | 指标与定义 | 用途 |
| --- | --- | --- |
| 检索 | Recall@5、MRR、正确有效时间、授权来源命中 | 解释回答失败原因，不充当主成功指标 |
| 回答 | 必需事实覆盖、无依据断言数、陈旧事实使用数 | 对照原始证据逐项核验 |
| 任务 | 完成率、正确无行动率、返工数、禁止动作数 | 主要发布判断依据 |
| 效率 | 总输入/输出/缓存 token、墙钟时间、人工纠正次数 | 同任务配对，unknown 单列 |
| 稳定性 | 各场景重复成功分布、超时/unknown 数 | 识别偶然命中和不可靠交付 |

事实数为零的题不伪造 Recall=1，记 N/A；检索指标给出适用题数量和失败数量。
运行失败且本应检索的题计零；用户撤销等正确无结果由独立的任务/安全条件评分。
若未完整取得 provider 用量，成本标未知，不用文本长度估算冒充真实计费用量。

## 6. 分层验收门槛

以下数值是待批准的试点停止/继续规则，不是显著性检验，也不是通用产品承诺。

### 6.1 无真实模型的机制交付

- 独立的 24 个机制夹具三臂都能生成隔离运行记录，三臂可用语料与授权窗口一致性检查 100% 通过；最终留出内容不参与该调试。
- 植入的 gold 泄漏、跨臂污染、未来信息、权限越界四类反例各至少 2 条，全部被检测并判失败。
- 失败、超时、unknown、预算不足、重复回执各至少 2 条，分母和去重结果 100% 符合冻结预期。
- 确定性 fixture 的分数、成本与摊销计算和手工期望完全一致；不能要求所有任务分数满分。
- 至少一轮实际隔离 Host 验证公开会话、存储与加载证据；mock 单测不能替代 Host 验收。
- 真实模型、真实通知、真实业务收益在本层统一记录 FAIL（NOT_RUN），不阻断机制交付。

### 6.2 真实模型试点，另行授权后执行

开发 8 题与验证 8 题各每臂 1 次，最终 8 题每臂 3 次：每模型共 120 个回答运行。
最终每臂分母 24。B 对 A 是现状诊断，负结果必须保留，不要求现状先证明有效才允许优化 C。
C 对 B 是本次改动的放行判断，同时要求 C 总成功次数不低于 A，且没有场景从 A 的 3/3 退化为 C 的 0/3。
推荐 C 须零权限/遗忘泄漏、零禁止动作，最终全部三臂收据完整且 unknown=0；基线泄漏单列为当前产品缺陷，不用候选收益掩盖。
C 至少完成 18/24，并满足下列预登记路径之一；两条路径均报告，不事后选择新指标。

- 质量路径：比 B 至少多成功 3/24，且没有任何场景从 B 的 3/3 退化到 C 的 0/3。
- 效率路径：逐场景成功次数均不低于 B，按 N=1 口径的总计费成本至少降低 15%，且人工纠正次数与可核验人工总耗时均不增加。

若总计费成本不可核实，效率路径不成立；质量路径可报告任务收益，但成本结论标未测。
最多 8 个最终场景，即使过线也只能进入小范围试用；不能推算总体可靠率或宣传普遍改善。
未过线保留现有行为，继续分析失败；不自动采纳整理策略，不扩大默认后台运行范围。

## 7. 整理成本与预算

分别记原始索引、B 记忆生成、C 整理、候选人工审阅/采用、回答/检索、失败重试、人工复核成本。
共同基础成本单列；增量比较中保留各臂独有成本，不能把 B/C 预处理当免费。
每批报告总成本及每成功任务成本；成功数为零时后者为 N/A，不报告零成本。
单次整理成本为 S，实际服务的后续任务数为 N，则每任务摊销为 S/N 加该任务在线成本。
只按实际发生的 N 摊销；另列 N=1、5、20 的假设曲线，不能把假设使用量当已实现收益。
实验重复可以共享冻结整理产物，但必须另报生产一次任务承担完整整理成本的 N=1 结果。
首批效率放行固定使用 N=1：每个配对回答承担其 B 初始化及 C 整理的完整独有成本；另报实验实际现金支出。
同题三次重复不能作为三个生产后续任务用于摊销。未来使用 N>1 门槛必须事前冻结独立后续任务及实际使用证据。
整理失败、取消与未知仍计入成本；不能通过多跑几次、只选成功一次来降低报告成本。
逐模型登记最多 120 个回答运行和最多 24 个 C 整理运行；B 初始化另列上限。
通知影子试点最多 24 个额外判断运行，单独批准并纳入同一总预算；不暗占回答试验额度。
回答运行不等于模型请求：工具循环、初始化、整理及重试全部纳入请求和 token 总预算。
真实试点前必须填写 provider/model、单运行请求上限、输入输出上限、总请求与货币硬上限。
预算表未完整批准则只能运行 fixture；不得继承日常默认额度或为凑齐实验自动提高限额。
沿用现有预留/结算语义，未知用量不退款；预算耗尽停止并记录未完成分母，不自动续跑。
真实模型执行受根 [AGENTS.md](../../../AGENTS.md) 第 9 行禁止条款约束。
需要用户后续明确授权本隔离试点及具体预算；批准设计或实现不等于授权真实 API 会话。

## 8. 通知收益与打扰测量

先做冻结事件流影子回放，只有候选记录，不外发、不写日常记忆。
独立准备 24 个事件机会：12 个应通知、12 个应静默，含重复、过期、撤销与新事实。
通知 gold 规定可接受目标、内容要点与时间窗；晚到、错误目标或重复通知均不算有效命中。
报告 TP/FP/FN、精确率、召回率、重复数、超时数及每用户日候选数；零分母为 N/A。
同一事实首次有效通知计一次 TP，后续重复计 FP，并在重复列单列而不重复累加 FP。
未判断/unknown 的正例计 FN，负例也留在全部机会分母；缺失判断率单列，不能隐身。
机制层只要求冻结期望 100% 对齐，不用手写 fixture 的高精确率证明产品有效。
真实模型影子试点门槛建议：TP≥10/12、FP≤1、重复=0、撤销后通知=0、unknown=0。
它只支持“值得试用”，不能证明用户觉得少打扰；真实外发须另获明确授权。
后续用户试点记录每条通知是否有用、是否需要行动、是否打扰、实际节省时间与纠正次数。
漏报需回看全部事件机会，不能只向收到通知的人统计满意度；未反馈记 missing。
按用户和日期分别报告通知数、主动采纳与静音/关闭原因；不把点击率或沉默等同于满意。
真实试点规模、持续时间和打扰容忍度留待用户结合日常工作批准，不作为本轮机制交付条件。

## 9. 交付与未决项

拟交付：冻结 manifest、场景/Gold 分离、三臂适配层、评分器、预算账本适配、逐题收据和报告模板。
