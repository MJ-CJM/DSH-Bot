# 定时唤醒与任务恢复设计

状态：**待审批／未实施**。日期：2026-11-16。
核查基线：`3b1c32c2a7c9fb1f4959bdc80f68c0c0c92a23a0`，0.7.0 发布准备之后。
本文仅提出设计、能力门槛与验收方案，不授权开发、部署或真实模型运行。
实施阶段由[总览](README.md)及配套任务计划统筹；本文件不替代运行证据。

## 1. 产品目标与边界

用户约定关注事项后，系统在有新事实时短暂处理；等待期间不维持模型循环。
恢复时回到准确的原工作和原对话，说明现在发生了什么、还有什么需要本人处理。
首批时间触发仅覆盖已明确登记的提醒／关注核对，不自动补跑工程修改或外部发送。
时间到达是事件事实，不构成新权限，不应为了检查时间额外请求模型。
原生 Host 关闭或机器休眠时不运行；恢复后的行为必须按明确补偿策略验收。
不承诺无人值守的系统守护进程、任意跨版本兼容、外部操作 exactly-once。

## 3. 原生能力门槛：先 spike 后选择实现

只读参考仍锁 `deepseek-harness@dsh-v0.2.1-rc.2`，日常兼容版本另在隔离 Host 验证。
公开 `Agent.followup`、`runMaintenance` 见参考 `packages/core/agent/src/runtime-types.ts:185–222`。
`followup` 返回只证明准入／排队边界，不能当作模型完成或业务交付确认。
`schedule/changed` 为变更通知，不假定它是到期通知；不从内部 scheduler 导入。

| 门槛 | 必须取到的证据 | 未通过时 |
| --- | --- | --- |
| G1 到期身份 | 公开入口可将具体 occurrence 与原登记、规则代际、原 Session 精确关联；重复输入同身份 | 不开放自动时间来源 |
| G2 零模型消费 | 纯关注到期不唤醒模型；混批中正常用户输入和原生管理消息不丢失、不变来源 | 不安装生产输入过滤器 |
| G3 冷恢复 | Host 停机跨到期，重启原生就绪后无需新建另一日程即可核对事实；历史不全可明确报告 | 不宣传 durable 时间跟进 |
| G4 原子业务准入 | 并发、重复、重启下同 occurrence 同规则代际至多一个业务准入收据 | 保持能力关闭，不用内存锁代替 |
| G5 原生延期工具 | 公开持久 pending-call、暂停／释放、答复关联、恢复、拒绝／取消语义实际可用 | 仅做工作级等待与显式续办 |
| G6 就绪与生命周期 | 原生服务晚到、重载、关闭、旧响应迟到不重复注册、不越代际派工 | 停用桥并显示明确不可用原因 |

G1 的 occurrenceKey 是**本插件拟定的逻辑键**，不是宣称 DSH 存在同名接口。
允许由已验证的公开不可变事实组合得到；若 history、输入、规则版本不足以唯一确定，判 unavailable/unknown。
不得仅 hash 正文、用到达时间、标题、`source.kind=schedule` 猜 occurrence。
所有门槛以安装后的同包真实 Host、合成模型计数及持久收据为证；静态签名不算 PASS。
G1–G4 全通过才进入完整时间路径；G5 独立决定是否支持真正延期工具，不绑架已有能力交付。

## 4. 事件与持久化边界

原生 schedule 管理时间规则，原生 Session/Inbox 管理对话；原 coordinator 管理业务准入和收据。
FollowUp 保存关注状态，原 Work 保存执行事实；不再复制第二份任务正文／任务状态权威。
拟在现有 coordinator schema 中增加最小时间准入记录，不新建独立数据库或后台调度进程。
记录关联原 owner、Bot/群代际、原会话及创建身份、登记批准、schedule ID 和规则代际。
还需来源版本、occurrenceKey、原定时间、实际观察时间、有效期、状态、原 Work 引用及操作收据。
签名／摘要仅作完整性和幂等校验；不能把摘要当授权，更不能永久保存被遗忘正文。
原生 history、当前规则及本地记录冲突时停止自动准入，保留可核对原因。
输入事件至少区分时间事实、条件事实、真实所有者答复、原生审批决定与取消／撤权。
后台事件保留 machine/native provenance；禁止改写为 user 来绕过原生审批。
只有经过 owner Remote 验证的实际用户操作才能形成对应人工事件和批准引用。
源事实、去重占位、准入决定与待处理意图在 coordinator 一个短事务内提交。
调用原生 Agent 或通知服务发生在事务外，之前先持久化派发意图，之后记录准确回执。

## 5. 短 run 与状态转换

以下为业务协议状态，实施时映射到原 Work/FollowUp/receipt，不机械新建完整状态机副本。

| 阶段 | 允许行为 | 离开条件 |
| --- | --- | --- |
| observing | 无模型观察、合并事实、核对当前登记 | 新有效事实进入 ready；撤销转 closed |
| ready | 原身份／来源／权限重核，事务取得唯一准入收据 | 权限足够才提交 dispatch-intent，否则 waiting |
| dispatch-intent | 原生派发一次，记录稳定 operationId 与目标 | 确认排队转 queued；传输不确定转 unknown |
| queued/running | 原生执行器拥有 run，现有预算／取消生效 | 明确结果、等待、失败、取消分别落原工作 |
| waiting-input | 保存缺少的具体输入及引用，结束本次业务处理 | 精确所有者答复成为新事件；无答复不循环 |
| waiting-approval | 保存准确待批范围和原生关联，未批不执行 | 原生批准／拒绝／取消；G5 不通过不暂停工具冒充 |
| ready-to-resume | 原操作／答复／批准和当前版本再次核对 | 原生支持的续办；不满足则保留 waiting/unknown |
| delivered | 结果已落原工作，可产生一次通知意图 | 人工接受、继续修改或关闭；沉默不算接受 |
| unknown | 只读核对原生收据和原工作，不自动重发 | 准确证据解疑；否则等待人工核对 |
| closed | 已取消、已过期或已完成的准确终态 | 原 ID 不复活；新登记需要新明确授权 |

“短”指处理完当前有界事件后释放资源，不指硬截断任意原生模型请求。
模型／工具运行时限、token、并发与取消沿现有工作预算，禁止另设无限续跑。
协调器不能持串行锁等待模型、Agent idle、审批或用户输入；它只提交状态／接纳结果。
工作等待不占协调执行名额；原生运行句柄是否可释放、主会话是否可继续由 G5 实测决定。
持久等待计划至少保存缺少的输入、原工作／会话引用、批准引用、恢复前置条件、有效期和版本。
冷启动只重建这份计划与原生审批可见状态；实际续办仍需真实答复和重新准入。
若原生 pending approval 占用当前 Agent，就明确显示当前原生等待，不声称该 Agent 已休眠释放。
对只需用户补材料的任务，优先正常结束该轮并保存 waiting，再由真实用户动作发起后续轮。

## 6. 原对话后续消息与权限

恢复绑定 workId、originSessionId、Session 创建身份、Bot/群代际、原人类输入及待回复对象。
用户在原对话发新消息时先遵从原生 Inbox：不清空、不抢走、不自动当作批准。
明确回复准确待办且只有一个匹配对象时，调用现有续办路径；多个合理对象才最少澄清。
无关新任务正常处理，旧 waiting 保留；不能用“最新一句话”覆盖旧授权范围。
当前 `resumeWork` 要求原会话 idle、准确最新用户输入等；扩展前必须为每个放宽条件单独验收。
原会话归档、主绑定替换、Bot 删后重建时拒绝旧事件自动运行；只读提供失效原因。
若允许迁移工作到新对话，应另行设计显式迁移授权，当前方案不包含隐式迁移。
准入与实际 dispatch 前都重核资料读者、工具／外发范围、owner、策略版本、有效期与预算。
连接 ready 只是依赖满足；不得自动等同用户答复或批准，继续复用明确继续操作。
旧批准和新的背景事实不能组合成更大权限；扩大范围走原生增量审批。
资料删改／遗忘使原引用失效时停止恢复，不从快照或记忆重新拼出已撤回资料。
真正 deferred tool call 只有 G5 通过才接通：原生 call identity 必须跨重启可核验。
原生批准改变、参数变化或目标变化时旧 call 不可恢复；新批准交给原生机制。
没有原生支持时交付 waiting 工作卡＋原对话显式续办，不缓存工具参数后自行补执行。

## 7. 错过日程、时区与时钟

建议默认：仅对仍有效的提醒合并告知，不逐条补模型执行；过期事项标过期，不补执行。
合并只在相同 owner、准确登记代际、读者范围及通知目标内进行，保留各原 occurrence 引用。
“有三次提醒错过”须有三个准确原生事实；无法枚举时只显示恢复待核对，不编造次数。
若原生在插件接管前必然唤醒模型／执行副作用，则该策略无法兑现，G2/G3 判失败。
历史不全、恢复超过扫描预算、旧 rule revision 无法核对时停止该范围自动处理。
补偿回看窗口建议默认 24 小时，范围 1 小时–7 天；只限制读取，不产生新的定时事实。
到期与有效期比较使用 UTC instant；重复规则的墙钟解释、IANA zone 和 DST 语义归原生 schedule。
展示本地时间、时区及下一次原生计划时间；模糊时间由用户确认，不擅自选时区。
DST 重复小时的两个原生 occurrence 是否为一次或两次，由原生已验证规则语义决定。
DST 缺失小时不私自前移／后移补跑；若公开 API 无法说明行为，相关重复规则先不开放。
系统时间前跳不批量补执行，后跳不重新准入已有 occurrence；进程内超时用单调计时。
跨重启不依赖单调时间戳；大幅时间变化触发原生事实重核，未知保持停用／待核对。

## 8. 并发、崩溃与保证

复用现有 coordinator 单写者及所有权保护；多个 Host 不得同时写同一业务库。
来源回调可并发入站，但业务准入按原生 occurrence＋登记代际的唯一键事务串行决定。
不同 Bot/工作可沿现有执行预算并发；同一工作续办必须 CAS revision，不能全系统等待一个用户。
合并队列只持引用，超限标 dirty 并受限补扫；来源不能回放时明确报告缺口，不静默丢事件。
原生 Session flush 和 SQLite 提交没有假定的跨库事务，必须逐窗口记录不确定性。

| 崩溃窗口 | 重启行为 | 可宣称保证 |
| --- | --- | --- |
| 原生事实出现、业务事务前 | 原生公开事实可回放才再观察；不可核实时 unknown | 不假定零丢失 |
| 准入提交、派发前 | 根据确定未派发证据执行原意图；缺证明保持 unknown | 同 occurrence 至多一次业务准入 |
| 派发调用中／原生排队后、收据前 | 用准确原生输入／执行引用核对；不换 operationId 重试 | 不确定执行不重复启动 |
| 模型结束、业务结果前 | 读准确原执行结果；不把 idle 当成功 | 可核对结果才更新工作 |
| 通知 claim 后、record 收据前 | 沿既有 unknown，查询准确 ledger；无证明不重发 | 不承诺外部 exactly-once |
| 用户答复后、恢复回执前 | 复用答复 ID／call ID／resume operationId 核对 | 同答复不得创建第二次恢复 |
| 取消与派发竞争 | 同工作版本决定胜者；取消后阻止新准入并等待清理证明 | 已发生的外部效果不可伪称撤销 |

定时 at-most-one 仅指业务准入收据；它不等于每个事件一定完成，也不等于外部副作用仅一次。
外部发送／执行若无可查询幂等合同，超时永远保留 unknown；当前首批不新增这类动作。
业务重复防护的 tombstone 保留必须覆盖可回放窗口；清理后旧来源不得重新复活。

## 9. 配置与关闭

以下是拟定配置，实施纳入现有 Config/Schemastery 和中英 locale，不作为当前接口引用。

| 配置 | 建议默认／校验 | 作用 |
| --- | --- | --- |
| 时间关注开关 | false；能力门槛未过不能开启 | 不改变现有原生日程 |
| 原生延期工具开关 | false；G5 不通过不显示可用入口 | 不创建第二审批系统 |
| 错过提醒策略 | merge-valid；仅 merge-valid/expire | 不允许补执行工程任务 |
| 恢复回看窗口 | 24h；1h–7d | 受限查原生事实 |
| 单批核对上限 | 16；1–64 | 沿现有维护循环，保证公平性 |
| 待核对引用上限 | 512；16–4096 | 超限保留 dirty 和可见积压 |

静默、每日额度、通知合并窗口、模型预算复用既有配置，不新增同义参数。
关闭阻断新时间准入并注销桥；既有工作按原取消语义处理，历史与未知收据保留。
配置热更增加 epoch；已结束 fiber 的迟到响应不能改变新 epoch 状态。
所有订阅、队列、取消与 disposer 归属 `ctx.effect`；不开额外常驻模型、系统 launch agent 或全局服务。

## 10. 完整验收矩阵（本方案全部未执行）

先固定 runtime、源码与包 hash；每个场景记录原生身份、业务收据、实际请求数和恢复结果。
隔离真实 Host 使用合成模型；正式验证还需同包 Browser／中英／亮暗和生命周期检查。

| 编号 | 正例／反例及故障注入 | 必须观察到的结果 |
| --- | --- | --- |
| W01 | 正常到期；尚未到期 | 到期有一条准确事实；提前零业务准入，观察零模型 |
| W02 | 同 occurrence 重复／乱序 100 次、并发回调 | 一个准入收据；不同摘要冲突，不新增执行 |
| W03 | 同时间两个独立日程；删除重建同名日程 | 独立身份不误合；旧代际不绑定新登记 |
| W04 | 提醒＋真实用户消息＋SCHEDULE CHANGE 混批 | 用户消息完整、来源不变；管理消息不作到期授权 |
| W05 | 停机跨到期后自然重启；原生服务延迟 ready | 无新日程刺激也能核对，未 ready 不错误确认 |
| W06 | 多条错过提醒仍有效／已过期／history 缺页 | 合并且保留引用／标过期／待核对；均不补模型执行 |
| W07 | UTC、跨时区、DST 缺失和重复小时 | 与公开原生规则一致；不能证明的组合明确不支持 |
| W08 | 时钟前跳／后跳／进程恢复 | 旧 occurrence 不重入，超时不失控，不编造历史 |
| W09 | 业务提交前／后 SIGKILL；派发前／中 SIGKILL | 按第 8 节窗口恢复；unknown 不换 ID 重放 |
| W10 | 原生排队成功但 flush 或业务回执失败 | 不把排队当完成，不产生第二次原生输入 |
| W11 | 等待资料时另一 Bot 有事件 | 协调 worker 可继续；原任务无模型轮询 |
| W12 | 原对话准确回复／无关消息／两个待办歧义 | 只续准确工作；保留其他消息；歧义最少澄清 |
| W13 | 主会话替换、归档、Bot 删后重建、群成员变更 | 旧身份拒绝，已获准读者不被隐式扩大 |
| W14 | 批准后撤权／参数变化／资料遗忘／到期 | 实际派发前拒绝；旧批准不可复用 |
| W15 | 后台文本伪装用户批准、未知 source、过期 answer | 不生成合法人工授权；准确审计拒绝原因 |
| W16 | G5：等待审批、重启、批准／拒绝／取消／重复答复 | 仅原生准确 call 恢复一次；等待释放能力有实际证明 |
| W17 | G5 不支持或原生 pending 占用 Agent | 显示原生等待或工作卡；没有自建工具补执行 |
| W18 | 通知静默／合并／日限额／claim 后强杀 | 沿原 notice 策略；unknown 不盲发，零通知模型 |
| W19 | 两 Host 抢同库；队列超限；持续实时事件 | 单写者有效；积压可见且后台补扫不饿死 |
| W20 | 热关闭／重开、卸载、旧异步回包迟到 | 无残留订阅／跨 epoch 写入，新准入停止 |

| W22 | 旧数据升级、关闭功能下原聊天／条件跟进／通知 | 原数据与行为保持；新表迁移不激活旧任务 |

## 11. 分条件交付与退出

阶段与总览统一：P0 验证原生日程及延期工具能力，P3 交付任务等待／恢复，P4 才接时间来源。
P1 质量评测基线与 P2 手动离线整理另见总览；本文件不另设重复的阶段编号。
P0 只交付能力 spike 和故障收据；保留失败原始证据，不以写完桥接代码代替通过。
P3 至少交付持久等待计划、原生已有审批状态核对及受支持的恢复；不存在的原生能力不模拟补齐。
G1–G4、G6 通过：交付默认关闭的时间关注，范围只含受支持规则、有效提醒合并和原工作核对。
G5 通过：另行接通原生延期工具；业务等待与原生等待状态分开展示，完整跑 W11–W17。
G5 不通过：交付工作级 waiting、原待办查看、原对话显式续办；明确“不支持跨重启延期工具恢复”。
G1–G4 任一不通过：时间自动来源保持关闭；交付已有条件跟进的恢复加固、可见失败原因和手动核对。
手动核对只读取现有权威事实，不生成伪到期记录，不补执行、不替用户登记另一个日程。
不能以局部降级版本宣称完整 durable timers；报告分别列实现、运行、能力阻塞及延期范围。
G5 不支持时通用 deferred 能力记 FAIL（CAPABILITY），不能标全 scope PASS；受限交付单列验收。
P4 依赖 P0 与 P3；P5 再做组合验收及另行授权的有界真实试点，合成模型结果不能替代业务效果。
本次审批应确认的是上述阶段与收窄边界；进入开发后不越过原生能力门槛扩大承诺。
