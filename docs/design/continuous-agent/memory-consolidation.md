# 离线记忆整理：候选、来源与受控采用

> 状态：用户已批准，未实施。2026-11-16；源码基线 `3b1c32c2a7c9fb1f4959bdc80f68c0c0c92a23a0`。
> 本文属于[持续 Agent 优化方案](README.md)。批准本设计不代表已授权真实模型调用、部署或发布。
> 首版默认关闭、手动触发，一次只整理一个 Bot、产生一份候选；不依赖定时器。

## 1. 目标与现有能力

把已经完成的工作转成少量可复用经验，并允许用户核对原文后采用。
优先提炼用户纠正、失败原因、适用条件、验证过的操作方法；容易重新查证的动态事实保留指针。
不以“笔记更多”“摘要更长”作为收益，不预先建设向量库、知识图谱或 wiki。

| 现有能力 | 本次复用位置 | 不应推断的能力 |
| --- | --- | --- |
| V2 版本、op 日志、CAS、epoch、owner lease | 候选版本与采用提交 | 原生日志引用已具备完整证据语义 |
| 私有/共享、trust、status、有效期 | 首版私有 proposed → active | 用户采用等于外部事实真实 |
| BM25、冲突裁决 | 候选去重提示、检索旧经验 | 自动解决语义矛盾 |
| 动态 `systemPrompt.context` | 采用后沿用预算注入 | T06 旧静态快照仍是现状 |
| 群经历召回及来源校验 | 本人已参与工作的有限原文 | 全群、全部历史可读 |
| changes / restore | 采用后历史及纠错入口 | 当前 facade 可原样承载新来源与幂等 |
| 遗忘预览、屏障、库存核验 | 候选、派生内容与执行副本清理 | 新表自动进入现有清理范围 |
| 原生 Agent / subagent 与现有预算接入 | 受控离线推理 | 已有后台 dreaming |

## 2. 首版产品流程

1. 用户在当前 Bot 的记忆页手动选择“整理一次”，范围限定为明确选定的已完成工作/会话片段。
2. Host 展示来源范围、已有相近记忆、输入规模和预算；不扫描整个用户历史。
3. Host 固定输入快照，启动一个受控原生执行，输出一份结构化候选或“没有值得保留的经验”。
4. 现有记忆页展示候选正文、用途、适用条件、来源片段、证据等级和与旧记忆的差异。
5. 用户可编辑、拒绝或采用；编辑后重新执行结构、来源和权限检查。
6. 采用前重读来源、核对目标与 revision/epoch，以一个 CAS 提交落库；冲突返回比较界面。
7. 候选未采用不进入模型检索或系统上下文；已采用沿用现有 changes / restore 查看与纠错。

“审阅采用”仅约束本功能产生的记忆候选，不改变其他功能已有授权方式。
首版只新增一条私有经验或修订一条已有私有经验，不批量删除、自动置顶、共享或修改人设。
拒绝/过期候选撤销正文可读性并按保留策略擦除；可保留不含正文的状态收据用于幂等。
建议候选最多保留 7 天；该值进入导出 Config/schema，过期必须在读取/采用时检查，不依赖定时清理运行。
首版每个 Bot 最多一个未结束任务，全 Host 并发最多一个；重复点击返回同一任务状态。

## 3. 受控输入与证据等级

Host 根据 BotKey、userScope、当前标签及来源归属构建输入，不接受模型指定任意 sessionId 或 BotId。
输入只包含当前可读的有限记忆版本、选定原文片段、必要的任务结果与原有验证证据。
群经历复用 GroupRecall 的参与约束和 validateReferences；不得绕过它直接按 sessionId 读取全群。
普通私聊的准确来源读取需完成下述 spike，不能把群 root 的读取条件直接套到私聊。
任何 unavailable、来源撤销、正文缺失、范围不明都减少输入或停止，不补猜缺失原文。

| 等级 | 可支持的候选表述 | 限制 |
| --- | --- | --- |
| E0：助手陈述/生成摘要 | “曾提出此方案，尚未验证” | 不得改写为完成、成功或用户偏好 |
| E1：有定位的直接用户陈述 | “用户在此处表示/纠正……” | 当前原生 ingress 无不可伪造证明，不可升级自动共享信任 |
| E2：可重读的工具或测试结果 | “在版本/环境 X，命令 Y 得到 Z” | 工具输出仍可能不可信，限定范围，不保证长期成立 |
| E3：独立验证且可追溯 | “在明确边界内复核通过” | 验证路径、版本、时间必须保留，不自动跨环境推广 |

等级由 Host 依据可验证的事件类型、身份、工具结果结构和独立验证收据判定；模型只能建议等级与引用。
只有一段“测试通过”的文字不能判 E2/E3；缺少结构证据降为 E0/未证实，Host 不用模型自评填补。
等级是本功能的证据描述，不替换现有 trust，也不赋予任何执行权限。
采用事件可记录 user_confirmed，但原始 E0/E1 及其来源仍保留；“用户采用”不将 E0 变成 E3。
模型仅输出正文、适用范围、证据引用编号、建议 action 与目标候选编号。
身份、来源 receipt、labels、trust、status、版本号与 opId 全由 Host 提供。
引用材料中的指令只作为数据处理；不得据其修改 persona、root instructions、工具权限或审批策略。
[自动共享 gate](../../../packages/dsh-bot/src/host/memory/trusted-ingress.ts)保持 fail closed；本设计不创造 RPC nonce 等替代证明。

## 4. 最小数据扩展与来源 spike

当前 sourceRefs 只有 sessionId、eventSeq、callId、parentVersionId、entryReceiptId、managementOpId。
它没有原生日志事件类型、messageId、片段范围/编码、摘要、原文可见性或群参与证明。
当前 related 遗忘沿 labels.sourceVersions 与 parentVersionId 追踪版本依赖；仅填 sessionId 不形成派生闭包。
当前 receipts 保存的是 sessionId/versionIds/read 等状态，不能伪装成 accepted-entry 原文证据。
当前管理 create 会生成新的随机 opId、空 sourceRefs；不能直接拿它接收整理结果并声称来源完整。

因此先完成 M0 spike，再批准具体 schema；以下是最小候选设计，不是已存在 API：

- 新增 Host-only `consolidation_runs`：runId、BotKey、范围摘要、输入 revision/epoch、状态、原生执行 ID、预算、候选 ID、固定提交 opId。
- 候选正文优先存 V2 proposed payload/version，避免另建笔记库；runs 只保存控制字段和引用。
- 新增 `memory_evidence`：不可变 receipt ID、来源定位、受控片段 hash、提取规则版本、证据等级、验证时间与来源限制。
- `sourceRefs` 增加可选 `evidenceRefId`；它是本插件来源证据，绝不复用 `entryReceiptId` 冒充可信用户入口。
- 群证据嵌入既有 GroupRecallReference；普通日志引用含 sessionId、eventSeq、事件类型、messageId/callId（适用时）。
- 片段明确使用原文提取函数版本、UTF-16 offset/length 和 SHA256；不混用 auto-share 的 Unicode code-point 偏移。
- 原文通常仍在原生 Session；证据表只留指针/hash，审阅时按权限重新读取，不默认复制整份 transcript。
- 对既有记忆的派生必须同时写 parentVersionId 与 labels.sourceVersions；不能只把依赖藏在候选正文。
- 对原生日志的派生通过 evidenceRefId 建立可枚举反向索引；索引是可重建缓存，证据表才是权威引用。

新增控制状态的理由：原生执行记录管理会话，不表达候选审阅、CAS 采用与同一 opId 的未知结果。
新增证据表的理由：现有 sourceRefs/receipts/recall_reads 均不足以通用表达原生日志定位和派生有效性。
不新建调度器、模型客户端、全文仓库或授权系统；使用原生 storageDomain 和现有内核队列。
新增表/可选字段的 domain schema、迁移与旧版本拒绝降级策略必须先 spike，不能擅自保持 version=2。
若 spike 无法可靠绑定普通原文，首版只开放通过撤销/删除闭环验收的来源；GroupRecall 的即时重读不自动等于持久派生准入证明。
首版可缩小到内核完整控制的既有记忆版本；未证明原生日志闭环时，普通会话及群片段均不持久派生。

M0 必须核实：

1. 锁定 rc.2 的公开 SessionQuery/SessionPersistence 能否准确读到选定事件和当前可见性；同时核对目标兼容宿主。
2. 活跃、冷存储、摘要/压缩后、编辑/删除/分支情况下，定位是否稳定；找不到原文时正确停用。
3. 群成员撤销、Bot 删除重建、源记忆遗忘后，已存 receipt 是否及时不可读。
4. 新字段与 table 的 migrate/replay/备份/回滚规则；旧记录无需自动模型重写。
5. 控制表、证据表和 V2 op 无跨表事务时，prepare→commit→recover 的结果可唯一判断。
6. 原生只读执行的工具范围、调用预算、usage 缺失和取消语义；不能仅凭工具描述声称已隔离。

## 5. 生成、采用、去重与恢复

状态建议：prepared → running → review → committing → accepted；旁路为 rejected、expired、failed、unknown、blocked。
为提交落盘 intent，先分配 runId、候选 ID、输入/请求摘要和稳定 opId，随后启动/接纳执行；此时尚无输出正文摘要。
模型输出经严格 schema、内容上限、密钥启发式检查后，Host 持久化 proposed 候选并发布 review 状态。
执行去重键由 Bot 身份、来源版本集合、提取规则、整理提示版本、模型参数和用户操作 ID 形成，启动前持久化；同操作重复只读已有状态，不再请求模型。
同输入/规则/模型的已知成功结果可以提示复用；参数变化形成新请求，用户明确重新生成使用新操作 ID 并重新预占预算，旧 unknown 仍保留且不自动重放。
生成后的正文规范化摘要、来源集合和候选目标用于候选内容去重及采用 CAS；它不可能用于阻止首次模型请求。
语义相似只提示相近记录；不自动合并不同有效期、环境条件或数值，使用现有 factKey 冲突视图。
人工改正文后生成新的候选修订和内容摘要，旧“采用”按钮失效；摘要只能防止版本错配，不能证明语义有据。
实质改写必须重新核对支持片段；无法确认仍受原文支持时标为“人工新主张”，保留编辑来源，不能继承原证据等级。
人工新主张采用沿用私有管理写入语义，明确区分用户采用与外部验证；不得假借旧引用声称原文已证明。

采用请求包含 runId、候选版本 ID、expectedRevision、目标版本 ID（修订时）和审阅摘要。
Host 在内核串行提交边界复查 Bot 身份、候选状态、来源有效性、epoch、目标权限与 CAS。
原文验证有异步窗口：先异步重读，再持锁检查 Host 来源证明快照的 revision/sourceEpoch、当前标签和 CAS；不持锁调用模型。
sourceEpoch 是本插件失效序号，不假设原生提供 generation；只有 M0 证明原生变更与该序号之间的关闭窗口机制才允许来源上线。
未证明删除/撤销的完整覆盖与最终请求准入顺序时，关闭该来源，不能以一次重读、短 TTL 或本地计数假冒原生一致性。
采用提交保留来源限制、合并 lineage，并设置私有读者；不扩大 readers、grants 或出口权限。
采用 `accept`/`revise` 写一次 op；调用新 Host 内部适配器复用 kernel，不让模型调用管理 facade。
修订失败不静默创建新条目；CAS 冲突显示当前差异，重新审阅后产生新的提交意图。

commit 返回未知时进入 unknown，禁止换 opId 重试、自动重新运行模型或宣布采用成功。
恢复先读取原固定 opId：存在且摘要相同则补齐 accepted 状态；不存在且内核已完成恢复则重新验证原意图。
无法判断、payload 被擦或参数不一致保持 blocked；不从“界面没显示”推断提交失败。
启动崩溃与候选落盘崩溃分别用原生执行 ID、固定候选 ID 和日志交叉核对。
没有可恢复执行证据时只允许明确重新生成新 run；原 unknown 不复用为新成功记录。
所有注册、监听、执行取消与资源关闭纳入 ctx.effect；卸载不得晚到补注册或补提交。

## 6. 遗忘、来源撤销与副本清理

[现有遗忘闭包](../../../packages/dsh-bot/src/host/memory/forget-preview.ts)及
[库存/清理入口](../../../packages/dsh-bot/src/host/memory/forget-service.ts)必须随新表一起扩展。
源记忆遗忘沿 parentVersionId/sourceVersions 纳入候选和已采用派生；普通日志依赖则经 evidenceRefId 查找。
原文删除/权限撤销与记忆遗忘不是同一个事件，必须分别接入来源有效性检查；不能依赖 epoch 自动覆盖一切。
采用异步准入与同步读取分离的闭环，禁止将 I/O 塞入当前同步 memoryContext provider：

1. Host 异步来源适配器在输入收集、候选审阅及请求准备阶段读取原文/权限；初始与冷恢复状态均为 unverified。
2. 验证完成后在内核队列发布不可变 sourceStates 快照：evidenceRefId、状态、证明摘要、来源策略版本、sourceEpoch。
3. sourceStates 是新增的可重建运行投影，不把缓存持久化后直接当有效证明；它的异步入口与公开请求生命周期顺序必须在 M0 验证。
4. 同步 context/search 只读取已发布快照与当前内核标签；缺证明、失效或 epoch 不一致的派生一律不选入，并将 sourceEpoch 纳入缓存键。
5. 删除/撤销路径先递增 sourceEpoch、发布 blocked 状态、失效派生和正在准备的请求，再异步清理；不能等清理结束才关读口。
6. 复用 MemoryAdmission 的最终请求门，核对本次已观察证据的快照版本；准备后发生变化则取消/拒绝，重新准备而不发送旧文本。
7. 异步校验来不及完成时本次不注入，若已有历史含失效内容则拒绝请求并走既有历史清理，不能只删新 section 继续发送。

以上是拟扩展协议，不是现有原生能力承诺；provider 不触发校验、网络、文件读取或异步等待。
M0 必须证明所有受支持来源的删除/撤销信号覆盖及与最终请求门的顺序；不能证明的来源首版关闭。
TTL 只可用于主动丢弃旧证明，不能授权读取或替代撤销证明；已有 GroupRecall 也须通过同一闭环门。
查验失败先阻止读取与采用，再进入待清理状态；首版条数受限，避免无界扫描。

遗忘预览 inventory 必须增加 runs、evidence、候选正文、执行输入输出、审阅缓存与反向索引。
可枚举内存缓存也要失效；原生整理执行的 session 纳入现有历史清理，不能遗漏干净 child 会话。
若只有普通日志依赖而没有 MemoryVersion，也必须有可枚举 cleanup owner 与受影响会话，不能伪造一条事实当锚点。
删除候选不删除用户原始会话；“清理整理副本”和“删除来源”是独立动作。
持久控制记录不得留原文或敏感 hash 列表作为永久 tombstone；清理后只保留最小随机 ID/状态/提交关联。
清理失败保留 blocked 和原因；必须用冷启动后枚举/读取验证收据放行，文件不存在不是充分证明。
restore 必须沿 evidenceRefId 检查当前源权限及 tombstone；不能用历史版本绕过新依赖检查。
验收覆盖源先删、候选先删、提交中遗忘、重启恢复、跨 Bot 同文本、群成员撤销和原文已压缩。

## 7. 执行边界与预算

使用公开原生 Agent/subagent，参考现有[Supergroup 接纳](../../../packages/dsh-bot/src/host/supergroup/service.ts)与 clean-task 隔离路线。
首版由 Host 供给全部有限输入，执行不注册记忆写入、消息、连接器、shell、网络或递归派工工具。
仅靠 `tools.restrict` 描述不够；spike 必须验证本地与继承工具 schema、dispatch 都拒绝越界。
沿用原生取消/超时与现有 request 计数接入，不另建模型传输或修改全局 never/ask 策略。
独立整理任务需要自己的有界计数归属，但共享已有预算实现；不得冒充某个真实 Supergroup 工作授权。

建议首版 Config 默认：enabled=false、maxRequests=1、maxConcurrent=1、timeoutMs=60000、maxInputChars=24000、maxOutputChars=4000。
单条候选持久正文仍遵守现有 2048 UTF-8 字节上限；来源数量建议 8、总事件扫描上限建议 200。
maxOutputTokens 默认 2048，需验证原生参数确实下传；输入 chars 只作大小门，不宣称等于精确 token。
追加每日硬限额：每 Bot 3 次请求、全 Host 10 次请求；复用既有预算预留/结算实现与配置时区，不新建独立计费账本。
Host 在 dispatch 前原子预占单次、Bot 日限及 Host 日限；计数跨重启持久化，反复手动触发或并发不能绕过。
超时/取消/网络结果未知保留预占，不退还为零成本，也不自动重试；每日切换和重复收据必须幂等。
usage 可得时记录实际 input/output tokens；缺失标 unknown，不编造零，不据估算提供精确费用。
若将来设置金额预算而缺少可信 usage/定价，停止后续自动调用；首版仍靠请求数、输入、输出和时限硬界限。
当前授权仅实现/验证 mock 管线；真实模型质量实验须单独获得调用范围和预算授权。

## 8. 分阶段实施与验收门

下列 M 编号是本子方案的工作项，不替代总计划 P0–P5：M0 归 P0；评测框架/基线先在 P1 建立；M1/M2 归 P2；组合验证与有界真实评测归 P5。
P2 明确禁止自动常驻晋升与自动共享；不依赖 P3 等待恢复或 P4 定时唤醒，M4 仅为后续评测驱动选项。

| 阶段 | 可交付增量 | 必须通过的验收 |
| --- | --- | --- |
| M0：原生与来源 spike | 精确来源、执行限制、usage、迁移/恢复矩阵 | 冷/热原文读取、越权拒绝、摘要缺原文停用、工具逃逸拒绝、缺 usage/崩溃反例；隔离 Host+mock |
| M1：候选与依赖底座 | schema/migration、单 Bot 候选、证据表、inventory、CAS/幂等 | 同 opId 重放、并发修改、unknown 恢复、来源撤销、跨 Bot 隔离、全路径遗忘；禁用时零新增执行 |
| M2：手动整理闭环 | 原生受控执行、记忆页审阅/拒绝/采用、changes/restore | mock 驱动真实 Agent→候选→采用；双窗口旧按钮失败；亮暗主题/中英；取消不补提交 |
| M3：收益评估（P1 建基线，P5 做最终对照） | 固定任务集与独立结果报告 | A 原始搜索 / B 现有记忆＋搜索 / C 整理记忆＋搜索同条件对比；报告成功率、错误采用、过时误用、token 与未知用量 |
| M4：条件性优化 | 小型导航索引/注入晋升提案 | M3 证明收益再立项；来源可撤销、索引可重建、预算不增加、无权限扩大 |

三臂严格遵守[质量评测方案](memory-quality.md)：相同原始搜索与可见时间窗，C 从 B 快照派生，不增加事实权限；比较 B 对 A、C 对 B，完整计入整理成本。
新增验收覆盖 provider 零 I/O、校验与发送间撤销、冷恢复未验证状态、编辑后无依据断言、日限并发/重启/跨日/unknown 不退款。
每阶段代码完成后执行任务针对性测试及 `scripts/pnpm check`；使用仓库隔离 DSH_HOME，不触碰日常安装。
测试名称、文档或 mock 通过不能证明真实模型整理有用；M3 无真实模型授权时只交付评估框架并明确未验证。
M0 若否定可靠原文来源或副本可清理性，相应来源不进入 M1/M2，不能靠 UI 提示绕过。
M1 的清理/恢复没有通过前，不启用任何实际候选持久化入口。

## 9. 未来索引与注入晋升的依据

先用实际检索失败样本区分：找不到来源、查询词不匹配、候选选择错误、正文质量差或预算截断。
只有导航困难才增加短索引（主题→既有 memoryId/来源指针），不复制所有事实为另一份真相。
晋升条件建议为重复跨任务有效、人工纠正后稳定、难以重查、来源仍可读且无未解决冲突。
动态价格、版本、CI 状态等只存权威指针/核对条件，不通过晋升变成长期常驻事实。
优先复用 pinned/现有预算字段；自动晋升若需要新质量分数，先定义可解释证据及降级条件再设计字段。
保持当前 maxInjectChars 总上限，比较晋升前后任务成功率和无关上下文占比；不能只测命中率。
wiki/向量方案只有在对比现有 BM25 和小型索引后仍有明确增益才进入后续审批。
