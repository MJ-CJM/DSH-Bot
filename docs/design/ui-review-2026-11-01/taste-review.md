# Taste 应用界面评审

使用项目安装的 design-taste-frontend（`.agents/skills/design-taste-frontend/SKILL.md`） 及 `references/app-screens.md`，按应用界面规则审查，不套用营销页面的照片、动效、巨型标题或装饰规则。

方向抽签：`workspace / true-black-flat`，seed `1304909193`，保留 `palette,type`。选取其低干扰、平面层级、内容优先的布局方向；**DSH 已有设计规范优先**，不采用方向卡的硬编码黑色、反白胶囊、禁用品牌导航色等与 Host 不符的细节，也不复制 app.css。主特征仍是可辨认的 Bot 身份、原生会话和每问题的执行过程。

本轮是用户要求的评审，完成一轮“截图 → 测量 → 人工判读 → 提案”，未执行产品重绘。

## 七项应用界面判读

1. **最大的内容是否回答当前问题？** 我的 Bots 与群资料基本清楚；通知、记忆的首屏没有优先回答“收到什么 / 记住什么”。群聊目前已把每题过程挂回对应问题，方向正确；诊断数字与成员操作还能再减轻。
2. **对齐和留白是否有用途？** 主要分区采用统一边距，未见需要另造一套外壳的理由。连接器多列长表单与全宽 Bot 选择框占据较多空间；Bot 详情展开能力后会成为很长的居中弹窗。任务空态留下空白本身合理，问题是缺少明确下一步，不应通过添加统计卡填空。
3. **颜色是否支持操作与身份？** 大体遵循 DSH 亮暗主题，品牌蓝为选中/操作，鲸鱼头像有身份作用。保留，不按通用审美规则删除彩色头像。需要统一的是按钮权重、焦点、菜单与状态，而非换主色。
4. **数字与重复事实是否一致？** 测试群显示2名成员，运行视图也显示2名成员，和 fixture 一致；本轮只有1条演示记忆。记忆页执行统计为“最近保留的显式执行记录”，不是群聊总执行量，不能和群消息数比较或制造成功率。Bot 选择跨分区不一致已实测，是高优先级问题。
5. **零、未知、不可用是否区分？** 当前文案有区分“受理/完成/未知”，应保留。不支持 IM/Team 的页面有真实说明，但内容偏诊断。新建 Bot 默认工作目录显示“正在加载”，而创建模式没有触发对应加载，需修正。任务空态应提供打开 Bot 对话的路径。
6. **标记、文案与控件是否清楚？** 无统计图，不要求新增图例或图表。模型菜单分 provider 的做法保留，群/成员/Bot 继承来源保留。多层“兼容设置 / 高级选项 / 更多”难预测；应按用户任务命名。IM 版本 pin、契约检测、派发 JSON 等默认不应占据主要阅读空间。
7. **手机是否仍能完成同一任务？** 原生侧栏能收为窄栏，页面没有被强制塞成桌面两列；但导航换行、多层说明、全展开表单让主要操作下移。群运行时每成员按钮多行，需菜单收敛；Bot 创建弹窗可用，头像入口可更紧凑。主内容每次只展示一层，返回、保存和成员操作不能依赖鼠标悬停。

## Taste 工具结果的使用方式

- Source lint 扫描111个文件，输出5项 FAIL、1项 WARN；这是规则命中，不等于6个需要修复的产品缺陷。
- 4个 gradient 命中来自两个 CSS 文件里用双三角绘制 select 箭头；不是装饰渐变。可随控件收敛移除重复绘制，不单独作为视觉缺陷。
- Emoji 命中来自 AvatarPicker 的用户头像候选，是身份自定义能力，不是导航装饰；保留。
- `shadow` WARN 实际匹配 `AutoShareStatus.tsx` 的业务字段 `status.shadow`，不是 CSS 阴影；忽略该误报。
- 对已导航的每个截图状态，执行 skill 原始 `probe()` / `app()` 和 `judge(... APP_SKIP)` / `judgeApp()`。没有直接宣称运行完整 `inspect.mjs`：其新开 URL 流程无法保留这个 SPA 的当前设置/弹窗状态，本轮用真实浏览器适配其同一测量内核。
- 测量范围包含 DSH 原生外壳。聊天页 `no-title`、Host composer 渐隐遮罩、系统 SF Mono 字体回退等不能据此要求插件修改原生外壳；rgba 边框被归一为不透明白色的强边框提示需人工判读，不能直接宣称不符合对比度。
- 自动探针没有替代 WCAG 审计、真实辅助技术测试或逐元素键盘验收。完整键盘矩阵、全部平板状态与英文长文本在开发验收清单中逐项执行。
- API fixture 在群根留下早期测试子任务的“已完成”行，且示例推理包含测试文本/ID；这些是测试数据，不把它们统计为生产重复消息缺陷。

原始扫描与每图测量保留在截图目录。此处的优先级来自截图、实际交互和源码三者对照，不以工具的 FAIL 数量排序，也不以单一审美分数概括整个产品。
