## 同包双版本 Host 复验

使用仓库 `scripts/group-members-host.mjs`，以仓库隔离 `DSH_HOME` 和指定版本 CLI 安装相同原包。模型回复由本地模拟 Adapter 提供，不使用真实用户数据或模型密钥。

| 宿主 | 热运行 | 冷启动 | 模型请求 |
| --- | --- | --- | --- |
| DSH `0.2.1-rc.2` | PASS | PASS | 热运行 7 次本地模拟，冷启动 0 次，真实模型 0 次 |
| DSH `0.2.2-rc.5` | PASS | PASS | 热运行 7 次本地模拟，冷启动 0 次，真实模型 0 次 |

两个宿主分别验证以下行为：

- 纯移出无需新增历史授权；新增成员缺少明确授权时拒绝，既不修改名单，也不写入持久操作尝试。
- 明确确认后的新增、所有者限制、准确 Bot 创建代际、至少 2 人、配置上限、操作重放和版本冲突符合预期。
- 保留现有不可用成员不会阻止其他成员修改；也可明确移出该不可用成员。
- 名单变更使旧私有预览及授权令牌失效，不发布或重执行旧内容。
- 移出只取消被移出成员的原生执行；另两位成员正常完成，被移出成员的回复不发布。
- 合成群原生日志原始前缀、所有合成 Bot、私聊主会话身份及私有记忆正文保留。
- 冷启动查询及重复操作核对保留收据、名单、历史、私聊和记忆，不触发模型重放。

热运行各记录 7 份操作收据及 3 个原生 worker。收据中的群、会话和 Bot 标识仅用于隔离合成数据，不进入公开说明。

## 原生界面检查与覆盖边界

新包在隔离 rc.5 原生群管理页通过 CUA 完成亮色冒烟：初始名单为 3/6，包含一位停用成员；「管理成员」保留该成员；明确确认新增读者和历史范围后增加一位成员，标题及列表同步为 4；从行菜单移出新增成员，仅出现一次确认；完成后标题及列表回到 3，停用成员仍在。此次未发送模型消息，未改日常 profile。

其他管理入口、右侧成员列表、暗色及 480px 窄视口此前已在业务实现等价的本地候选上验收，详见[群成员管理实现与本地部署验收](../validation/group-members-management.md)。本次新包没有重复这些界面步骤，保留为先前验收证据，不表述为新包完整浏览器遍历。

## 旧客户端兼容

旧五参数 Remote `dshBot.groups/teamApply` 保持参数合同。纯移出和排序继续兼容；加入新成员时，旧调用无法提供明确的新读者授权，Host 安全拒绝。新客户端使用带明确确认选项的 `teamApplyMembers`。普通用户使用新版页面即可，无需新增配置或手动处理接口参数。

这项拒绝保持新增读者的权限边界，不通过放宽私有记忆或历史访问来兼容旧客户端。
