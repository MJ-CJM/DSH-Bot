## 需要修正的实施路径

插件内部已使用现有存储和生命周期完成两项修正：主动设置通过原生 volatile 更新，仅重组主动子服务，保留 Bot registry 和会话 guard；首次启用在任何旧 pending、自动规则或通知泵恢复前提交准确 Subject 的持久准入与操作收据。这些属于现有批准范围，没有增加新的用户配置概念；两个宿主的当前验证见[生命周期报告](v066-follow-up-lifecycle.md)。

定时路径尚不能直接冻结为产品方案。正常混批桥接可行，但冷启动失败后缺少保证就绪后重新扫描的公开路径；当前解析桥也没有覆盖所有同源原生消息。只读源码确认 rc.2 在本轮 drive 中排除失败日程计算后续 timer，没有公开强制重试接口。受控创建另一日程可以唤醒扫描，但该诊断操作不适合作产品补偿。也不能用删除重建、修改用户时间或另造 timer 来声称复用了原生日程。

另行核查了只更新受管日程 prompt 的 CAS 包装：rc.2 的公开 update 保留时间和 ID，真实修改会重新扫描；桌面公开 edit 还会向关联会话注入管理通知。真实绑定或用户内容修订可以使用它，但每次重启无意义更换 nonce 仅为唤醒扫描，不是已验证的恢复接口。该路径没有运行验收，不能替代自然补偿或跨崩溃一次准入的证明。

最小原生补齐方向是就绪后的可恢复投递，以及带准确 occurrence 身份、区分提醒/管理消息的公开消费接口或非模型目标。这是所需能力说明，不是已存在的 DSH API。本仓库锁定 rc.2，DSH 参考源码只读，因此本轮没有擅自修改宿主、升级依赖或承诺现有更新版本能解决。继续按原定范围交付，需要先解决该原生组合并完成剩余 P0；若缩减 0.6.6 的定时范围，应另行明确，不能沿用当前“全部完成”标准标记通过。
