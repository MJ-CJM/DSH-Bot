## 安装与包名过渡

全新安装可在 DSH 的第三方插件安装入口填 `dsh-botgroup@0.6.7`，也可对 Web profile 使用 `dsh plugin --profile web add dsh-botgroup@0.6.7`。

旧 `dsh-bot` 用户按以下顺序迁移。

1. 停止对应 DSH Host，备份完整 profile、Bot 数据与会话；保留自定义数据目录。
2. 通过原生插件管理移除旧 `dsh-bot`，再安装 `dsh-botgroup@0.6.7`；同一 profile 不保留两个包的依赖/bundle。
3. 启动前检查原 profile 的 `cordis.patch.yml`：对原插件 `id: dsh-bot` 覆盖行，如果还有 `name: dsh-bot`，只改为 `name: dsh-botgroup`。保留 `id`、`config`、`dataDir` 等原值；未带 `name` 的行无需补字段。若还有其它自定义包含层或模板，应逐项检查其旧包引用，不把此两宿主标准 profile 验收推广到任意自定义结构。
4. 完整重启，核对设置、Bot、记忆、群和原会话，再继续使用。回退使用升级前备份，不让旧包重新覆盖已迁移数据。

市场以默认分支 `packages/dsh-bot/package.json` 的包名和 npm `latest` 的 `repository.url` 自动关联现有条目。保留原 YAML、固定 GitHub 下载地址和目录 ID，包名调整无需另提 PR。网页目录当前 tarball 入口已经能下载新版，但 npm 映射、下载统计与原生发现索引尚未同步。目录下载数覆盖滚动 30 天的 registry 下载，历史 GitHub 附件下载单独统计。 [维护者发布步骤](../community-release.md#8-npm-首发与市场回读)
