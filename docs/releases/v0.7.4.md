## 群成员管理更直接

- **从当前页面管理成员。** Bots 群目录、群聊管理页、右侧群成员栏和群设置统一打开「管理成员」。可以在同一处添加、移出、调整顺序，保存前查看变更摘要，也可以撤回草稿变更。主成员列表和右侧成员列表的菜单均提供「移出群聊」。
- **移出只确认一次。** 单独移出成员时说明影响后确认即可。只移出成员、排序或修改普通设置，不再要求确认新增成员的历史访问；确实加入新 Bot 时，才明确确认新读者及本群已授权的历史范围。团队配方应用采用相同规则。
- **完整显示名单与容量。** 停用但未移出的成员仍在名单中并占用名额，保存其他设置不会把它误删或重新启用。保留现有不可用成员不妨碍移出另一位成员。普通群保留至少 2 位成员，沿用最多 6 位 Bot 的上限；已有超额群允许逐步减员。
- **名单与操作结果同步。** 保存后同步更新主列表、右侧名单、人数和成员头像。版本冲突时保留草稿并展示最新名单，供重新核对；保存成功但刷新失败时只重试读取，不重复提交。结果不确定时先核对原操作，不自动重做。
- **移出保留资料与隔离。** 移出只停止该成员在本群未结束的执行，其他成员继续。Bot 本身、私聊、私有记忆和群历史保留。名单改变后，旧成员版本的回传许可与待审预览失效，旧回复不会自动重发。

本版保留现有普通群多轮交流、Bot 互问、群外转问及回复折叠行为，不调整自动续办次数、发言路由或模型预算。

## English

Status: the 0.7.4 archive is frozen and has passed local release revalidation; the release PR, merge and publication are pending. Verified on November 24, 2026. Changes below are compared with [published 0.7.3](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.3). Check the corresponding GitHub Release and npm dist-tag for publication status and downloadable versions.

- **Manage members where you work.** The Bots group directory, group management page, right member sidebar and group settings open the same **Manage members** dialog. Add, remove or reorder members, review the changes before saving, and undo draft changes. Both member lists offer **Remove from group** in the member menu.
- **Confirm removal once.** Removing members, changing their order or editing ordinary settings no longer requests consent for a new reader’s history access. Adding a new Bot requires explicit confirmation of the new readers and the group history already authorized for them. Team recipes follow the same rule.
- **Keep the full roster visible.** Disabled members still occupy a place until removed. Saving other settings neither removes nor re-enables them. An existing unavailable member can be kept while another member is removed. Ordinary groups retain at least two members and the existing six-Bot limit; older oversized groups can shrink gradually.
- **Keep lists and save results consistent.** The main list, sidebar, counts and member avatars refresh together. A version conflict keeps the draft for review against the latest roster. A failed refresh after a successful save retries the read, not the change. Uncertain results are checked against the original operation rather than replayed.
- **Preserve data and private boundaries.** Removal stops only that member’s unfinished work in this group. Other members continue, while the Bot, private chats, private memory and group history remain. Roster changes invalidate return permissions and pending previews tied to the previous membership; old replies are not automatically resent.

This release keeps existing multi-turn group exchanges, peer questions, outside-group relays and reply folding. It does not change continuation allowances, speaker routing or model budgets.

## 接口兼容 / API compatibility

普通用户通过新版页面操作，无需新增配置。旧版五参数 `teamApply` 保留纯移出和排序兼容；涉及新增成员时，因旧调用无法携带明确的新读者授权，Host 会安全拒绝。新版客户端通过 `teamApplyMembers` 完成明确确认，团队配方与普通成员管理遵守同一授权边界。

No additional configuration is needed for normal UI use. The legacy five-argument `teamApply` remains compatible with removal and reordering. It safely rejects additions because that call cannot carry explicit new-reader consent. The updated client captures consent through `teamApplyMembers`, using the same authorization boundary as ordinary member management.

## 从 0.7.3 升级 / Upgrade from 0.7.3

After publication, verify `dsh-botgroup-0.7.4.tgz` or its fixed-name alias `dsh-bot.tgz` against the checksum from that same Release. Quit DSH, back up the existing profile and data, update `dsh-botgroup` in the original profile through native plugin management, then reopen DSH. Keep the storage location; do not delete Bots or reset data as an upgrade step. Upgrading does not change existing rosters or sharing permissions.
