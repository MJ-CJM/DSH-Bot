# DSH-Bot 0.7.2

安装包为 `dsh-botgroup-0.7.2.tgz`。以下更新相对于[公开版 0.7.1](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.1)。

## Bot 互问与结果复用

- **普通问答可以直接进行。** 在一个 Bot 的对话里说「问 Jarvis 有哪些公开接口」，就能在原对话收到答案，接着追问。发送问题、回复和跟进都无需逐次审批，也无需开启 Supergroup。双方会话保留可展开的收发记录。普通问答期间及完成后省去重复的「协作」卡片。群任务仍有自己的详情入口。
- **问过的结果可以直接取回。** 上一轮只向一位 Bot 提了一个问题时，接着问「他查到的结果是什么？」即可取回已交付、当前仍有权读取的原答案。这次读取不会再次发送问题或调用模型。任务归属不清、答复尚未完成或结果已不可读时，插件不会把旧正文作为本轮答案。
- **私有内容单独确认。** 普通提问只带上本次明确交给对方的任务及相关的已共享结果。要转发私有记忆或私聊原文时，可以先看收件人和准确正文，再决定是否发送。若答案只在对方私聊里，索取结果的问题可直接发送，由回复方在分享正文前请求确认。

## 13 项巡检修复

### 私有记忆

- 共享确认绑定到所属 Bot 和预览的具体版本。另一窗口改了内容，必须重新预览才能分享。
- 置顶或修改标签时保留原条目的类型、归属、可信度、限定条件、有效期和版本历史。事件到期后仍从当前有效的检索结果中排除。
- 整理记忆遇到明确的版本冲突时，保留仍有效的选择，刷新后可重新提交。仅在响应丢失、结果待确认时核对原操作，避免重复调用模型。

### 群消息与回传

- 同一草稿既选择「只记录记忆」又引用消息或追问时，输入框会提示先取消一项。成功发送后下一条恢复默认。
- 发消息时若群成员已变，保留草稿并显示新名单。确认原消息未受理后，可按新名单重新发送。响应丢失时先核对原操作，避免重复群发。
- 回传后丢失响应，可只读核对同一条回传的最新记录。确认已发送或已拒绝后更新回执，证据不足时保留待核对状态。
- 每条群消息最多附 16 个文件。分多次选择也会累计，超限时在上传前提示。
- 长群聊读取历史时，分页和摘要共用同一次轮次排序。2,000 条输入的回归场景中，整组排序由 2,001 次降至 1 次，显示的消息数量一致。

### 待办、活动与主动跟进

- 某只 Bot 的待办暂时读不到时，界面列出该 Bot 并提供重试，其他 Bot 的待办仍可打开。
- 某只 Bot 的主会话暂不可用时，其他 Bot 的最近活动和未读摘要继续显示。
- 待发通知遇到临时读取失败会保留，恢复后重新核对权限与有效期。确认已记录的通知只发一次，明确撤权或过期后停止投递。
- GitHub Actions 跟进可跨过默认的 256 次运行，分时间段保存进度，重启后继续，并回看延迟完成或重新运行的任务。若同一分支在同一秒内超过接口可返回的 1,000 条，保留进度并报告原因。
- 子任务中断、受阻或达到输出上限时显示具体原因。已被旧版误标为「关注中」的卡片可恢复为相应的结束状态。

## 从 0.7.1 升级

已有官方原生工作区的用户，只需在同一 profile 更新 `dsh-botgroup` 产品包。升级前正常退出 DSH，备份现有 profile 和数据。用 `SHA256SUMS` 核对版本包，在 DSH 的 **插件 → 添加插件 → 安装第三方插件** 中选择 tgz，安装后完全退出并重开 DSH。原有 Bot、群聊、会话和私有记忆继续使用原数据目录。

## English release notes

Package `dsh-botgroup-0.7.2.tgz`. Changes are relative to [0.7.1](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.1).

### Ask another Bot and reuse its answer

- Ask your Bot to contact a teammate, read the reply in the original conversation, and ask follow-up questions. Ordinary questions and replies need no per-message approval, including when Supergroup is off. Both conversations keep their expandable message receipts. The extra collaboration card is hidden during and after an ordinary exchange. Group tasks keep their details.
- If the previous turn had a single peer question, ask “What did they find?” to retrieve its delivered answer. The plugin checks that the task completed and the current reader still has access. A successful lookup sends no new message and makes no model call. An ambiguous or unavailable result cannot supply an answer.
- Private memory and private chat excerpts still require confirmation of the exact recipient and text. If a result exists only in the other Bot’s private chat, asking for it needs no approval. The responding Bot requests confirmation before sharing that text.

### Audit fixes

- **Private memory (3).** Sharing is bound to the owning Bot and the version shown in the preview. Pinning and tag changes preserve the original type, ownership, trust, qualifiers, validity period and history. After a confirmed consolidation conflict, valid selections survive a refresh. An uncertain outcome is checked against the original operation.
- **Group messages and replies (5).** The composer resolves a quote or follow-up conflicting with “Record memory only” before sending. A roster change keeps the draft and allows resubmission to the new members once the original send is confirmed unaccepted. A lost reply acknowledgement can be checked without resending. The 16-attachment limit covers all selections for one message and is checked before upload. History pages and summaries share one sort of the group’s turns, down from 2,001 sorts in a 2,000-input regression case.
- **Pending tasks and activity (2).** A Bot with temporarily unavailable tasks is identified and can be retried while other Bots’ tasks remain accessible. An unavailable main conversation no longer hides other Bots’ recent activity or unread counts.
- **Proactive follow-up (3).** Pending notifications survive temporary read failures and recheck permission and expiry before delivery. GitHub Actions tracking resumes in time windows beyond the default 256 runs and revisits delayed completions and reruns. If a single branch exceeds the provider’s 1,000-result limit within one second, the checkpoint is retained and the failure is reported. Interrupted, blocked and output-limited subtasks show the applicable reason, including previously tracked tasks with an incorrect status.

### Upgrade from 0.7.1

For an existing official native workspace, update `dsh-botgroup` in the same profile. Shut down DSH and back up the profile and data first. Verify the versioned tgz against `SHA256SUMS`, select it through the native plugin manager, then quit and reopen DSH. Existing Bots, groups, conversations and private memories use the same data directory.
