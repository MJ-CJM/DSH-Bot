- 首次开启保留现有主会话、头像、记忆、工具和审批。复用 DSH 的 ConfigEditor、Session、工具审批、群执行和原有协调器。

## 使用顺序

1. 在个人 Bot 的任务页开启“主动跟进”，再进入一个群的活动页独立开启。其他 Bot 和群保持原设置。
2. 登记一项明确事项；在群聊天中提出事项后，确认群卡片。查看卡片可直接回到原任务或群活动。
3. 对已有任务查看结果、补充明确缺失的信息或继续处理；群失败事项选择一个成员，并输入本次要处理的内容。
4. 暂停范围或停止单项，确认其他范围和已经接受的手动任务不受误取消。需要核对结果时使用原卡片上的核对入口。

## 边界与回退

- 本版主动跟进不包含定时提醒。原生普通日程保留；不承诺关闭 DSH 后继续工作，也不新增自己的 cron 或后台模型扫描。具体失败反例见[原生日程 P0](../verification/v066-schedule-p0.md)。
- 合成模型验证证明原生执行、来源、路由及幂等行为，不代表真实模型理解或任务质量。实际模型任务使用已有 DSH 路由和审批。
- 工程产物执行和外部消息发送继续受已有能力门槛约束，本版没有新增写入、外发或自动授权。
- 旧本地协调库迁移为 schema 9。升级前保留原 profile 和完整数据备份；回退需恢复升级前备份，不能让旧版本直接写已迁移的数据。卸载插件与显式遗忘不同，卸载不会擦除用户持久数据。
- 开发验收阶段只使用仓库 `.dsh-dev` 隔离环境。后续按用户明确授权更新日常 desktop profile，完整备份后原位升级并冷启验证，未修改宿主应用本体。公开发布属于用户另行授权的后续步骤，源码 PR 保留人工合并。
