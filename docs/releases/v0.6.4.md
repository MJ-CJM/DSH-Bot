已公开发布为 [GitHub Release v0.6.4](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.6.4)（latest）。安装包 `dsh-bot-0.6.4.tgz` 与固定名称 `dsh-bot.tgz` 字节相同：1,162,495 字节，SHA256 `6188b1bf1a8089ec5ed48d62a9c40e49ed12704e898caacc0a7e70250c301cf7`。

包由 GitHub Actions **Release candidate** 工作流（[run 41824621092](https://github.com/MJ-CJM/DSH-Bot/actions/runs/41824621092)）在干净检出的 `0e90ca3` 上构建，`release.json` 记录 `workingTreeDirty: false`。之后的提交只改本页、发布说明与测试脚本，不改变包内文件。下列运行验收全部针对下载回来的这一份 tgz。

## 功能与变更

相对 [v0.6.3](v0.6.3.md)：

- 群聊统计：每个问题下的成员 token、缓存命中与活动，历史问题选择（[#24](https://github.com/MJ-CJM/DSH-Bot/pull/24)）；原生输入区样式的统计栏、带状态与当前选择的问题菜单、“整个群聊”合计（[#31](https://github.com/MJ-CJM/DSH-Bot/pull/31)）。
- Bot 间消息在双方对话中可见，Bot 详情可在会话右侧打开（#31）。
- 群输入框 `/` 命令菜单与 `+` 按钮，按宿主为群会话提供的命令目录显示（#31）。
- 群访问模式在运行或排队时可切换，建群时选择工作区，并提示越权拒绝（[#27](https://github.com/MJ-CJM/DSH-Bot/pull/27)）。
- 成员运行失败时显示原生原因（[#29](https://github.com/MJ-CJM/DSH-Bot/pull/29)）。

各项的设计与验证见 [群聊统计](../verification/group-statistics/README.md)、[群访问模式](../verification/group-permissions.md)、[Bot 消息、群命令与统计栏](../verification/bot-message-presence.md)、[成员失败原因](../verification/group-failure-reason.md)。

## 兼容与升级

- 宿主声明范围仍为 `>=0.2.1-rc.2 <0.3.0`，peer 与依赖不变，无新增依赖。
- 存储：只在群成员投递记录上新增可选的 `failure` 字段，旧记录不迁移、照常读取。
- **从公开 v0.6.3 原位升级已实测**（见下表），Bot、记忆、主会话历史、群、连接器与通知保持不变，升级后不重放模型工作。
- **不能直接降级到 0.6.3。** 0.6.3 打开群数据时按严格 schema 逐条校验（`@deepseek-ai/dsh-storage-domain` 未设 `invalidRecords` 时任何一条不合格即拒绝打开），不接受 `failure` 字段；一旦记录过成员失败原因，0.6.3 的群数据无法打开，插件启动失败。回退须恢复升级前的完整备份。该结论来自 0.6.3 源码与锁定 rc.2 包的只读核对，未实跑降级。

### 本次发现的测试环境问题（未改产品）

- `scripts/deepening/b3-runner.mjs` 为子进程重建环境时不转发 `DSH_BOT_DSH_BIN`，基于它的脚本会落到桌面版内置 CLI（rc.5）。本次 rc.2 运行通过把 rc.2 的 `dsh` 放在 `PATH` 最前（`scripts/dsh` 会优先使用），并以脚本记录的 `cliVersion` 为准。
- Host 夹具以离线模式安装依赖。rc.2 解析到的 `hono@4.13.16` 不在隔离 pnpm 存储中，安装报 `ERR_PNPM_NO_OFFLINE_TARBALL`；用 `scripts/pnpm store add hono@4.13.16 --store-dir .dsh-dev/pnpm-store` 补入后通过。包的依赖声明与 0.6.3 相同。
- `live-persona-runtime` 期望群问题结束为 `completed`；自并发群（`7df508f`，已含于 v0.6.3）起，完成的问题按设计停在 `idle`，成员投递仍为 `completed`。已更新断言。
