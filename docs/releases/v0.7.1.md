# DSH-Bot 0.7.1

**发布候选，待确认。** 安装包 `dsh-botgroup-0.7.1.tgz`。对比基线为 [0.7.0](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.0)。

## 本版更新

- **Bots 进入 DSH 原生工作区。** 从侧栏打开 Bot 或群聊，可搜索、置顶和查看待办。原生右栏集中显示任务、资料、成员和群设置。单独的 Bot 模式已退役。
- **一次处理多条群回传。** 在输入框上方逐条预览内容及接收成员，勾选后批量回传。群设置中的「始终允许回传」可按 Bot 开启和撤销，仅适用于后续符合条件的回复。成员变更会使原授权和待审回复失效，可批量关闭失效待办，原轮次和执行记录仍可查看。
- **群聊成员上限和头像。** 普通群与 Supergroup 最多支持 6 个 Bot 成员。既有超限群的成员和历史会保留。侧栏可组合显示最多 4 个成员的彩色头像，并随名册更新。
- **记忆和任务续办。** 普通群的「＋ → 只记录记忆」让各 Bot 写入各自的私有记忆，群里只回报写入状态。手动整理私有记忆默认关闭，启用后生成的候选经审阅采用才进入检索。任务详情区分等待资料、等待审批、排队、执行、交付和结果未知，便于重启后回到原任务补资料续办。原生日程的规则编辑、历史查看与手动运行已适配当前宿主。

## 两项修复

- **旧引导的预置会话打不开。** 修复 DSH 将空白 Bot 主聊复用为默认会话后，Bots 入口无法打开的问题。主动打开时，插件核对原会话和 Bot 身份，并在确认会话未使用且没有排队输入后恢复同一个会话 ID 的 Bot 身份和权限。
- **群里只发附件时显示空白。** 文件名和打开入口现在正确显示，获准接收的群成员可以收到对应的附件引用。先前受此问题影响的消息也能在重启后恢复显示，保留原消息和原始历史。

## 安装与升级

用 `SHA256SUMS` 核对版本包，再通过 DSH 的 **插件 → 添加插件 → 安装第三方插件** 选择 tgz。固定名 `dsh-bot.tgz` 是同字节别名，使用 `dsh-bot.tgz.sha256` 核对。安装后完全退出并重开 DSH。

0.7.1 的原生工作区以官方 DSH `0.2.2-rc.5`、官方 `dsh-web-app` 和单个 `dsh-botgroup` 产品包为目标组合。升级前停止 DSH，冷备份完整 profile 与数据。已有官方组合可在原 profile 更新产品包。若 0.7.0 启用了旧 `dsh-bot-web-app`，先在 profile 副本中将活动组合切换为官方 `dsh-web-app`，核对设置和数据后再应用。回退到旧产品版本时，应先另外保存升级后新增的数据，再使用与旧包和宿主匹配的升级前备份。

兼容范围以随包验收中实际测试的宿主和升级路径为准。主动跟进依赖本地 DSH Host 运行，停机期间的自动定时唤醒仍关闭。真实模型质量、外部认证与 IM 收发需另行验收。

## English release notes

**Release candidate awaiting confirmation.** Package `dsh-botgroup-0.7.1.tgz`. Changes are relative to [0.7.0](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.0).

### What's new

- **Bots in the native DSH workspace.** Open Bot and group conversations from the sidebar, search or pin them, and see items that need attention. The native details pane brings tasks, materials, members, and group settings together. The separate Bot mode has been retired.
- **Batch review of group replies.** Preview each reply and its recipients above the composer, then send selected replies together. The group settings offer a revocable, per-Bot permission to automatically send future eligible replies. Membership changes expire earlier permissions and pending reviews. You can close expired reviews in bulk and still inspect the original turns and execution records.
- **Group roster limits and avatars.** Ordinary groups and Supergroups support up to six Bot members. Existing groups above that limit retain their members and history. The sidebar displays up to four member avatars together and updates them when the roster changes.
- **Memory and task continuation.** In an ordinary group, **＋ → Record memory only** writes to each Bot's private store and reports only the outcome in the group. Manual private-memory consolidation is off by default. When enabled, a candidate becomes searchable after review and adoption. Task details distinguish waiting for input or approval, queued, running, delivered, and unknown states, so users can return to the original task with more materials after a restart. Native schedule editing, history, and manual runs now use the current host APIs.

### Fixes

- **Existing onboarding conversations open again.** DSH could reuse an empty Bot conversation as a default conversation and cause its identity check to fail. When you explicitly open an eligible conversation, the plugin checks the original conversation and Bot identity. It restores the Bot identity and permissions on the same conversation ID after confirming the conversation is unused and has no queued input.
- **Attachment-only group messages display correctly.** Filenames and open controls appear in the conversation, and authorized group members receive the appropriate attachment reference. Affected older messages display again after restart, with the original message and history preserved.

### Installation and upgrade

Verify the versioned tgz using `SHA256SUMS`, then install it with the native DSH plugin manager. The stable filename `dsh-bot.tgz` is a byte-identical alias with its own `dsh-bot.tgz.sha256`. Quit and reopen DSH after installation.

The target setup is official DSH `0.2.2-rc.5`, the official `dsh-web-app`, and one `dsh-botgroup` product bundle. Shut down the host and back up the complete profile and data before upgrading. An existing official setup can upgrade the product in place. If 0.7.0 used the replacement `dsh-bot-web-app`, first switch the active composition to the official `dsh-web-app` in a staged profile copy. Check the settings and data before applying the migration. To roll back the product, preserve data added since the upgrade separately and use the pre-upgrade backup that matches the older package and host.

See the candidate's validation record for the host versions and upgrade paths actually tested. Proactive follow-up requires a running DSH host, and automatic scheduled wake-up while it is stopped remains disabled. Real-model quality, external authentication, and IM delivery require separate validation.
