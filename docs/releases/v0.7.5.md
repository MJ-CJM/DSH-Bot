# DSH-Bot 0.7.5

状态：本包已完成下述源码、同包双 Host、升级和界面验收。本说明相对于公开 [0.7.4](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.4)，覆盖其后合入的发送、界面、并发稳定性和群工具变更。公开状态与可下载版本以 GitHub Release 和 npm dist-tag 为准。

## 群聊使用已配置工具，保留审批边界

普通群成员、自动协作成员和受邀 Bot 可使用对应 Bot 已配置的搜索、网页读取、文件、Shell 与 MCP 工具，不必为了这些能力改为单聊。Bot 的工具禁用设置、原生审批及沙箱继续生效；记忆专用回合、失效任务和受限续办不会因此获得执行工具。

执行成员在入场及后续步骤核对群根会话的 `ask`／`never` 策略。`ask` 允许通过原生界面请求本人决定，不等于自动批准；`never` 仍拒绝需要审批的操作。等待原生工具内部审批期间，若根策略撤销、成员任务失效或授权上下文卸载，旧批准不能继续执行。MCP 原生重连更新本连接实际注册的工具代际，外来同名工具不能借用连接器权限。

文件、编辑差异及命令结果按可能含私有内容处理，分享回群仍需现有的准确正文与读者检查。MCP 外发继续核对准确参数、目的地和一次性授权；允许工具执行不等于允许把结果自动分享给其他 Bot。

## 群发送和保存结果更容易恢复

- 发送失败区分未提及成员、输入过长、任务已结束、目标不可用及权限拒绝等原因，并保留可修改的草稿。
- 不确定的发送或续办回执先核对原操作，不因重试而自动重复投递。
- 群改名及成员设置的保存收据可以恢复，读取或刷新失败不直接重做已提交的修改。

## 编辑和补充消息更清楚

Bot 设置直接进入资料编辑，重置、保存状态和按需展开的自定义模型项更清楚。新建群表单提供模式说明，群编辑会提示缺失的保存条件，成员可向下排序。运行中成员提供直接「补充」入口；窄输入区、换行、回复入口及右侧 Bot 导航得到改进。

## 界面稳定性、无障碍和客户端性能

修复轮询与编辑状态之间的竞争，保护未提交草稿；共享变更流减少重复请求和重复样式，并压缩客户端包。改进键盘操作、中英文文案、附件大小显示、共享记忆确认摘要及技术详情的呈现。

群上下文在发送前核对预算，长引用按 Unicode 边界截断，必要时移除引用以保留当前问题；派发使用同一份已核对的输入。日志脱敏与协作回执恢复也得到加强。

## Host 并发与清理

修复并发记忆修改与资料出口之间的死锁、取消后的等待、缺失原生结束回执时的挂起，以及部分卸载失败导致后续资源未清理的问题。群改名恢复保存必要的持久收据；升级时保留完整 profile 和数据，并核验已有记录。

## English

Status: this archive has completed the source, same-archive two-Host, upgrade and UI checks described below. These changes are compared with published [0.7.4](https://github.com/MJ-CJM/DSH-Bot/releases/tag/v0.7.4), including subsequent sending, UI, concurrency and group-tool changes. Check the matching GitHub Release and npm dist-tag for publication status and downloadable versions.

- **Configured tools in group work.** Ordinary members, automatic collaborators and invited Bots can use their configured search, web, file, Shell and MCP tools under Bot restrictions, native approval and sandbox rules. Memory-only work, expired tasks and restricted continuations remain limited. Execution workers check the group root’s `ask`/`never` policy at entry and subsequent steps. `ask` permits requesting a decision; it does not approve the operation. Revocation or loss of the exact worker context while a native tool awaits approval blocks the old decision. MCP reconnects track definitions registered by that connection; unrelated same-name tools gain no authority.
- **Private results remain checked.** File contents, edit differences and command results retain private-data boundaries. Returning them to a group still checks exact content and readers. MCP export checks exact arguments, destination and one-time authorization. Tool execution does not automatically authorize sharing its results.
- **Recover sending and saves.** Clearer failure reasons retain editable drafts. Uncertain sends and continuations are reconciled against their original operations instead of automatically repeated. Durable rename and membership-save receipts support recovery without replaying a committed change after a read failure.
- **Clearer editing and follow-up input.** Bot settings open profile editing directly, with clearer reset/save state and expandable custom-model options. Group creation explains modes, editing identifies missing save conditions, and members can move down. Running members offer a direct supplement action; narrow inputs, line breaks, reply entry points and sidebar Bot navigation are improved.
- **More stable and accessible UI.** Polling/edit races and draft loss are addressed. Shared change streams reduce duplicate requests and styles, and the client bundle is compressed. Keyboard interaction, bilingual copy, attachment sizes, memory-sharing summaries and technical details are improved. Context budgeting truncates long quotes at Unicode boundaries, keeping the current question and dispatching the checked input.
- **Host concurrency and cleanup.** Fixes cover concurrent memory/export deadlocks, cancellation waits, missing native completion receipts, rename-save recovery and cleanup after an earlier disposer fails. Rename recovery stores durable receipts; preserve the full profile and data and validate existing records during upgrade.

## 安装、升级和限制 / Installation, upgrade and limits

目标组合为官方 macOS arm64 DSH `0.2.2-rc.5`、官方 web-app 与一个 `dsh-botgroup` 产品包。开发依赖保持 `0.2.1-rc.2`，声明兼容范围 `>=0.2.1-rc.2 <0.3.0`；这不表示所有宿主版本和平台均经实测。0.7.5 实际验收范围以上表的最终记录为准。

公开发布后，从同一 Release 获取 `dsh-botgroup-0.7.5.tgz` 或固定名 `dsh-bot.tgz`，核对对应校验文件。完全退出 DSH，备份现有 profile 和完整数据，在原 profile 更新 `dsh-botgroup` 后再启动。保留原存储位置，不通过删除 Bot 或重置资料升级。回退须保留升级后新增的历史与设置，不能整库覆盖历史备份。

无需新增配置即可使用正常群工具入口；外部连接仍须先按 Bot 配置，原生审批和沙箱规则继续适用。升级不自动授予共享权限、开启自动协作或重新执行结果不明的任务。旧 `dsh-bot` 包名或替代 web-app 的安装应先按 [README 的迁移说明](../../README.md#升级与迁移) 核对，不能同时启用两份产品或 web-app。

The target composition is official macOS arm64 DSH `0.2.2-rc.5`, its official web-app and one `dsh-botgroup` product. Development dependencies remain pinned to `0.2.1-rc.2`; the declared `>=0.2.1-rc.2 <0.3.0` range is not evidence that every host/platform was tested. Use the final verification table for this archive’s actual coverage.

After publication, download the versioned archive or its fixed-name alias and checksums from the same Release. Quit DSH, back up the existing profile and complete data, update the package in the original profile, then reopen DSH. Keep the existing storage location. Do not delete Bots or reset data as an upgrade step. Preserve newly added data/settings when rolling back; do not overwrite them with an old whole-database backup. Configured external connections, native approvals and sandbox rules still apply. Upgrading does not grant sharing permission, enable automatic collaboration or replay uncertain work.
