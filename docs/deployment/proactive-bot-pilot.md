# 主动 Bot 试点验收单

本表用于验收人冻结一次受控试点。先在隔离 DSH rc.2 Host 使用合成来源完成验证。真实 CI、业务模型和外部通知分别确定授权范围后才能进入试点。

## 执行前填写

| 项目 | 填写内容 |
| --- | --- |
| 版本 | 插件包与协调器 SHA-256、DSH 版本、schema 版本、配置摘要 |
| 负责人 | 操作人、独立验收人、撤销与停止负责人 |
| 来源 | 仓库、分支、来源代际、CI run 和 job、允许读取的字段 |
| 执行 | Bot 及代际、模型和版本、允许编辑的隔离夹具及字段、检查命令、可选群成员 |
| 上限 | 模型请求次数和金额、外部运行次数和金额、通知条数、结束时间 |
| 对照 | 同一输入和数据权限下的人工基线、启用的流程、可接受的误报与漏报变化 |

验收人启动前先记录模型和外部服务的预算上限，并确认仅打开当次试点需要的策略。真实业务试点的操作默认停在任务审阅。若需要外部发送，单列精确目标、正文、条数和审批人。

## 验收

| 检查 | 所需证据 | 结果 |
| --- | --- | --- |
| CI 来源与建议 | scope、来源代际、run、job、attempt、建议、应处理标签、归并或忽略原因 | 待填 |
| 修复与测试 | 原 Ticket、Assignment、隔离副本、修改字段、检查命令、前后退出码、产物哈希 | 待填 |
| 技术群审阅 | 批准正文、群与成员、证据版本、逐成员请求和原生 Session、轮次状态 | 待填 |
| 人工验收 | 独立验收人的决定、准确证据哈希、时间、必要时的返工关联 | 待填 |
| 指定成员跟进 | 新事实、前序轮次、选定成员、调用次数、重复或撤权时的零调用证据 | 待填 |
| 预算与出站 | 模型、外部运行和通知分账，所有真实副作用及回执 | 待填 |
| 停止与恢复 | 暂停或撤销后停止新派工，已发或未知可对账，冷启动零重放 | 待填 |

出现越权读写、超预算、未经授权的外部目标、未知回执或无法核对任务时，先暂停新派工，保留日志、版本和运行关联，由独立验收人决定是否恢复。提交、推送、合并及评论属于另行授权的发布动作。

验收填写 PASS 或 FAIL。未执行、环境受阻及未授权分别标原因。合成结果、长跑和实际业务交付分别记录。 [原验证计划](../design/proactive-bot/validation.md)
